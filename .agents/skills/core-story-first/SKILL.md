# 重大な不確実性を先に試し、コアを証拠で閉じる

[AGENTS.md](../../../AGENTS.md)の必須正本と現行ゴール・要求者の目的と訂正を適用する。親/主担当は要求者の目的に照らし、NGならコア・採否・後続設計を覆す未解消の不確実性を優先し、小さな主軸と範囲・完了を管理する。固定の機能順や枝葉の件数を成果にしない。

AI自身が「問題がある・試さないと分からない」と認識した、採否や設計を左右する前提は、注意書きで済ませず最小の実経路で先に試す。未検証のまま、その前提に依存するUI・設定・抽象化などへ進まない。実行不能なら具体的な不足と影響を示して依存作業を保留し、独立した作業だけを進める。

順序は「重大な不確実性→最小の実装・E2E→観測による採用/簡素化/代替/不採用→必要な製品実装」。仕様条件・合格基準は判断根拠の代わりにならない。未確認の前提に周辺実装や設計見直しを積むと、手戻りに加え、残予算・agentの実行余力・代替を選ぶ余地を失うため、この順序を守る。

## 着手前に固定する

| 固定するもの | 担当へ渡す内容 |
|---|---|
| 一つの最小コアstory | 要求者の目的→今回確かめる問い・その証拠で決めること→最小の実経路と観測結果、今回の対象・作らない枝葉。未指定なら現行ゴールの最重要コアから主担当が小さく選んで明示 |
| 判断根拠と検証の上限 | NGなら捨て直すもの、既存証拠と不足する観測、必要最小限の実験、時間/費用/試行の上限。観測が採否をどう変えるかを定め、有効な既存証拠で判断できるなら実験を増やさない |
| 既存機能の回帰保護 | [開発方針](../../../docs/policies/開発方針.md#実装と検証)に従い、共通処理・状態・呼出元・依存先を含む影響範囲と既存テストの網羅性を変更前に確認する。不足する回帰テストは製品コード変更前に追加・実行し、基準結果を残す。実装後に実行する影響範囲のリグレッション（必要な結合/E2Eを含む）を固定する。コア優先を既存機能の保護を省く理由にしない |
| E2Eと完了条件 | 問いに必要な入口（UIなし/簡易UIも可）→実処理→必要な通信/相手側→最終出力・副作用→終了/再開/回復の操作と観測先、必要環境と証跡 |
| 範囲の変更 | 発見をstory阻害・重大回帰・後続改善へ分け、必須追加だけ親が根拠と影響を示して更新。「簡単・ついで・共通化」で設定/UI polish/抽象化/別機能を足さず、保留を勝手に実装しない |

## 実装・E2E・修正を閉じる

要求者の判断に必要な最小の実経路を先に通す。技術検証はUIなしの実行入口や簡易UIでよく、その経路のE2E実行・観測・修正を先に閉じる。検証に不要な製品UI・画面作りを先行させない。製品Appへの接続が問いの対象なら実Appを通す。技術検証/試作でも、問いに必要な利用可能環境（Simulator・Mac・複数process/端末・ローカルserver/provider・UI・native音声I/O等）を組み合わせ、実際にE2Eを実行する。文章の机上レビューや起動/単体/結合/build成功、送信受付で代替しない。全環境の無条件総当りには広げず、狭いstoryの重要境界は省略しない。

UIのstoryはUI入口、音声は相手native出力/波形と該当する双方向・遅延・連続性・停止/再開まで確かめる。既存入口で通らない経路は必要最小限のE2Eを追加/実行する。製品実装の不具合は担当側で原因切分け→修正→関連E2E再実行し、採用を続ける経路の実行可能なE2Eを残して枝葉/別storyへ流れない。App/packageの工程分離と必要なTDDは維持する。

技術検証でNGを再現した場合は、その証拠で不採用/簡素化/代替を判断して実験を閉じられる。機能成功とは報告せず、元の案を成功させるための修正・抽象化を無制限に続けない。判断に必要な証拠が揃ったら試行を止める。

実機/Apple/外部待ちでも、先に固定scope/問いに必要なデスクトップ検証経路と重要条件を省かず実行する。無関係な全環境の総当りには広げない。不可なら試した手段・具体的不足・残る経路を示し未完/検証待ちにする。物理機材等でしか証明できない残りを分け、必要な設定/承認/機材は求められるが、未検証機能を「試してください」と利用者へ丸投げしない。

## 親の完了・引渡し判定

最終のソース・設定で影響範囲のリグレッションテストを実行し、既存機能の維持を結果で確認する。回帰があれば修正・再実行し、必要な回帰テストの未実行・失敗を残したまま、新しいコアの成功だけで完了・引渡しを認めない。

製品機能・技術経路の成立/利用可能性を主張する作業にこの判定を適用する。固定scope全経路の必要E2E結果と最終source/設定との対応と変更影響、実行日時/環境・操作/期待と実際・両端/最終出力・証跡、件数0/skip/失敗/timeout/実行時警告/crashを親が照合する。mockで置換した本番経路まで検証済みとしない。未実行/失敗なら「できた・動く・完成・使える・確認してください」と機能完成/利用可能性を主張せず、未完と残経路を返す。

技術経路の成立、部品検証、ローカルE2E完了、実機受入未了、製品story完了を分ける。「成立した操作・判断を変える観測・重大な妨げ・次に止め/進めるもの」を示す。区切りは仕様更新・commit・main統合/pushまで開発方針と許可範囲で閉じ、情報を消してbacklogを減らさない。

## 必要な参照だけ読む

[優先判断の根拠と実行](references/優先判断の根拠と実行.md)の「狭いscopeとE2Eの実行・完了判断」は実装/検証/完了時、「利用者の理由」「選択と後回し」「判断根拠と証明の範囲」「実験」「継続と記録」は各判断時に必要節だけ読む。モデル・役割・文脈再利用・小さなmerge・検証資源は[efficient-work](../efficient-work/SKILL.md)を適用する。関連機能の設計整合と重大不確実性の先行確認を保ち、待ち中の独立作業を未実行E2Eの回避にしない。機能成立を主張しないスキル/文書のみの変更に不要なアプリE2Eを強制せず、形式/参照検証を機能実証と扱わない。依頼からアプリ実行・修正や外部操作へ範囲を広げない。
