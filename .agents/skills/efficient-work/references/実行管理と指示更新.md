# 実行管理と指示更新

実行管理役を置くときと指示更新時の参照。モデル別の詳細は[モデル選択と再利用](モデル選択と再利用.md)、レビュー・品質・保存する再開情報は[品質・レビュー・引継ぎ](品質・レビュー・引継ぎ.md)の必要節だけ読む。

## 直接処理と管理役

密接な設計判断、同じ共有状態の頻繁な編集、必要な背景を小さく正確に渡せない作業は主担当に残す。独立して受入条件を閉じられるまとまった調査・実装には委任を検討する。単純作業に管理層を足さず、管理役の入力・出力・履歴・待ち・再試行も総負担に含める。

| 担当 | 初期候補・仕事 | 境界 |
|---|---|---|
| 主担当 | Astra / medium。要求・全体設計、範囲と費用、未解決対立、最終受入を判断 | 管理役へ目的・不変条件・受入条件・利用可能枠・再委任範囲・コミット実行者を渡す。最終責任を保持 |
| 実行管理役 | 通常はSol / medium、競合を伴う調整はhighを検討。定型の狭い進行管理はTerra / mediumも候補 | 担当契約、所有、順序、必要レビュー、検証対象、通常質問、証跡集約、指示更新、回収を管理。要求の意味・品質閾値・承認範囲の変更は主担当の判断を受けて反映する |
| 作業者 | 作業のモデル初期候補から選ぶ | 指定範囲で調査・修正・検証。通常の質問と結果は管理役へ直接送る。追加分担は管理役が指定する担当へ依頼する |
| レビュー役 | レビュー表の条件で選ぶ | 指定ソースを独立に調べ、管理役と作業者へ根拠を返す。受入は主担当が判断し、編集は所有する作業者が行う |

再委任の許可は実行管理役にだけ、対象・最大深さ・同時枠を明示する。既定の深さは主担当→管理役→作業者またはレビュー役まで。管理役はその範囲を管理し、孫は担当した実作業を閉じる。再委任はこの明示許可と、ツール・上位指示が認める範囲で行う。主担当と管理役は同じ台帳で稼働総数を数える。通常の子二つまでという初期値には管理役と配下を含め、待機中も枠の仕様に従い数え、必要なら順次実行する。

委任に実益がある場合はモデル・思考を明示する。この環境の`collaboration.spawn_agent`で別モデル・思考を指定するときは`fork_turns: "none"`と必要な指示・資料を渡す。必要な背景だけを渡し、指定モデルを使用できることを確認して依頼する。他環境では実際の仕様に合わせる。関連する検索・調査は一つの依頼にまとめる。

## 担当契約と連絡

| 契約へ渡す内容 | 具体化すること |
|---|---|
| 目的と正本 | 目的、対象ソースの基準commitまたは差分、必要な原文・規約・決定、受入条件。適用境界・数値・単位・例外・品質閾値は正確に保持する |
| 所有と権限 | 対象ファイルと編集可否、App/packageの工程、共有Simulator/build/processの所有者、委任・外部操作の許容範囲 |
| 実行と終了 | 検証方法、終了条件、返す証跡、連絡先の管理役ID、担当間の直接連絡先、適用する指示記録の位置と更新日時 |

管理役は自分と各担当のID・モデル・思考・既読資料・確認ソース・渡した要求と更新・編集範囲・成果・未解決・handleを短い担当メモで保持する。同じ背景の続きは既存担当へ差分を渡して再利用し、モデル変更・履歴肥大化は再利用表で判断する。

作業者とレビュー役は`send_message`等で管理役へ直接連絡し、同じ論点の当事者間でも必要な根拠を共有する。作業者は待ち・修正・再検証を管理役へ返し、管理役は通常質問に既存決定の範囲内で答える。自動テストの実行・解析・許可範囲内の修正は[品質・レビュー・引継ぎ](品質・レビュー・引継ぎ.md)の該当節で担当側に閉じ、難しい原因調査も必要に応じSolへ渡す。主担当へは判断が必要な論点を根拠付きで渡す。変更指示は管理役が正本へ反映・差分配信し、要求変更は正本と関係担当へ反映する。

返却は結論、根拠のパス・行・URL、変更箇所、検証結果とログ保存先、未解決に絞る。長い探索記録は参照へ退避する。管理役も主担当も採用時は、判断に必要な原文・差分・証跡を確認する。

| 主担当へ戻す判断パッケージ | 含める内容 |
|---|---|
| 要求の曖昧さ・正本との矛盾 | 該当原文と参照、解釈候補、影響、管理役の推奨、必要な回答 |
| 範囲・費用・権限・品質の変更 | 現在の許可と提案差分、理由、選択肢と負担・品質への影響。未承認部分を止め、独立作業は続ける |
| 未解決対立・進展なし・外部制約 | 相反する証拠、試行と結果、不足情報、止めた対象、再開条件。次の試行は仮説や観測が変わるものを選ぶ |
| 最終受入 | 要求充足、最終対象差分、検証ソース・設定・環境と結果、残る制限と未確認、レビューの処理状況、受入の推奨 |

ツールが子の完了を親へ自動通知することや、孫が親以外へ起動できないことがある。通信・既存担当の再利用がツリー制約でできなければその制約を明記し、主担当が必要な起動・中継だけを行う。管理役への直通が失敗した場合も、配送不能の範囲をツール結果で示し、確認できたツール結果・宛先・未配送内容を添えた最小パケットだけを主担当が管理役へ中継する。必須報告の隠蔽と承認回避は禁止する。主担当が利用者への報告・承認を担当する。利用者への質問と重大な判断は主担当が担う。

## 指示の正本と更新

作業開始時に管理役は指示の正本を一つ示す。短い作業なら担当メモ、長い作業なら既存引継ぎ文書を使い、恒久要求・仕様・検証記録はリポジトリの分類へ置く。製品要求を満たす進め方をスキルで定める。スキル自体の変更も依頼された範囲に限る。

| 更新記録 | 残す内容 |
|---|---|
| 出典と担当 | 利用者の訂正または決定の参照、正本パスと更新日時、起案者・更新担当・判断した主担当。指示の識別には見出し・出典・更新日時を使う |
| 変更理由と範囲 | なぜ変えるか、変更前の前提と置換する文言、維持する条件、適用対象と対象外、発効条件 |
| 対象と検証 | 対象commitまたは差分・ファイル・設定・環境、影響する検証、再検証の要否と根拠、未解決 |
| 実行中への影響 | 該当担当・process・成果の有効/無効、停止・継続・やり直しの範囲、次の完了条件 |
| 配信と受領 | 配信先、受領確認と理解した適用範囲。未確認の担当と次の取得方法 |

既存担当へは差分と置換対象を送り、担当が受領した指示の位置・更新日時、変更後の範囲と検証を言い返して一致を確かめる。新規担当には現行契約と必要原文を渡す。担当の受領と理解の一致を確認して適用済みとする。返信待ちは影響する次の編集・検証・受入を止め、無関係な作業を進める。送信が処理中のツールを止めない場合、その結果は旧条件の証跡と明記し、再利用は新条件への影響を確認してから判断する。旧条件の実行が新条件や共有状態を壊す、または不要な費用を生む場合は、当該作業が所有し安全に止められるprocessだけを停止する。参照のみのテストなど新条件へ影響しない実行は継続して旧条件の証跡として保持できる。他作業・所有不明のprocessやSimulatorを止めず、判断が必要なら対象と影響を主担当へ返す。

利用者の明確な訂正・変更指示は既に与えられた承認として、管理役が既存の権限と範囲内で正本へ差分適用・配信する。要求の解釈が曖昧、正本との矛盾、範囲・品質・費用のトレードオフ、外部操作・承認範囲または所有の衝突が未解決な場合だけ、その論点を主担当の判断へ戻す。既存許可内の誤記修正や確定済み決定の伝達も管理役で閉じ、明確な訂正は既存承認の範囲で適用する。実行権限は元の承認範囲を維持する。

秘密・音声内容の記録への複製は禁止する。全文ログ・探索履歴は適切な保存先を参照する。原文の参照と判断に必要な抜粋だけを保ち、重要な数値・例外・禁止は正確に保持する。古い記録は現行指示と区別して置換先を示し、過去の成功は元条件で保持し、新条件は対応する結果を記録する。圧縮前は正本と受領状態を含む再開情報を保存し、復元後はその位置と実ソースの一致を確認して必要な担当へ差分を再通知する。

## 統合とコミットの単一実行者

主担当は統合とコミットの可否・対象・実行者を判断する。管理役を置く構成では、開始時に管理役または一人の作業者を単一実行者として指定し、主担当の受入後に操作を行わせる。管理役が必要ない短い作業は主担当が直接終える。ツール・権限上どうしても主担当の操作が必要なら、その部分だけを主担当が実行する。実行委任は判断責任の移転ではない。実行者は同時に一人とし、交代時は停止と所有移管を確認する。メッセージ作成は既存担当または主担当が直接行う。

実行者は検証対象と最終差分・既存indexを確認し、自分の差分だけを含むパス限定の方法を使う。他作業のindexを保護し、同じファイルに他作業が混在し安全に分離できなければそのコミットを止めて主担当へ戻す。他担当が書込中なら待ち、commit後に対象ファイルと内容が決定・検証と一致する証跡を返す。統合は主担当が受け入れた変更を対象にする。


## 管理役単位のworktreeとmainへの段階的merge

利用者の「実行制御役」は本スキルの実行管理役として扱う。並行作業を隔離するため、実行管理役単位でmain由来の短期branchとworktreeを使うことを許可する。worktreeは管理役単位で共有し、同じ管理役の配下は編集所有を分けてその作業領域を使う。小作業や編集が競合しない作業は既存の作業領域を使う。別管理役と分かれたworktreeでもApp/package工程・共有Simulator/build/processの所有と総同時枠は共通して守る。

責務と受入条件が閉じる小さな完了単位を先に決め、検証・commitを済ませてmainへ段階的にmergeする。関連する変更を小さな完了単位でmainへ統合する。管理役は実務と記録更新を行えるが、各単位のmerge許可・保留の決定と管理責任は親/主担当が必ず持つ。worktree使用・局所commit・mergeの許可はそれぞれ対象を明確にして管理する。

| 親/主担当が必ず管理する項目 | 記録と判断 |
|---|---|
| 領域と所有 | worktreeの絶対パスとbranch、管理役と編集所有、基準mainのcommit、対象commit/差分と予定する小さな完了単位 |
| 検証と残件 | 検証したソース/差分・設定・環境と結果/証跡、仕様更新、残る失敗・未確認・依存、他単位との関係 |
| 許可または保留 | 具体的な対象commit/差分・統合先mainの状態に結びつく主担当の決定、理由、保留の再開条件、許可された単一実行者。許可への変更は主担当が判断する |
| 統合後 | 統合済commit、取り込まれた対象と検証の一致、次の単位と残件、worktreeと生存資源の継続/回収状態 |

管理役はmerge判断用に対象と根拠・残件・推奨を集約し、親/主担当が許可または保留を明示して記録する。許可された単一実行者へ操作は委任できるが、mergeは明示許可された対象と統合先に限定する。統合先がdirty、他作業のindexが存在するなど安全に分離できない場合、未解決の統合は保留して主担当へ戻す。他作業を変更する無断のstash/reset/cleanは禁止する。他作業のworktree・未コミット/未追跡差分・processを保護する。

許可後に対象commit/差分、競合解消内容、依存関係、mainの状態が変わったら、管理役は許可時との影響を確認して親/主担当へ示す。許可範囲と検証がなお有効か不明、または対象・挙動に影響する場合は再判定までmergeを止める。検証も変更の影響範囲で更新し、検証は変更後の対象ソースと対応させる。主担当が判定できる記録を残し、許可の有効性は変更影響と証拠で示す。

保留中は独立した許可済み作業を続けられるが、保留対象は許可時の状態を保持する。新しい単位と対象・所有・検証を分け、必要な範囲判断へ戻す。圧縮/引継ぎではこの表と許可・保留の根拠を復元できるようにする。不要なworktreeは対象のmain統合、未コミット差分・未追跡ファイル、生存process/検証handle、残す証跡を確認してから回収する。未統合・所有不明の作業領域の無断削除は禁止する。

[開発方針](../../../../docs/policies/開発方針.md)のブランチ運用とビルド場所を適用する。通常のXcode Build/Run/Test/Archiveはmainの実projectとXcode既定DerivedDataを入口とする規定を維持し、worktreeは許可された分担と隔離検証の範囲で使う。一方、並行変更に必要な検証をworktreeで行うことと通常buildの入口/設定の変更は区別し、隔離領域での検証は正本の範囲と今回の許可に従って選ぶ。正本の制約との実際の矛盾によって必要な検証を実施できない場合だけ、該当原文・必要な例外と理由・選択肢を主担当へ返す。mainへの統合と方針の変更は主担当の判断・承認に従って進める。
