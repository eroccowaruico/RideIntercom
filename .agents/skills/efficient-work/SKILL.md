# 品質・コスト・コンテキストを保つ実行管理

本スキルが選択された作業に適用する。主担当はモデルの種類や価格帯によらず、要求解釈・範囲・品質・承認・最終受入に責任を持つ。主担当に最上位モデルを前提とせず、利用可能なモデル・ツール・権限に合わせて担当構成を選ぶ。Copilotなど選択肢が限られる環境でも、フロンティアモデルを必須にせず、利用可能な候補から必要な品質と費用に合うものを選ぶ。モデルや思考設定を変更できない環境では、実際に利用できる条件で進める。適用はこのプロジェクトの依頼・実行権限・承認範囲に限定する。

[AGENTS.md](../../../AGENTS.md)の正本と対象仕様を適用する。選択・範囲・完了は[core-story-first](../core-story-first/SKILL.md)、回帰・GUI実行・配置は[開発方針](../../../docs/policies/開発方針.md)の該当節が正本。既読資料は今回必要な節だけ確認し、モデルや並行数によらず品質条件を維持する。

## 最初の判断

委任の可否は利用者の指示と実環境の制約に従い、直接処理の指定時は主担当が実行する。

短い検索・確定済み操作・小修正は現在の主担当が直接終える。委任は独立して完了できる範囲があり、起動・説明・履歴処理・検証・統合・引継ぎまで含めても総負担が減る場合に選ぶ。利用可能な担当数や実行枠を増やすためだけに委任しない。

| 仕事 | 選び方 |
|---|---|
| 定型抽出・限定検索・既知テスト | 条件を守れる範囲で、利用可能な低コスト・高速モデルを選ぶ |
| 明確な入出力の局所コード・テスト・文章・画面確認 | 必要な編集・実行ツールと文脈を扱えるモデルを選ぶ |
| 複数契約の調査・実装・原因切り分け | 必要な推論力と文脈を持つモデルを最初から選ぶ。安価なモデルで失敗させる工程を品質上の前提にしない |
| 要求・設計・統合と品質の判断 | 主担当が責任を保持する。広い範囲の整理・進行は、適性があれば低コストの調整担当へ委任し、採否や難しい中核判断は必要な能力を持つ担当に残す |

モデルごとの思考設定・コンテキスト上限・ツール利用可否は互換とは限らない。ラベルをモデル間の能力・費用の共通尺度として扱わず、実環境で選択可能な設定だけを使う。失敗時は入力・再現・環境・権限・検証を先に切り分け、能力不足の根拠がある場合に担当や設定を見直す。モデル選択の運用例は[モデル選択と再利用](references/モデル選択と再利用.md)を参照する。

## 通常運用の境界

作業人数・独立性・実際の利用可能枠に合わせて[実作業を中心にした構成](references/実行管理と指示更新.md#実作業を中心にした構成)を選ぶ。作業者一人は直接委任し、管理役は継続調整の利益がある場合に置く。主担当は要求解釈、範囲・費用・品質の変更、未解決対立、最終受入を判断する。

再利用は[文脈の継続条件](references/モデル選択と再利用.md#渡したコンテキストと再利用性で分担を決める)を満たす担当へ行う。担当の管理役は同時に一人とし、[所有と連絡](references/実行管理と指示更新.md#担当契約と連絡)・[再委任と総枠](references/実行管理と指示更新.md#再委任と総枠)を守る。起動失敗や一人への集中は[分担の復旧と定期見直し](references/実行管理と指示更新.md#分担の復旧と定期見直し)で改善する。

**[開発方針の小さく動く単位](../../../docs/policies/開発方針.md#小さく動く単位で検証・コミットする)で検証・仕様更新・commitを閉じ、未コミットの滞留を抑える。** [担当ごとの運用](references/品質・レビュー・引継ぎ.md#動作を保つ小さな完了単位)を適用する。worktreeは管理役単位で隔離でき、[mainへのmerge許可・保留と管理](references/実行管理と指示更新.md#管理役単位のworktreeとmainへの段階的merge)は親/主担当が必ず担う。共有資源・編集所有を分け、コミットは指定した単一実行者が他作業の差分・indexを保護して行う。

ツールから親への通知・承認処理・利用者への報告は実環境に従って主担当が引き受ける。主担当は必要な実行と最終品質の責任を保持する。

ゴール遂行中はスキルを参照専用とし、現行ルール内で分担を改善する。恒久的な問題は[改善記録と後続の改訂](references/実行管理と指示更新.md#作業中の改善記録と後続のスキル改訂)へ残し、明示されたスキル保守の工程で反映する。
