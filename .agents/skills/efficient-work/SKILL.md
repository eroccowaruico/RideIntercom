# 品質を保つモデル選択と実行管理

`$efficient-work 今回の作業を進めて`で適用する。主担当Astraは要求解釈・全体設計・トレードオフ・最終受入の責任を持つ。設定や圧縮を強制変更できないため、現在のモデルで続ける場合は実際のモデルを明記する。適用はこのプロジェクトの依頼・実行権限・承認範囲に限定する。

[AGENTS.md](../../../AGENTS.md)の正本と対象仕様を適用する。選択・範囲・完了は[core-story-first](../core-story-first/SKILL.md)、回帰・GUI実行・配置は[開発方針](../../../docs/policies/開発方針.md)の該当節が正本。既読資料は今回必要な節だけ確認し、モデルや並行数によらず品質条件を維持する。

## 最初の判断

委任の可否は利用者の指示と実環境の制約に従い、直接処理の指定時は主担当が実行する。

短い検索・確定済み操作・小修正は現在の主担当が直接終える。Solで進めるスキル/文書の局所修正も判断・修正・確認を一括して行う。起動・説明・履歴処理・検証・統合・圧縮後復元までの総負担で委任を選び、単価・並列数と完了までの総負担を合わせて決める。

| 仕事 | 初期候補 |
|---|---|
| 定型抽出・限定検索・既知テスト | Luna `gpt-6-luna` / low。狭い判断はmedium |
| 明確な入出力の局所コード・テスト・文章・画面確認 | Terra `gpt-6.1-terra` / medium。抽出・整形はlow |
| 複数契約の調査・実装・原因切り分け | Sol `gpt-6.1-sol` / medium。厳密性・競合等で必要なら最初からhigh以上 |
| 要求・設計・統合と品質の判断 | 主担当Astra `gpt-6-astra` / medium。厳しい音声・RTC等は必要に応じhigh |

同じ思考ラベルはモデル間の能力・費用の共通尺度ではない。失敗時は入力・再現・環境・権限・検証を先に切り分け、能力不足の根拠があるとき上げる。Solはhigh以上が必要な仕事もあり、昇格は要求の難しさと必要な品質から判断する。設定を指定できない場合は制約と実際に使用するモデルを明記する。

| 必要な判断・担当 | 読む場所 |

## 通常運用の境界

作業人数・独立性・実際の利用可能枠に合わせて[実作業を中心にした構成](references/実行管理と指示更新.md#実作業を中心にした構成)を選ぶ。作業者一人は直接委任し、管理役は継続調整の利益がある場合に置く。主担当は要求解釈、範囲・費用・品質の変更、未解決対立、最終受入を判断する。

再利用は[文脈の継続条件](references/モデル選択と再利用.md#渡したコンテキストと再利用性で分担を決める)を満たす担当へ行う。担当の管理役は同時に一人とし、[所有と連絡](references/実行管理と指示更新.md#担当契約と連絡)・[再委任と総枠](references/実行管理と指示更新.md#再委任と総枠)を守る。起動失敗や一人への集中は[分担の復旧と定期見直し](references/実行管理と指示更新.md#分担の復旧と定期見直し)で改善する。

[小さな動作可能な完了単位](references/品質・レビュー・引継ぎ.md#動作を保つ小さな完了単位)で検証・仕様更新・commitを閉じる。worktreeは管理役単位で隔離でき、[mainへのmerge許可・保留と管理](references/実行管理と指示更新.md#管理役単位のworktreeとmainへの段階的merge)は親/主担当が必ず担う。共有資源・編集所有を分け、コミットは指定した単一実行者が他作業の差分・indexを保護して行う。

ツールから親への通知・承認処理・利用者への報告は実環境に従って主担当が引き受ける。主担当は必要な実行と最終品質の責任を保持する。

ゴール遂行中はスキルを参照専用とし、現行ルール内で分担を改善する。恒久的な問題は[改善記録と後続の改訂](references/実行管理と指示更新.md#作業中の改善記録と後続のスキル改訂)へ残し、明示されたスキル保守の工程で反映する。
