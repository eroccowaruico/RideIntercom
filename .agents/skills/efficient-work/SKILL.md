# 品質を保つモデル選択と実行管理

`$efficient-work 今回の作業を進めて`で適用する。主担当Astraは要求解釈・全体設計・トレードオフ・最終受入の責任を持つ。設定や圧縮を強制変更できないため、現在のモデルで続ける場合はAstraへ変更済みと報告しない。個人設定や他プロジェクトへ広げず、実行権限・承認権限・依頼範囲を増やさない。

[AGENTS.md](../../../AGENTS.md)の必須正本と[文書入口](../../../docs/README.md)から対象の現行仕様・残課題・必要な証跡を適用する。既読で変更されていない資料の全文を繰り返し読まない。

## 最初の判断

短い検索・確定済み操作・小修正は現在の主担当が直接終える。特にSolで進めるスキル/文書の局所修正に、管理役・作成役・レビュー役を形式的に起動しない。起動・説明・履歴処理・検証・統合・圧縮後復元までの総負担で委任を選び、単価や並列数だけで決めない。

| 仕事 | 初期候補 |
|---|---|
| 定型抽出・限定検索・既知テスト | Luna `gpt-6-luna` / low。狭い判断はmedium |
| 明確な入出力の局所コード・テスト・文章・画面確認 | Terra `gpt-6.1-terra` / medium。抽出・整形はlow |
| 複数契約の調査・実装・原因切り分け | Sol `gpt-6.1-sol` / medium。厳密性・競合等で必要なら最初からhigh以上 |
| 要求・設計・統合と品質の判断 | 主担当Astra `gpt-6-astra` / medium。厳しい音声・RTC等は必要に応じhigh |

同じ思考ラベルはモデル間の能力・費用の共通尺度ではない。失敗時は入力・再現・環境・権限・検証を先に切り分け、能力不足の根拠があるとき上げる。Solはhigh以上が必要な仕事もあり、low/mediumでの失敗を昇格の前提にしない。設定を指定できない場合に黙って別モデルへ置換しない。

## 通常運用の境界

複数担当が継続して連携する場合は実行管理役を置き、通常の質問・進捗・証跡・指示差分の配信と受領確認をそこで閉じる。小作業のためだけに管理役を起動しない。主担当へは要求解釈、範囲・費用増、未解決対立、受入など判断が必要な情報を根拠と推奨付きで返す。

子は原則再委任しない。主担当が明示許可した実行管理役だけが、総同時枠・深さ・所有を管理して作業者とレビュー役へ再委任できる。通常は子を同時に二つまでとし、管理役とその配下も含め実環境の上限を守る。

並行作業は管理役単位のworktreeで隔離できる。親/主担当は小さな検証済み完了単位のmainへのmerge許可・保留と管理を必ず担う。編集所有とApp/package工程・共有実行資源を分ける。レビューを全役常設にしない。主担当が最終受入し、コミットは決定済みの単一実行者だけが他作業の差分・indexを保護して行う。

ツールの親への通知、承認要求、ユーザー向け報告義務は管理役で遮断できない場合がある。主担当が必要な通知・承認処理を引き受け、判断だけで完全に済むとは保証しない。品質責任も移さない。
