# 品質を保つモデル選択と実行管理

`$efficient-work 今回の作業を進めて`で適用する。主担当Astraは要求解釈・全体設計・トレードオフ・最終受入の責任を持つ。設定や圧縮を強制変更できないため、現在のモデルで続ける場合は実際のモデルを明記する。適用はこのプロジェクトの依頼・実行権限・承認範囲に限定する。

[AGENTS.md](../../../AGENTS.md)の正本と対象仕様を適用する。選択・範囲・完了は[core-story-first](../core-story-first/SKILL.md)、回帰・GUI実行・配置は[開発方針](../../../docs/policies/開発方針.md)の該当節が正本。既読資料は今回必要な節だけ確認し、モデルや並行数によらず品質条件を維持する。

## 最初の判断

委任の可否は利用者の指示と実環境の制約に従い、直接処理の指定時は主担当が実行する。

短い検索・確定済み操作・小修正は現在の主担当が直接終える。特にSolで進めるスキル/文書の局所修正に、主担当が判断・修正・確認を一括して行う。起動・説明・履歴処理・検証・統合・圧縮後復元までの総負担で委任を選び、単価・並列数と完了までの総負担を合わせて決める。

| 仕事 | 初期候補 |
|---|---|
| 定型抽出・限定検索・既知テスト | Luna `gpt-6-luna` / low。狭い判断はmedium |
| 明確な入出力の局所コード・テスト・文章・画面確認 | Terra `gpt-6.1-terra` / medium。抽出・整形はlow |
| 複数契約の調査・実装・原因切り分け | Sol `gpt-6.1-sol` / medium。厳密性・競合等で必要なら最初からhigh以上 |
| 要求・設計・統合と品質の判断 | 主担当Astra `gpt-6-astra` / medium。厳しい音声・RTC等は必要に応じhigh |

同じ思考ラベルはモデル間の能力・費用の共通尺度ではない。失敗時は入力・再現・環境・権限・検証を先に切り分け、能力不足の根拠があるとき上げる。Solはhigh以上が必要な仕事もあり、昇格は要求の難しさと必要な品質から判断する。設定を指定できない場合は制約と実際に使用するモデルを明記する。

## 通常運用の境界

複数担当が継続して連携する場合は実行管理役を置き、通常の質問・進捗・証跡・指示差分の配信と受領確認をそこで閉じる。小作業は主担当が直接終える。主担当へは要求解釈、範囲・費用増、未解決対立、受入など判断が必要な情報を根拠と推奨付きで返す。

担当の再利用は[モデル選択と再利用](references/モデル選択と再利用.md#渡したコンテキストと再利用性で分担を決める)の継続条件を満たす場合に選ぶ。各担当の指示・優先順位を管理する管理役は同時に一人とし、管理役をまたぐ依頼と所有移管は[担当契約と連絡](references/実行管理と指示更新.md#担当契約と連絡)に集約する。一人への依頼の積み上げは順次処理として扱い、並行化は独立作業が実際に進む構成で選ぶ。起動失敗後の代行や一人への集中は、[分担の復旧と定期見直し](references/実行管理と指示更新.md#分担の復旧と定期見直し)で定期的に再判定し、利益がある分担へ戻す。

再委任は主担当が明示許可した実行管理役が担当し、総同時枠・深さ・所有を管理して作業者とレビュー役へ再委任できる。通常は子を同時に二つまでとし、管理役とその配下も含め実環境の上限を守る。

並行作業は管理役単位のworktreeで隔離できる。親/主担当は小さな検証済み完了単位のmainへのmerge許可・保留と管理を必ず担う。編集所有とApp/package工程・共有実行資源を分ける。レビューは変更のリスクに必要な役を選ぶ。主担当が最終受入し、コミットは決定済みの単一実行者だけが他作業の差分・indexを保護して行う。

ツールの親への通知、承認要求、ユーザー向け報告義務は管理役で遮断できない場合がある。主担当が必要な通知・承認処理を引き受け、必要な実行と最終品質の責任を主担当が保持する。
