# 未確認事項

## Mac音声サービスの応答待ち

2026-10-31の本人確認と音声許可のApp接続後、独立音声E2EのMac側が測定開始前に30秒の初期化期限へ達した。専用targetは現行のKeychain・招待・依存注入へ修正し、Mac/iOS buildと事前試験は成功したが、duplex測定は未完である。

短時間の再現とstack採取では、`AudioE2ETests.swift`の`AVAudioEngine.mainMixerNode`取得からCoreAudioの`HALC_ProxyIOContext::_TellServerAboutStreamUsage`へ入り、OSサービスの応答を待っていた。本人確認・通話・音声測定の開始前であり、今回の許可判定が原因とは確認されていない。Macのロックとの因果も未確認。共有音声サービスや他の利用アプリを停止せず、所有した検証ホストと専用Simulatorだけ回収した。

証跡は`.validation/app-admission-delivery/e2e/`と`e2e-diagnosis/`。音声サービスが利用可能になった後に、同一ソースのLocal/WebRTC duplex、設定変更、連続性・125ms基準を独立E2Eで再確認する。App単体・RTC結合の成功を、この実測の成功に置き換えない。
