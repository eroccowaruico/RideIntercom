## 認証ユーザーと削除後の再登録

Workerの`account.test.mjs`で、複数端末・再ログイン・全端末資格期限切れ後の同一公開ID、削除後の新ID、並行再登録・再起動・古い削除再送、残存する通話予約の迂回拒否を確認する。Appの`InternetAccountTests`では公開IDと資格の内部locatorが異なる登録応答を保存できることと、不正なlocatorの拒否を確認する。これは保存ユーザーの本人確認や通知許可までの結合確認ではない。

## 署名付き端末証明

Workerの`account.test.mjs`でBearerの本人と端末への証明発行、bodyによる他人のID指定の無視、秘密の非公開、期限、削除・再登録、不正鍵・仮ID・署名設定欠落を確認する。Appの`DeviceIdentityCertificateTests`はJOSE生成のES256署名とCryptoKitの相互運用、署名・発行元・用途・期限・各ID・公開鍵の検証を扱う。`InternetAccountTests`は取得と資格保存の一連の処理、不一致時の資格回収、再起動、サインアウト、欠落／破損した秘密鍵の保持を確認する。相手による秘密鍵の所持確認と保存ユーザーへの対応は後続の検証対象である。

## App音声・機器

GeneratedDuplexAudioTestsは実PCM16 codec、現行GroupRelay暗号化、共通受信待ち、Appのdecodeを通して双方向各30,000フレーム・9,600,000サンプル・順序・誤差・重複拒否を検査する。合成時間であり実音響品質の確認ではない。

App単体・結合テストはオフラインAVAudioEngineと偽のハードウェア境界を用いる。SessionManagerのruntime eventを入力し、資源解放・接続維持・再試行を検証する。

## 実発話E2E

独立した`RideIntercomAudioE2E` schemeを[音声E2Eテスト入口](../development/音声E2Eテスト.md)から実行する。MacとiPhone Simulatorの両端で、録音済みの異なる発話をLocal / WebRTCへ送り、相手の実出力engineの波形を照合する。全codec指定・16/24/48kHz・bitrate境界・session profile・VAD・各effect・音量・muteと復帰を設定マトリクスで扱う。iOSのcaptureは実OS backendを起動し、callbackのマイクsampleだけをfixtureへ差し替える。サーバーはlocalhostのWorker/SFU fixture、アプリのHTTP/WS clientとWebRTC媒体は実物である。物理マイクのAEC品質・Bluetooth・実Cloudflareの保証は含まない。

## Local探索

実Multipeer探索の反復start/stopとSimulatorの接続・切断UIを扱う。端末間の無線通信・実機相互通話は確認待ちへ分ける。

## VADGateの試験範囲

| テスト観点 | 確認内容 |
|---|---|
| 既定値 | Realtime VAD / gate 用の初期設定になっている |
| 値の正規化 | 各設定値が定義範囲に丸められる |
| RMS | `[Float]` サンプルから RMS と dBFS を計算できる |
| attack | speech しきい値超過が attack duration 続くまで `silence` を維持する |
| release/hangover | silence しきい値未満が release duration 続くまで `speech` を維持する |
| gate | `applyGate(to:)` が更新後 gain をサンプルへ適用する |

| VADGateEffect 生成 | `VADGateEffect.make()` が `AVAudioNode` を持つ effect を返す |
| VADGateEffect 設定反映 | `make(configuration:)` で渡した設定が `vadGate.configuration` に反映される |

## 全体監査で追加した異常系

| 領域 | 自動検証 |
|---|---|
| 音声入力境界 | 非有限PCM/時刻、channel 0・過大format、PCM16 sliced Data、偽compressed envelope count/offset、5.1拒否とinterleaved入力 |
| 出力backlog | Mixer/SessionManagerの20並行offline fixtureで、破棄後の最初のblockから最新音声が出ること、旧音声が再開後に出ないこと |
| graphと並行性 | bus/source/faderの反復追加削除、effect設定の再正規化、VADの並行更新・reset・snapshot、全packageの任意Thread Sanitizer実行 |
| RTC | control overflow後の回復、queue上限、二重start・重複route、不正Local ID、旧channel callbackの所有期間 |
| App保存 | secret/runtime非保存、破損保持・書込停止、鍵準備/manifest commit失敗の復旧、削除、8人上限、同鍵再招待・通話中異鍵拒否 |
| App音声 | sample長に基づくVAD、preroll再送防止、remote時計に依存しない発話期限、離脱graph解放、未知codec/不正RTC format拒否 |
| Worker | numeric/空/制御/過大ID・SCTP部分一致拒否、WS null close、8人publish/9人拒否、body停滞timeout後のroom再利用。表示名なしのjoinと、余分な表示名がSQLite/WALとpeer一覧に残らないこと |
| 実行基盤 | 依存段階blocked、timeoutとSIGINTの子process終了、0 tests/skip/todo拒否、xcresult解析、既存証跡保護、危険なcleanup拒否 |

## リアルタイム会話の追加範囲

[音声E2E手順](../development/音声E2Eテスト.md)のrealtime / codec / group / switches / conversationを独立して実行する。通常のpackage・App結合・UIテストの成功だけでは音声合格としない。各処理のsample clock・queue上限・異常値、native AAC、8人混在経路、相槌、微小欠落とclickの負例、設定切替時の無音と通常区間、capture→render遅延を別々に判定する。実機無線・Bluetooth・実Cloudflareは[未確認事項](未確認事項.md)で扱う。
