# 画面とデザイン見本の照合

## 指示と経緯

2026-11-06の利用者指摘「実装のDiagnosticsとHTMLとだいぶ印象が違う。他の画面も含めて精査不足」を受け、実際に描画した画面とHTML見本を並べて照合した。同日の先行点検（[デザイン案の未反映](../../backlog/未実装課題.md#デザイン案の未反映2026-11-06の点検)）はコードと文言の読み取りだけで行い、Diagnosticsを「デザインどおり」と判断していた。これは見た目を確認しない誤った判断であり、本書の照合で訂正する。

## 方法

| 項目 | 内容 |

| 実行 | 通常作業フォルダを使わず、scratchpadの別worktreeに一時UI試験（`ZZAuditScreensUITests`、commitしない）を置いて実行。専用Simulator `rc-audit-iphone`（iPhone 17 Pro、iOS 27.2）。`RIDEINTERCOM_LOCAL_TESTING=1`、`RIDEINTERCOM_ACCOUNT_FIXTURE=signed-in`、Standardは日本語、Advancedは英語。文字サイズは標準 |

## 結果

### 印象が大きく違う画面

| 画面 | HTML見本 | 実装 | 主な差 |
|---|---|---|---|
| Diagnostics Overview | 判定2行（TX・RX）、Pipelineの全段を状態ドットで1行ずつ、Participants・Networkを1行ずつの表、症状ボタン4つ | 旧来の「Current Overview」の4枚のカード（Audio Path「Shared packet audio」、Call「CALL Reconnecting / Offline」、Network Quality「RTT -- / LOSS --」、Invite「INVITE READY」）が先頭に残る。その下のPipelineは大きな文字の箇条書き（「TX: Input — Idle」、段ごとに丸印と「Session: Passing」）。症状ボタンは本文中の文字リンク | 設計で廃止したカードが残り、一覧性のための状態ドット行がない。判定行がない |
| Diagnosticsのページ切替 | 上部のセグメント（Overview・TX・RX・Network・Applied） | 標準の文字サイズでも中央の`Menu`型のPicker（「Overview ⌃」） | 今どのページかと他のページが一目で見えない |
| Diagnostics Network | 経路ごとのカードに「RTT」「Send queue」「Event drops」のラベルと値の2列、見出しに「Updated 2 s ago」 | 「RTT: Not measured」「route event drops: overflow 0, expired 0」のような文の羅列。ラベルと値の列がそろわない | 表ではなく文になっている |
| Diagnostics Applied | 「Requested → Applied」の表。行ごとに値と「Same」「Differs」 | 「Requested: mpeg4AACELD / 48000 Hz / 48000 bps」「Applied: …」の文の羅列。CodecなどのIDがそのまま出る | 一致・不一致の判定が見えない。表示名でなく内部ID |
| Diagnostics TX・RX | 段の行（段名・状態・主な値）と入れ子のeffect | 段の行のカードは近いが、状態の丸が空の円で、未開始の値が「Idle」「Media Idle」の繰り返し | 構造は近い。未開始の見せ方が設計の`Idle`表示（`TX: Idle`と値`Not available`）と違う |
| Standardの通話のシート | 状態ヒーローは左寄せのガラスのカード（種別・人数／名前／状態／経路）。ナビゲーションのタイトルなし | 中央寄せ。カードがなく、大きな丸いグループの記号の下に種別・名前・状態を並べる。上に「通話」のタイトル。操作列の下に「通話が始まるとマイクがオンになります」 | ヒーローの型が違う。設計にないタイトルと案内文がある |
| AdvancedのCall | 接続待ちは`Waiting`（warning） | 1人だけの接続待ちで「Reconnecting / Offline」と赤い警告の記号 | 自分しかいない正常な待ちを異常に見せる |

### 見本の側の古さ

照合の過程で、HTML見本の一部が最新の設計に追従していないことも分かった（「メンバーを追加」の「追加して招待を送る」、接続待ちの「通知は送りません」、招待中の「未参加・再共有」、グループのアバターの緑）。同日に見本を直した。

## 総点検（2回目）

同日の利用者指示「他の画面も実装とHTMLの差を総点検」「細かい違いも親子関係を維持してバックログへ」により、範囲を広げて撮り直した。

| 項目 | 内容 |
|---|---|
| 実行 | 一時UI試験`ZZAuditAllUITests`（commitしない）を別worktreeで実行。iPhone 17 Pro（iOS 27.2）で5試験60枚（サインイン・名前の入力、Standardの一覧・招待・通話のシート・メニュー・確認・横画面、設定の全体・通信経路・開発者向けの高度な設定・アカウント削除、AX3、Advanced）、iPad Pro 11インチ（M5）で1試験11枚（縦・横の一覧・設定・Diagnostics）。全試験成功 |
| 既存の画像 | Apple Watch 3枚（2026-11-03）、Widget・Live Activityの描画試験64枚（2026-11-03） |
| 証跡 | `.validation/design-audit-20261106/screens2/`、`surfaces/`、一覧画像`sheet2_0〜3.png`・`sheet_surf.png`、試験のソース |
| 撮れなかったもの | 試験用の招待URLの受け入れが「この招待を確認できませんでした」で失敗し、保存ユーザーがいる状態（ユーザーの行、1対1の通話、メンバーの行、切替の確認）が撮れなかった。iPadの通話の列、Control、Watchの会話中以外の状態、ダーク表示も未撮影 |

新たに分かった主な差: iPadの一覧が全幅・設定が中央の帯（縦）と左寄せ（横）、AX3で招待中の行が1〜2文字ずつ折り返して読めない、招待のシートが名前を先に入れない旧来の構成、日本語の表示に英語（Speaker、Auto、Internet、Audio Session等）が混ざる、「送信する声を明瞭にする」など用語集で使わない語、Widgetのミュート中にミュートと切断が同じ赤の塗りに見える。差分はすべて[画面実装とデザイン見本の差分](../../backlog/画面実装とデザイン見本の差分.md)に画面ごとの階層で記録した。

## 扱い

実装の差は[画面実装とデザイン見本の差分](../../backlog/画面実装とデザイン見本の差分.md)へ記録した。実装からデザインへ取り込んだ点（人とグループのアバターをどちらも青い円にし、記号で区別する）は[デザインシステム](../../design/デザインシステム.md#共通コンポーネント設計案)へ反映した。iPadの通話の列、Macの実ウインドウ、ダーク表示、会話中の画面、保存ユーザーがいる状態の照合は未実施であり（iPadの一覧・設定・DiagnosticsとAX3は総点検で照合した）、[未確認事項](../未確認事項.md#画面デザインの実環境受入)の範囲として残す。
