# 検証プロセスの終了と回収

2026-10-31、headlessの音声packageがCoreAudio応答待ちになった際、Swift親とは別process groupのXCTest子も所有範囲で回収する必要があったため、Runnerの異常終了処理を修正した。App・package・server本体は変更していない。

| 対象 | 変更と検証 |
|---|---|
| 所有確認 | 開始時に親のPID・UID・起動時刻を記憶し、停止前に子孫を取得。signal直前にPID・UID・起動時刻・commandを照合し、親終了後のPPID変更は許容する |
| 終了 | 所有する子からTERM、残存時だけKILL。直接の子をwaitで回収する。名前による一括停止は行わない |
| 結果保持 | timeout 124、中断130を保持。回収に失敗した場合も元の失敗理由を失わず追加情報として記録する |
| RED／GREEN | 別sessionでTERMを無視する子が残る失敗を先に再現。修正後はその子を回収し、独立の無関係プロセスが生存することを実試験で確認 |
| 自動検証 | schema 8の復旧fixtureを合わせた独立工程でPython 105件、Node 4件成功。失敗・skipなし。551入力のbefore／after byte hash完全一致 |
| 同一性の負例 | 起動時刻・UID・commandの変化、消失、zombieをmockで検査。signal直前の消失も許容。意図的な回収失敗時に元のtimeout結果と直接子の回収を保持 |

証跡は`.validation/runner-cleanup-delivery`。`independent-summary.json`に各試験との対応、`integration-inputs.json`にmainへ取り込んだscript入力との照合を残す。元のRED／GREENと独立検証は`/private/tmp/RideIntercom-runner-cleanup/.validation`に保持する。

`ps lstart`の起動時刻は秒精度であり、敵対的なPID再利用への完全保証ではない。停止前に取得した子孫が対象で、継続監視・常設台帳は追加しない。CoreAudio待ちそのものを修正した結果ではなく、停止したAudioMixer／SessionManagerと独立音声E2Eの再受入は[未確認事項](../未確認事項.md)に残す。
