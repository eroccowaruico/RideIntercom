# 音声開始の完了待ちと中断処理

2026-11-01。WatchをiPhone通話の音声・操作端末へ接続するため、音声sessionの非同期開始と、終了・中断の順序を共通基盤へ実装した。package単独検証を終えてからAppを追従させた。Watchとの媒体配送そのものは、この記録の完了範囲ではない。

## 変更と確認

| 対象 | 実装・確認したこと |
|---|---|
| SessionManager | `requestActive`の呼出時に要求を登録し、native完了を待つ。同じ未完了要求を共有し、古い完了を開始成功として扱わない。終了要求は開始待ちの後に必ず適用する |
| Watch音声基盤 | 非同期activation、Watchで指定できない設定の報告、PCM入出力のcompileを確認。中断・音声サービスresetを通知し、古いnative成功を解除する。解除失敗を成功として隠さない |
| PCMミュート | native voice processingがOFF／非対応でもPCM配送を閉じる。解除失敗では閉じたままにする |
| Appの通話 | activationの実完了後に相手・ログイン・利用権・期限・世代を確認して媒体を始める。終了、相手消失、アカウント切替、中断が遅い完了で取り消されない。native sessionのmanagerをprocess lifetimeで共有する |
| Audio Check | 準備中と録音中を分ける。準備中に取り消せ、取消後の旧完了で録音や次の通話の終了を起こさない |
| 中断と復旧 | 中断開始・音声サービスresetで開始待ち／通話音声／Audio Checkを止める。中断終了通知だけでは送話せず、既存の明示再開へ接続する。通常の音声設定変更では再activationしない |
| 独立音声E2E | 新APIへ追従し、XCTestの非同期teardownで停止完了を待つ。今回確認したのは標準Xcode buildでのcompileであり、新しい実音声測定値ではない |

## 検証範囲

| 工程 | 証跡と結果 |
|---|---|
| packageの非実機試験 | `.validation/watch-audio-foundation-package`。SessionManager 52件、AudioCore 14件成功。Watch arm64／arm64_32とiOS arm64、SDK 27.2／最低OS 26.4のcompile成功。28入力の最終hash一致 |
| Appの競合再現 | activation完了前の媒体開始を2テスト・8 assertionsで再現。中断/resetで開始待ち・動作中が残る問題も先に再現し、修正後の関連Mac試験152メソッド／172実行が成功。`.validation/watch-audio-activation-app-handoff`に21入力hashと結果を保持 |
| 統合macOS | `.validation/watch-audio-activation-native`。通常のXcode schemeで525メソッド／625実行が成功。失敗・skip・runtime warningなし。起動前の保存先確認、専用hostの終了、source一致を確認 |
| 統合iOS | `.validation/watch-audio-activation-ios`。通常のXcode schemeでApp単体試験と`testRecoveryWorkflowInOneLaunch`が成功（512メソッド／612実行）。失敗・skip・runtime warningなし。専用Simulatorの終了、source一致を確認。実機のWatch媒体受入ではない |

packageの実機依存7項目と`OutputDeviceFormatTests`は非実機選択から除外しており、package全試験の成功とは扱わない。以前のCoreAudio HALC待機で停止したnative試験を、同じ条件のまま再実行していない。物理iPhone／Watch、Bluetooth、画面消灯・背景継続、CallKitなしのWatch双方向媒体、電池消費は[未確認事項](../未確認事項.md)で管理する。

Watch対応の次工程ではiPhoneに通話処理を残す。[確定範囲と接続設計](../../backlog/機能拡張の実装前整理.md#watch音声の確定範囲と接続設計)を適用し、Watch独自の通話機能やWebRTC binaryのWatch移植を進めない。
