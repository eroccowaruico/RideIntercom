## 指示と判断

2026-10-21。実装と同じ内容を仕様、統一して求める目的・背景・方針を要求とし、未実装・未確認の管理場所を分ける指示。アプリ実装は変更しない。

| 情報 | 移動先 |
|---|---|
| 製品・packageの目的と共通方針 | requirements。API名・処理順・現在の達成状況は持たせない |
| 現行API・設定・動作・制約 | specの既存責務別文書 |
| 実装する残作業・未採用案 | backlogの未実装課題・改善候補 |
| 実装後の確認待ち | validationの未確認事項 |
| 実行済み試験と条件 | validationの自動検証範囲・history |
| Cloudflare準備と費用仮定 | developmentの試用手順・費用試算 |
| 初期構想と当時の対応 | validation/history。現在の完了状況として参照しない |

実装の制限（nilで返す統計や非対応OSでのエラー等）は、未確認事項ではなく実態として仕様に残す。未実装の設計案を仕様へ先行掲載せず、課題内の設計案として管理し、実装と同じ変更で仕様へ反映する。

# 製品要求

## 目的と対象

RideIntercomは、音楽を聴きながら、近距離・Internet・中継をまたいでグループの同時通話を続けるiOS/macOSアプリである。iOSを主対象とし、macOSもデスクトップとして使える体験を提供する。接続経路がある限り手動での繋ぎ直しを減らし、経路によらず同じ音声調整と分かりやすい状態表示を提供する。

本書は**アプリが何を満たすか**の正本。[開発方針](../policies/開発方針.md)は**どう作るか**、[文書作成規約](../policies/文書作成規約.md)は**どう記録・保守するか**を定める。実装済みという理由だけで要求を縮めず、未達は残す。

## 根本的な品質要求

| 項目 | 要求 | 具体化 / 確認先 |
|---|---|---|
| 対応端末 | iOSとmacOS両方をサポートすること。iOSがメインのターゲットで、macOSはiOSの単純移植で済ませないこと | [UI設計](../spec/App/UI/全体構成.md)、[開発方針](../policies/開発方針.md)のUI・UX方針 |
| 安全なグループ通話 | 同一グループの認証済み参加者だけで通話し、全経路で音声を暗号化する。秘密・音声内容をログへ出さない | [通信](../spec/App/通信仕様.md)、[ログ記録規約](../policies/ログ記録規約.md)。公開identity・失効は残件 |
| 直感的な操作 | 接続経路によらず音量・mute・effectを同じ意味で使える。接続、音声停止、失敗と再開方法を区別して示す | [使い方](../manual/使い方.md)、[状態遷移](../spec/App/UI/画面・状態遷移.md) |
| アクセシビリティ | 状態を色だけに依存させず、VoiceOver・文字サイズ変更・各端末の入力方法と画面サイズに対応する | [デザイン](../design/デザインシステム.md)、[検証状況](../validation/README.md)。実操作の未確認を残す |
| 音声品質・継続性 | 低遅延、無音時の送信抑制、音楽との共存、機器変化の説明と復帰を提供する。音響品質は実機で評価する | [音声仕様](../spec/App/音声処理仕様.md)、[設定と効果](../manual/設定と音声効果.md) |
| 費用と公開への移行 | 少人数試用で費用を抑え、利用枠と公開運用へ拡張できる構成を持つ。容量だけでなく全課金項目を試算し、継続通話で不要な再接続を要求しない | [費用](../spec/server/Cost.md)、[Worker](../spec/server/Worker.md)。請求上限の保証・公開準備完了とは扱わない |

## Diagnostics との関係

| 項目 | 方針 |
|---|---|
| Diagnostics | 直近の package report / event と metrics を画面表示する |
| Logs | 操作境界、失敗、fallback、handover だけを記録する |

| 生IDの保護 | `Logger.Metadata.event`が`peerID` / `groupID`を除去しSHA-256の先頭12byte（24hex）の`peerIDHash` / `groupIDHash`へ変換 | 個別音量・Isolation操作の生peer ID出力を修正。安定した仮名であり完全な匿名性を保証しない |
| 現行で追加発行 | `audio.pipeline.capture_failed` / `audio.pipeline.rebuild_failed` / `audio.pipeline.receive_failed` | pipeline単位の失敗。下位codecの個別イベント名と同一ではない |
| 現行で追加発行 | `settings.rtc_audio_format.changed` | presetとsampleRateを記録 |
| 設計上の候補・未発行 | `app.deeplink.invite.accepted` / `app.deeplink.invite.rejected` / `app.permission.microphone.denied` | UIの成功・失敗処理はあるが、このevent名の構造化ログを実装済みとは扱わない |
| 設計上の候補・未発行 | `audio.codec.decode_failed` / `rtc.application_data.decode_failed` / `rtc.handshake.rejected` | 現在のreport・error経路と、この名前での発行を区別 |
| 任意metadata | `operationID`等 | 全操作への付与は未統一。event表を実際の収集済みfield一覧として使わない |

実装は[RideIntercomLogging](../../../RideIntercom/App/RideIntercomLogging.swift)と各ViewModelの`.event(...)`呼出、回帰は[LoggingPrivacyTests](../../../RideIntercomTests/LoggingPrivacyTests.swift)を参照する。
