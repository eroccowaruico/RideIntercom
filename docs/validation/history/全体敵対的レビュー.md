# 全体敵対的レビューとローカル検証基盤

## 背景と範囲

2026-10-21。最新取得済みの `8b7a591` を基準に、コード、package境界、ディレクトリ、開発設定、文書、テスト、同梱成果物を点検した。保守性・堅牢性・安定性を改善し、正常系だけでなく、不正入力、保存失敗、順序逆転、遅延、離脱、再接続、検証自体の失敗を扱う。GitHub Actionsの実行費用を前提にせず、ローカルで再現できる自動検証を成果物に含める。

| 境界 | 今回の扱い |
|---|---|
| ファイル全体 | 基準版の253 tracked filesと追加ファイルを[ファイル台帳](全体監査ファイル台帳.json)で管理。調査方法・証拠・限界をファイル単位で区別 |
| packageとApp | packageを先に修正・試験・コミット（`77ae11e`）。そのAPIへAppが追従する工程を別コミット（`d226336`）に分離。最終gateで見つかった再生順の修正もpackageのみの`f9922de`で追加 |
| 人数 | App・RTC・Workerの上限を8に統一。保存済みの退席者が枠を占有して新規参加者を隠さない |
| 維持するもの | 製品要求、package独立性、48 kHzを基本とする機器/mixerと選択可能なRTC形式、暗号化・再接続・既存UI機能、過去文書の情報 |
| 外部環境 | 実Cloudflareへのdeploy、実マイク・スピーカー・Bluetooth・実回線試験は行わない。公開identity、abuse・請求停止基盤の新規開発は含めない |
| 検証範囲の意味 | ソース・契約のレビュー、構造検査、動作テスト、画面の画像確認を区別する。バイナリ内部の全ソース監査、全OS組合せ、形式的な安全性証明を行ったという意味ではない |

## 構造と責務の確認

| 領域 | 所有する責務 | 境界で確認したこと |
|---|---|---|
| App / UI / Platform | 表示・入力・状態、OS画面差分、Keychain操作 | 画面からsecretを直接保存しない。通常画面とDiagnosticsを分離。runtime更新を永続化へ流さない |
| Intercom / Groups | groupの恒久情報、資格、招待 | GroupRepositoryがmetadataと資格の更新順・失敗復旧を所有。ViewModelが未保存の状態を成功表示しない |
| Intercom / Audio / Transport | packageを組み立て、呼出順と選択設定を渡す | 形式を境界ごとに維持・明示変換。受信peerの所有期間に合わせてgraphを解放 |
| AudioCore / Codec | PCM契約、信号検査、符号化 | decoded/mutableな値を信用しない。allocationや整数演算の前にformat・長さ・有限値を検査 |
| SessionManager / AudioMixer / Effectors | OS音声入出力、graph、effectとruntime report | 一つのownerがlifecycleを直列化。音声callbackとsnapshot共有を同期し、callbackの外へ不要なlockを持ち越さない |
| RTC | 暗号化、中継、route、イベント、native接続 | 有界queue、時刻とgeneration、接続の再入、旧channelからの遅延callback、復旧可能性 |
| server | 端末認証、room所有、quota、SFU/TURN lifecycle | object型・サイズ・時間制限、厳密なSDP、期限cleanup、例外時の資源残留 |
| scripts / Xcode / VS Code | 再現可能な開発・検証・成果物更新 | sourceと生成物を混在させない。失敗・未実行・timeoutを区別。既存cacheや利用者データを消さない |
| docs | 要求・規約・仕様・操作・残作業・検証の分離 | 入口からの到達性、参照、現行仕様との一致。履歴の原文を現行成功で上書きしない |

巨大なViewModelを別の巨大クラスに移動する整理は行わず、保存の判断と更新順をGroupRepositoryへ切り出した。画面別UI、ViewModelの機能別extension、Audio/RTCのpackage分離は維持する。診断UIに残る表示分岐や長いテストファイルは、今後の変更単位と実測に応じた整理対象であり、ファイル数の増加自体を品質向上とは扱わない。

最初のclean gate（`.validation/20261021-182229-238181`）ではSessionManagerの最初のrender blockに音声が出ない失敗を検出した。独立するmacOS/Worker/pair/script試験の完了後、修正に移るため進行中のiOS試験をSIGINTで中断した。runnerはinterruptedを記録し、そのrunのSimulatorをshutdownした。成功runとして数えない。隔離コピーと20並行fixtureで再生開始順の問題を再現し、待機時間の追加やassertion緩和をせず、bufferを積んでから再開する実装へ修正した。Appleの[play(at:)の契約](https://developer.apple.com/documentation/avfaudio/avaudioplayernode/play%28at%3A%29)とも照合した。

macOS起動確認はApp自体が起動済みでも物理pathの差で失敗した。path正規化の修正後、`/tmp/ride-macos-launch-fixed.log`にbuild/launch成功を記録した。他checkoutで動作しているAppは停止しない。

最終gateの内訳は、9 package合計159 test定義（RTC 50 + native 2を含む）、Worker 20、Swift/Worker pair 1、Python 25、Cloudflare script 4、macOS App 82、iOS App/UI 86。各ツールの件数であり、platformを跨ぐ重複やparameter展開を単純合計した固有ケース数ではない。失敗・skipは0、両xcresultのruntimeWarningsは空。Xcodeのbuild logには前述のAppIntents metadata警告が残る。

検証環境はmacOS 27.0.1 / Xcode 27.1 (27A9275) / Swift 6.4 / Node 26.12.0 / npm 11.20.0。iOSは専用iPhone 17 Pro Simulator / iOS 26.4.1。run終了時に専用Simulatorをshutdownした。最終gate後の変更は本記録とファイル台帳の確定だけで、実装・テスト・設定のhashは検証対象から変更していない。文書参照・開発設定・diff検査を再実行して記録を確定する。

新規VAD試験の最初の `-only-testing` 指定は0件実行だったため、成功証拠から除外した。後のApp全件実行で実テストの成功を確認した。シェルsandbox内のcache/workerd起動不可と、移動したDerivedDataの古い絶対pathによる失敗は環境失敗として記録し、新しい外部cacheで再実行した。成功だけを残して原因を隠さない。

| 低・toolchain警告 | XcodeのAppIntents metadata抽出が未リンクを警告 | AppIntentsを利用していない。無関係なframework追加や全warning抑制はしない。警告ゼロ要求の未達として記録 | Xcodeの対応/必要なAppIntents導入時に再確認。コンパイラ警告と区別して追跡 |

この一覧は発見できたリスクの記録であり、未発見リスクがないという保証ではない。要求・既存履歴を削ってリスクを小さく見せず、今後の実装・受け入れの入口として保持する。
