# 責務分解と保存復旧の検証記録

## 依頼の背景と採用範囲

全体監査後に残った大きなAudioMixer / SessionManager、診断画面、テストの責務を整理し、遅い処理へ設定変更Taskが積まれる問題と、Keychain / UserDefaults間の強制終了時の不整合を改善する依頼。クリティカルなアプリではないという条件に合わせ、保証範囲を明示した最小限の保存復旧と待機制御を採用した。GitHub Actionsの自動CIは追加せずローカル検証を正本とする。

基準は`f870c03556bc4d19597b7f37e3081af21e426c4c`。package工程を先に完了し`39bd0c2`へ独立commitした後、App工程を行った。過去の[全体監査](全体敵対的レビュー.md)と全ファイル台帳は当時の記録として保持し、本変更の確認と混同しない。

| 対象 | 変更前と懸念 | 採用した構造と保持範囲 |
|---|---|---|
| AudioMixer | graph、model、bus、PCM port、normalizerが一つの大きなfile | 同一module内の責務別fileへ分離。公開API・排他・callback寿命・変換を維持し、新packageは追加しない |
| SessionManager | OS差分とsession/入出力stream owner、voice processingが密集 | model、owner、共通backend、OS別extension、PCM helperを分離。プラットフォーム共通経路を維持 |
| 診断画面 | 送信559行・受信827行に表示条件計算と描画が混在 | 入力snapshot、送受信の純粋なprojection、描画部品、画面構成へ分離。Live画面39/45行。表示情報・順序・識別子・更新周期を維持 |
| Appテスト | 1942行の単一fileとbackend helperの混在 | feature suiteとSupportへ分離。最大のAudioPipeline suiteは514行で、関連する実音声assertionを一緒に保つ。テスト名の移動は[対応表](責務分解テスト対応.json)へ保存 |
| 保存 | 同期例外ではrollbackするがKeychain更新とUserDefaults保存を跨ぐ強制終了に整合点がない | 不変の鍵versionを準備し、atomic JSON manifest replaceを唯一のcommit点にする。未参照鍵は後で回収。旧データはcommit後にだけ削除 |
| 復旧UI | 破損一覧を保護して書込停止するがApp内の復旧操作がない | Reload、鍵欠落時の再招待、退避付きresetとCancel。未知schemaは対応版へ案内。identity・音声・Internet設定を保持 |
| 設定待機 | 音声待ちはboundedだが、遅いRTCへ設定Task chainが増える | 最大64commandのtyped queueと単一worker。順序境界内の設定だけ最新へ置換。重いRTC生成は実行時に限定 |
| 過負荷復旧 | 待機を捨てた後に希望設定が適用されない可能性 | 上限超過で停止し、明示再接続に最新設定を復元。非協調の音声送信も実行中1件を保持し新Taskを重ねない |
| 検証host | App単体テストでもhost起動が実データの移行に到達し得る | buildのStorageNamespaceでApplication Support・defaults suite・各Keychain serviceをrun単位に隔離。本番のテスト専用起動分岐は追加しない |

## 残すリスクと割り切り

| リスク | 現行の抑制と限界 | 復旧・確認 |
|---|---|---|
| 電源断・媒体故障 | atomic replaceはプロセス中断の整合点。fsyncを含む永続transactionや外部backupはない | 実OS kill/lockと電源断は未検証。独立したデータ消失は再招待。電源断耐久性を保証しない |
| 例外がcommit後に発生 | UIでは成功と言えなくても新manifestは確定済みの場合がある。旧鍵へrollbackしない | Reloadで確定したsnapshotを読み直す |
| 鍵回収失敗 | 正常な一覧を取り消さず、不要鍵が一時的に残る | 回収待ちを表示し次の正常読込/commitで再試行。任意のserviceやInternet資格は削除しない |
| 旧版の同時利用・downgrade | 新形式へ一度だけ移行。旧版への二重書込や逆移行はない | 新版で利用を継続。未知schemaはresetせず対応版を案内 |
| 破損・identity不正 | 元データを自動上書きしない。group resetはidentity自体を直さない。退避は不透明な元bytesであり診断ログへ出さない | 明示resetはgroup単位の再出発。履歴選択・推測修復・自動restoreはない |
| 多重起動 | flockとsnapshot比較で同時書込・stale上書きを拒否。同期APIのまま上限内の小さな保存を扱う | もう一方を閉じReload。遅いKeychainのUI待ちを完全に除く非同期化は今回対象外 |
| 非協調RTC | commandと音声は各1件実行中。待機件数とpayloadを制限してもvendor awaitを強制終了できない | RTCが戻ってから停止・再接続。停止完了の期限は保証しない |
| FIFOの過負荷 | 順序を要するmessageを黙って間引かず停止するため通話が中断し得る | UIで明示再接続。設定の中間値は意図して上書きする |
| 自動試験の限界 | fake gate・故障注入・offline PCM・専用Simulatorが対象 | 実音声、Bluetooth/有線、10分通話、Cloudflare SFU/TURN、VoiceOver、Mac/iPad表示は[未確認事項](../未確認事項.md)へ継続 |
| ローカルgate | 自動CIなし。全段階成功・ソースhash不変を入口で検査するがpushをサーバー側で強制しない | main push前に実行し証跡を保存。検証namespaceとSimulatorは再調査用に保持 |

現行の契約は[アーキテクチャ](../../spec/アーキテクチャ.md)、[通信仕様](../../spec/App/通信仕様.md)、[自動検証範囲](../自動検証範囲.md)、利用者の導線は[困ったとき](../../manual/困ったとき.md)を参照する。
