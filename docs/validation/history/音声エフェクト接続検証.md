# 音声エフェクトのApp接続と自動検証

> この記録は記載時点の実装・コマンド・結果。現在の受け入れ状況は[検証一覧](../README.md)を参照し、当時の成功件数を現行HEADの再実行結果と読み替えない。

## 指示・背景と対象

| 項目 | 内容 |
|---|---|
| 指示 | 初回dev復旧で残った音声エフェクトをAppへ接続し、自動テスト・文書更新・コミットまで行う |
| 起点 | `codex/restore-dev-calls` の `243deb5`。開始時は作業ツリーclean |
| 責務境界 | Effectorsの生成・runtime契約を先に修正・検証・コミット。その後Appの構成とUI・診断を適応 |
| 対象 | SoundIsolation、DynamicsProcessor、PeakLimiterの実Audio Unitを既存AudioMixerへ接続 |
| 対象外 | 実機音響評価、Internet通話完成、push、merge、deploy |

## 接続結果

| 系統 | 実際の順序 | 設定変更 |
|---|---|---|
| TX | 入力/VAD → SoundIsolation → DynamicsProcessor → PeakLimiter → target format / codec / RTC | Isolationのbypassを即時変更 |
| RX peer | decoded PCM / peer volume → SoundIsolation → RX master | peerごとのIsolation bypassを即時変更 |
| RX master / output | SoundIsolation → master volume / mute → rx-output PeakLimiter → hardware format sink | master Isolation bypass、volume / muteを即時変更 |
| Audio Check | 録音PCM → RX経路（Isolation bypass）→ 最終Limiter → 出力 | 通話への移行は既存の世代・所有管理を維持 |

Mixerのeffectはbus faderより前段に入るため、最終Limiter用にrx-output busを設けた。master volume 200%をLimiterの後で掛けない。エフェクト変更ではengineを再生成せず、schedule済みPCMとmedia接続を維持する。

## パッケージ工程

| 変更 | 根拠・検証 |
|---|---|
| 固定Apple effect生成 | Apple SDKの `AVAudioUnitEffect(audioComponentDescription:)` を使い同期生成する。render callbackから呼ばない。外部AU extensionの非同期ロードは対象外 |
| VoiceIsolation runtime | 実Audio Unitのbypassをruntime snapshotへ反映。修正前はbypassでもactiveを返すことを `bypass-red.log` で再現 |
| 実ノードテスト | SoundIsolation 8件、DynamicsProcessor 5件、PeakLimiter 5件成功。生成・設定再適用・runtime一致を確認 |
| コミット | `b124ba8`。App実装はこの工程では未変更 |

## 自動検証

証跡ディレクトリは `/private/tmp/rideintercom-effects-validation/`。実行日は2026-10-21（JST）、Xcode 27.1 / Swift 6.4、macOS 27.0.1 arm64、iPhone 17 Pro Simulator / iOS 26.4で実行した。システムのxcode-selectは変更しない。

| 検証 | 結果・証跡 |
|---|---|
| 修正前のApp回帰 | `app-red-all.xcresult`。42件成功、追加2件失敗。未接続effectと音量適用後の出力ピーク超過を再現 |
| TX実PCM | 48 kHz / 440 Hz / 振幅0.8の1秒音声を送信graphへ入力。codec復号後の非ゼロ信号とDynamicsによるRMS低下を確認 |
| RX実PCM | 2 peerへ振幅0.9の1秒音声、master volume 200%。全出力が有限・絶対値1.01以下かつ非無音であること、最終sinkがLimiter後段であることを確認 |
| 設定と診断 | TX / peer / masterのIsolation active/bypassedと実Audio Unit runtime reportが一致。切替でengine生成数が増えない |
| 起動失敗・解放 | 実effectを構成した後にengine.start失敗を注入。graph/runtime reportを解放し、再試行成功。通常停止後もruntimeを除去 |
| 全package | 9 package / 122件成功、RTCNativeWebRTC build成功。全段階exit 0。`packages/results.tsv` |
| macOS App | 46件成功、失敗・skip 0。`macos-final2.xcresult` / exit 0 |
| macOS通常起動 | build / launch成功、exit 0。`macos-launch.log` |

| 画面証跡 | `ui-final/manifest.json` とCall / Settings / DiagnosticsのPNG・accessibility tree。CallとSettingsの操作表示も画像で確認 |

## 再現コマンド

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
VALIDATION_DIR=/private/tmp/rideintercom-effects-validation/packages scripts/validate.sh packages
scripts/validate.sh macos
scripts/validate.sh ios
scripts/build_and_run.sh
```

今回のApp回帰は初回復旧時のDerivedDataを再利用した。Simulatorは専用端末 `5DDF37BD-AAC5-4930-AB0D-FA16412C9E18` を再利用し、次の形式で実行した。

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild test \
  -project RideIntercom.xcodeproj -scheme RideIntercom \
  -destination 'platform=iOS Simulator,id=5DDF37BD-AAC5-4930-AB0D-FA16412C9E18' \
  -parallel-testing-enabled NO -only-testing:RideIntercomTests \
  -derivedDataPath /private/tmp/rideintercom-dev-validation/automation-ios/DerivedData-iOS \
  -resultBundlePath /private/tmp/rideintercom-effects-validation/ios-unit-final.xcresult
```

UI最終検証は上記の `-only-testing:RideIntercomTests` を `-only-testing:RideIntercomUITests`、結果パスを `ios-ui-effects3.xcresult` に変更して実行した。macOS最終検証はdestinationを `platform=macOS`、単体targetを `RideIntercomTests`、DerivedDataを `/private/tmp/rideintercom-dev-validation/automation-macos/DerivedData-macOS`、結果パスを `macos-final2.xcresult` にして実行した。各結果の件数は `xcrun xcresulttool get test-results summary --path <xcresult>` でも確認し、同ディレクトリへsummary JSONを保存した。

xcresultは上書きできないため、再実行時は新しい結果パスを指定する。利用者の実機・Simulatorデータは削除しない。
