# 要求と開発規約の構造整理記録

基準commitは`5ee1ec2`。前回の文書整理後に、要求の混在、三重管理する開発方針、旧計画prompt、空ディレクトリを点検した。App/package/Workerの実装は変更していない。

## 発見と対応

| 発見 | 対応 / 現在の場所 |
|---|---|
| requirements/requirements.mdに製品要求と文書規則・開発環境要求が混在 | [製品要求](../../requirements/製品要求.md)、[開発方針](../../policies/開発方針.md)、[文書作成規約](../../policies/文書作成規約.md)へ分離 |
| requirements/log.mdが実装上のログ規約なのに一般要求に見える | [ログ記録規約](../../policies/ログ記録規約.md)へ移動。Appでの発行状況と設計上のイベントを区別 |
| Appからpackageへの要望がspec/Appにあり、未達要求と現行仕様が混在 | [パッケージ改善要求](../../requirements/パッケージ要求.md)へ。編集責任・追記方法は文書作成規約へ。パッケージ工程で編集しない方針を維持 |
| AGENTS / CLAUDE / Copilotに同一6374文字の規約本文 | 全条項を共通正本へ移し、3入口から必須参照する。ルールを省略した独立コピーを作らない |
| 旧計画が実行用promptとして残り、削除済みIntercomCoreや旧UI配置を参照 | development/historyの3計画へ、原文をそのまま引用保存。現行との差と参照先を付記。実行用promptを残さない |
| 初期構想・状態確認の表題が名前や用途とずれていた | 内容を維持して「初期構想と対応経緯」「通話・音声・接続状態の見方」へ変更 |
| 文書移動後の空ディレクトリ | docs/design system、docs/spec/scriptsとBuildWebRTC、docs/spec/App/setting parameters配下をrmdir。計画移動後の.github/promptsもrmdir |
| Xcode内部に空configuration directory | project.xcworkspace/xcshareddata/swiftpm/configurationはツール管理領域のため保持。文書の取り残しとは区別 |

追跡ファイルに0 byte、.bak/.old/.tmp、copy/backupを名前に含む残骸は見つからなかった。生成物・依存・バイナリの内部は文書整理の対象に含めない。API名・package名・Xcode/VS Code/GitHubが要求する標準ファイル名は変更しない。

## 情報保持と要求の分類

| 分類 | 保持した内容 |
|---|---|
| 製品要求 | 通話、経路維持、中継、音声、設定、費用・公開、プライバシー、UI/アクセシビリティ。未達・初期候補を維持 |
| 開発方針 | 品質工程、TDD、App/package工程分離、共通化、設計原則、UI/技術選定、音声/通信方針、判断基準、開発環境要求 |
| 文書作成規約 | 採番禁止、記述形式、計画の詳細度、更新責任、要求の追記条件。命名・履歴・空ディレクトリの扱いを追加 |
| 過去計画 | .github/promptsにあった3文書の本文を完全一致で保持。旧パス・採番は引用内に限定 |
| 前回の文書整理記録 | 当時の48文書対応表・訂正理由を履歴として保持。旧パスは当時の情報であり現在の正本ではない |

「アプリを作り直す前提」という旧時制は現行の継続開発・App追従の表現へ変更し、暫定実装をpackage要求一覧に残さない方針自体は維持した。製品要求を実装に合わせて削ることはしていない。現行要求の入口は[要求の入口](../../requirements/README.md)。過去計画の未採用案を現行要件へ自動昇格させない。

## 継続検査

文書検査へ空ディレクトリ、AGENTS/CLAUDE/Copilotのリンク、原文引用の長いfenceを追加。新規3テストの失敗を先に確認し、既存4件と合わせて検証する。ログは `/private/tmp/requirements-structure-red.log`。

同じ採番禁止・図表優先・更新責任の条項は重複本文を統合し、禁止・義務・理由を保持した。「アホでもバカでも、低レベルなモデルでも」という原表現は「経験や前提知識の少ない実装者やモデルでも」に改め、具体的な手順を求める要件は保持した。パッケージ改善要求には、既存の不足に対応する解消条件を明記した。
