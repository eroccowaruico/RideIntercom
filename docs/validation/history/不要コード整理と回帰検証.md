# 不要コード整理と回帰検証

## 対象と判断

2026-10-21、`codex/restore-dev-calls`で実施。開始点は`4bc313c`、最終フル検証のソースは`ef6b9b0`。元のcheckoutとmain/devの履歴は変更せず、push・merge・deployは実施しない。

追跡されたApp・9パッケージ・native・Worker・テスト・scriptsを対象に、宣言と参照、実行経路、OS/protocolの入口、文書との対応を調べた。参照数だけで削除せず、現行経路を保護する回帰テストを先に用意した。生成済みSDK・依存cacheをアプリの未使用ソースと混同しない。

| 対象 | 整理した内容 | 維持する実処理 |
|---|---|---|
| Local旧音声経路 | per-routeの音声API、旧envelope・暗号化・sequence filter・media session・二重jitter/timer | GroupRelayの認証・暗号化・中継、CallSession共通受信待ち、Local handshake |
| route構成 | 未使用UnavailableCallSession、factory wrapper、表示名引数、RTP所有権/能力モデル | RTCCallRouteと実routeの注入、CallSessionFactory、利用可能経路・codecの診断 |
| WebRTC | 未生成のoffer/個別membership/trickleイベント、空の応答API、未使用candidate配送 | 完全SDP交換、membership snapshot、ICE資格、同一SFU接続・DataChannel、native SDP endpoint |
| Codec / Mixer | 未使用AudioCodec facade、誤解を招くForTesting名 | Encoder/Decoder、runtime report、実tapからのsink配送 |
| App | 未使用UseCase・standby分岐・手動参加者追加・旧診断snapshot/builder/summary・定数・重複hash | 現行ViewModel lifecycle、Diagnostics行、実音声pipelineとpackage report |
| fixture | サンプルgroupとInMemoryストアをTestsへ移動。ViewModelの保存先を必須注入 | 製品compositionはUserDefaults / Keychain。公開されたbackend境界からテストを注入 |
| Worker | noUnusedLocals / noUnusedParametersを型検査へ追加 | HTTP/WS/DOの本番経路。外部サービス代替はtest側だけ |

Appの未参照候補を再走査し、残ったNSApplication delegateや`@main`は実行時入口として保持した。SessionManager等の有効な公開操作、nativeのSDP受理、SDKが要求するdelegateメソッドも保持する。追跡ソース・文書の空ディレクトリはない。SwiftPM/Xcodeが生成するcache内部の空folderは管理対象外であり、再生成されるため削除対象にしない。

一括削除案は自動承認レビューで拒否された。現行経路のテストと修正を`ed5ed9e`へ保全後、責務ごとの小さい削除に分けて確認・コミットした。

## 発見した不具合と先行テスト

| 不具合・検証漏れ | 修正と検証 |
|---|---|
| 新しい音声を再生した後、待機中だった古いsequenceが再生される | enqueueだけでなくdrain時も再生済みsequenceを検査。先行テストで`[9,11]`の逆行を再現し、修正後`[11]`と破棄件数を検証 |
| 作成者には鍵がなく、招待だけ開発用代替鍵を使う | 新規groupで256bit乱数鍵を保存・読戻しし、接続・招待・再接続で一致させる。作成者/参加者をAppテストで照合 |
| 欠損鍵で接続し、存在しない招待鍵を補う | 開発用代替鍵を廃止。接続と招待生成を拒否し、有効な招待/新規作成を案内 |
| 保存失敗や空鍵の招待を処理する | group作成・参加の確定前に保存結果を確認。空鍵は保存前に拒否し既存鍵を維持。各条件の修正前失敗を確認 |
| 古いLocal APIだけを通る合成音声テスト | 現行GroupRelay暗号化と共通受信待ち、App decodeへ移行。双方向各30,000フレーム・9,600,000サンプル、順序・誤差・duplicate拒否を確認 |
| 人数/中継の境界と配送モード | 8人chain・最大path・9人目拒否と退室後受入、1024 replay window、peer単位の待機解除、Local配送モード、実nativeのreliable制御/unreliable音声を検証 |
