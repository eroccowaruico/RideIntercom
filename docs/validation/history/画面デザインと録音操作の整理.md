# 画面デザインと録音操作の整理

## 指示と範囲

2026-11-02、HTMLの主要な画面コンセプトとテーマを採用しつつ、標準コントロールで既存操作を保ち、StandardとAdvancedをそれぞれ改善する依頼。一般画面の英語を残し、設定の録音・停止を同一ボタンにする。Watchは表示のみを対象とし、録音の既存不具合は追わず、検証済みの小単位からコミットする。

## 設定の録音ボタン

`AudioCheckPanel`の同一`audioCheckButton`が、待機時は既存の開始処理、準備・録音・再生中は既存の停止処理を呼ぶ。開始制約・音声処理・入出力表示は維持し、標準Formの先頭行に配置した。[現行仕様](../../spec/App/UI/Settings.md)を参照する。

| 確認 | 結果・証跡 |
|---|---|
| iPhone Simulatorの表示 | `.validation/settings-display-final-20261102/`。標準schemeのbuild、隔離host確認、UIテスト1件内のStandard／Advanced × 英語／日本語の4条件が成功。開始ボタンの一意性・有効状態・翻訳・別停止ボタンの不在と画像を確認した。録音は開始しない |
| ソース対応・回収 | 同runの`inputs-before.json`と`inputs.json`が共通build番号の前進を除き一致。専用Simulatorのshutdown成功。xcresultは失敗・skip・実行時警告なし |
| 進行中のボタン | `isInProgress`による同一Button内のaction／label切替と、進行中に停止を無効化しない条件をコードレビュー。既存録音不具合のため実録音中の押下・録音再生完了は今回の成功範囲に含めない |
| 既存録音経路 | `.validation/design-one-button-red-20261102/`はシステムduckingのVoiceProcessingIOでクラッシュ。`.validation/design-final-20261102-0804/recording-ui.log`ではduckingをオフにしても`Microphone capture failed`。この経路の修正・追加実験は利用者指示で停止。音声fixtureは追加せず、既存native録音テストの本文は維持 |
| Macの検証制約 | `.validation/design-final-20261102-0804/design-macos-build.log`ではWidgetの開発用provisioning profileに現在の署名証明書が含まれず、build前に失敗。署名・アカウントを変更していない |

初回の表示テストは日本語タブを英語で探して失敗した。テストの操作対象を各言語の設定タブへ揃えた最終runを受入対象とし、先行runの失敗は保持する。音声設定の探索を試した中間runも製品の成功証跡として扱わない。

## Watchの表示

接続先の見出し、記号付き状態、広い送話ボタン、通常時の青いnavigation背景と利用不可時の黒い背景を適用した。Debug録音チェックも同じボタン内で既存の開始／停止操作を切り替える。音声controller、通信、押下gesture、scene lifecycleは変更していない。

上記`settings-display-final-20261102`のiOS buildで埋込Watchアプリもコンパイル・検証された。表示コードの独立レビューを実施した。Watchの実画面・送話・録音・接続の成立は確認しておらず、利用者の指示に従い音声の追加実験は行わない。
