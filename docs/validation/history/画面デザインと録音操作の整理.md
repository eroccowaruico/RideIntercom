# 画面デザインと録音操作の整理

## 指示と範囲

2026-11-02、HTMLの主要な画面コンセプトとテーマを採用しつつ、標準コントロールで既存操作を保ち、StandardとAdvancedをそれぞれ改善する依頼。一般画面の英語を残し、設定の録音・停止を同一ボタンにする。Watchは表示のみを対象とし、録音の既存不具合は追わず、検証済みの小単位からコミットする。

## 設定の録音ボタン

`AudioCheckPanel`の同一`audioCheckButton`が、待機時は既存の開始処理、準備・録音・再生中は既存の停止処理を呼ぶ。開始制約・音声処理・入出力表示は維持し、標準Formの先頭行に配置した。[現行仕様](../../spec/App/UI/Settings.md)を参照する。

| 確認 | 結果・証跡 |
|---|---|
| iPhone Simulatorの表示 | `.validation/settings-display-final-20261102/`。標準schemeのbuild、隔離host確認、UIテスト1件内のStandard／Advanced × 英語／日本語の4条件が成功。開始ボタンの一意性・有効状態・翻訳・別停止ボタンの不在と画像を確認した。録音は開始しない |
| ソース対応・回収 | 同runの`inputs-before.json`と`inputs.json`が共通build番号の前進を除き一致。専用Simulatorのshutdown成功。xcresultは失敗・skip・実行時警告なし |
| 進行中のボタン | `isInProgress`による同一Button内のaction／label切替と、進行中に停止を無効化しない条件をコードレビュー。既存録音不具合のため実録音中の押下・録音再生完了は今回の成功範囲に含めない |
| 既存録音経路 | `.validation/design-one-button-red-20261102/`はシステムduckingのVoiceProcessingIOでクラッシュ。`.validation/design-final-20261102-0804/recording-ui.log`ではduckingをオフにしても`Microphone capture failed`。この経路の修正・追加実験は利用者指示で停止。音声fixtureは追加せず、既存native録音テストの本文は維持 |
| Macの検証制約 | `.validation/design-final-20261102-0804/design-macos-build.log`ではWidgetの開発用provisioning profileに現在の署名証明書が含まれず、build前に失敗。署名・アカウントを変更していない |

初回の表示テストは日本語タブを英語で探して失敗した。テストの操作対象を各言語の設定タブへ揃えた最終runを受入対象とし、先行runの失敗は保持する。音声設定の探索を試した中間runも製品の成功証跡として扱わない。

## Watchの表示

接続先の見出し、記号付き状態、広い送話ボタン、通常時の青いnavigation背景と利用不可時の黒い背景を適用した。Debug録音チェックも同じボタン内で既存の開始／停止操作を切り替える。音声controller、通信、押下gesture、scene lifecycleは変更していない。

上記`settings-display-final-20261102`のiOS buildで埋込Watchアプリもコンパイル・検証された。表示コードの独立レビューを実施した。Watchの実画面・送話・録音・接続の成立は確認しておらず、利用者の指示に従い音声の追加実験は行わない。

## StandardとAdvancedのテーマ・導線

青いtint、Standardの淡い背景と通話先の見出し、記号付きの通話状態、標準glassボタンを適用した。AdvancedにはUsers／Groupsタブを加え、既存の詳細CallとGroups導線・参加者操作・診断を維持した。音声・通信・保存の処理は変更していない。

| 確認 | 結果・証跡 |
|---|---|
| タブ切替の変更前確認 | `.validation/advanced-tabs-red-20261102/`。単体5件中、AdvancedのUsers／GroupsをCallへ戻す従来挙動への期待2件が失敗し、変更対象を確認 |
| 単体・ライトの操作 | `.validation/theme-navigation-final-20261102/`。単体5件とUI2件が成功。英語で縦横回転・設定シート・ミュート操作、Standard／Advanced切替・Users／Groupsへの移動・通話とミュートの保持・終了・表示設定の再起動後維持を確認 |
| ダークの操作 | `.validation/theme-dark-final-20261102/`。UI3件が成功。特大文字の診断・横画面の設定・日本語の一覧と設定、録音開始ボタンのStandard／Advanced × 英語／日本語の4条件を確認。録音そのものは開始しない |
| ソース対応・回収 | 各runの入力snapshotは共通build番号の前進を除き一致。専用Simulatorをshutdown。最終成功段階のxcresultは件数非ゼロ、失敗・skip・実行時警告なし |
| 実画面 | xcresult添付画像を抽出し、ライトの英語通話・横画面の音声操作、ダークの日本語一覧・設定、特大文字の英語診断と横画面設定を確認。標準タブとスクロールで各操作へ到達できる。標準glassの終了操作はdestructive roleとEnd Call文言を保ち、ナビゲーション領域はOS標準背景を維持 |
| Mac | 同runの`macos-compile.log`。標準scheme／Debug-Validationの`xcodebuild build CODE_SIGNING_ALLOWED=NO`でコンパイル成功。署名付きbuildの既存問題とは別であり、Macの起動・UI操作を証明しない |

初回のダークrunでは、テスト補助処理が画面外のRecent Groups見出しだけで到達判定し、新しいGroupsタブへ進んだため末尾の旧画面検証が失敗した。画面ルートのgroupSelectionListも判定するようテストだけを修正し、旧導線を確認する目的は維持した。この失敗を含む元runは保持する。ライト2件と単体5件は同じ製品ソースで成功しており、補助処理を使わないため再利用する。

本検証はiPhone 17 Pro Simulator（iOS 27.2）、標準scheme／Debug-Validation、既存のsigned-in・local-testing fixtureを使用した。実サービス認証・相手への音声到達・実機VoiceOver・iPad実画面・Macの署名付き起動はこの結果に含めない。録音の既存不具合とWatch音声は指示どおり追加調査しない。画面構成案の残りは[バックログ](../../backlog/一般向け招待と利用制限・料金の見直し.md#既存導線を保つ表示修正)に保持する。

## 端末本体の録音開始修正

2026-11-02、利用者から録音不具合だけの修正を再開する指示を受けた。Watchは実装を保持し、端末本体の送信エフェクト込み録音を対象にする。他音声処理の深掘りは行わず、完了分は仕様へ、残る調査は改善候補へ分ける指示を適用した。

Audio Checkが音声pipelineを所有する間だけnative入力のother-audio duckingを無効にする。送信エフェクト・VAD・codecと保存設定は保持し、通常通話には既存設定を再適用する。[現行仕様](../../spec/App/音声処理仕様.md#audio-check)と[改善候補](../../backlog/改善候補.md#voiceprocessingioと既定デバイスの開始安定性)を参照する。

| 検証 | 条件と結果 |
|---|---|
| 変更前 | `.validation/recording-button-baseline-20261102b/`。Settingsからの開始でVoiceProcessingIO切替中に`IsFormatSampleRateAndChannelCountValid`例外を再現。`.validation/recording-button-unit-red-20261102/`では、録音中だけduckingを無効にし通話設定を保持する追加テストが期待した4箇所で失敗 |
| 既定デバイスの限界 | `.validation/recording-button-green-20261102/`。録音時のVoiceProcessingIO切替を除いても、既定音声デバイスのままではnative入力の形式検証に失敗。通常通話のVoiceProcessingIOでも例外を観測。これらの根本調査は改善候補へ分離 |
| iPhone Simulatorの実録音とUI | `.validation/recording-button-pinned-green-20261102b/`。iPhone 17 Pro／iOS 27.2、標準scheme・Debug-Validation。専用Simulatorの入力と出力を同じ実デバイスへ一時固定し、App 32件とUI 1件が成功。Settingsの同一ボタンで録音・5秒再生・再開始・途中停止・再録音を確認。各完了の入力240,000 frames、出力251,520／244,800 frames、終了後の入出力停止を観測。このUI実行の入力は無音のため有音品質の証明には用いない |

Simulatorの入出力固定は検証環境だけに適用し、終了時に元の割り当てと音量へ戻す。Mac全体の既定デバイスは変更しない。端末本体の録音修正を、Watch音声・実機iPhone・Bluetooth・通常通話の他音声処理全般の受入へ広げない。
