# 複数端末の経路断と自動復旧

2026-11-01の複合通信障害への要望に対し、`a7786236`から隔離したRTC工程で`GroupContinuityTests`の仮想経路を拡張した。既存のRouteManagerと暗号化GroupRelayで成立したため、製品コードは変更していない。

| 検証 | 確認できた範囲 |
|---|---|
| 4端末・3経路の同時断 | Localだけ、Internetだけ、両経路のgateway 2台を構成。2端末のInternetと別端末のLocalを同時に失敗させ、残存Localの会話を確認 |
| 異なる復帰順 | Internetだけの端末が先に戻る場合とgatewayが先に戻る場合をparameterized testで確認。Appからstartし直さず既存retryで再参加し、相互の新しい音声が届く |
| 別ネットワークへの移動 | 最後のLocalを他の参加者のいないネットワークへ復帰。Localの発見と相手への到達性を分け、Internet経由で会話を維持 |
| 古い音声と全体切断 | 圏外中に送ったmarkerが復帰後に再生されず、残存経路のある端末群が全体disconnectedへ変化しないことを確認 |
| 影響範囲 | 同じfixtureを使うsuite全3メソッド・5ケースが28.704秒で成功。既存8端末のInternet不達、混在中継とgateway離脱も成功 |
| 入力一致 | RTC関連39入力の試験前後一致。mainへのコピー後も39入力が一致。`.validation/network-recovery-delivery/{source-before,source-after,summary,delivery-check}.json` |

初回は実行環境のsandbox制限で失敗した。その後、新しい試験の最後の経路は既存2→4→8秒のbackoffに入るため、fixtureの一律6秒待機が先に満了した。製品のretryや合格条件は緩めず、その復帰段階の待機に説明と上限を付けた。先行ログと最終`final.log`を保存している。

本試験は経路の失敗通知と到達性を仮想化する。実Wi-Fi／セルラーの揺らぎ、OSによるネットワーク通知、実SFU、Appの本人profile再認証、音響品質・電池消費を証明しない。これらは[混在グループの受入](../未確認事項.md)に残す。
