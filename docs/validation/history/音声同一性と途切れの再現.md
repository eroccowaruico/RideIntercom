# 音声同一性と途切れの再現

## 指示と対象

2026-10-29、利用者から「iPhone同士の音声がブツブツ切れ、実用にならない。複数の音声を用意し、実際のテスト出力が同一性を保つか確認する」と依頼された。実機固有の問題とは扱わず、通信込みのSimulator試験と、通信を外した結合試験で確認した。

対象はHEAD `0280f4d5`上の作業ツリー。音声処理の製品コードは変更せず、E2Eの入力・測定・判定だけを追加した。既存のproject・Package.resolved・開発環境文書の変更は今回の変更に含めていない。各runのsource-manifest.jsonが当時のsourceと設定のSHA-256を保持する。

## 結論

音声の同一性・連続性は不合格。Local / WebRTCの18測定すべてで従来の部分照合は合格水準だったが、全時間を対象にした連続性判定では不合格となった。通信・VAD・送信Isolationを外したiOS単独の2条件でも不合格となり、通信に依存しない音声処理経路の問題を再現した。実機でしか検出できない問題という説明ではない。

| 試験 | 条件 | 結果 |
|---|---|---|
| 判定器の事前試験 | 遅延・音量・音色変化は許容し、100ms周期欠落、500ms無音、1秒繰り返し、順序入れ替え、無音、別話者は拒否 | iOS上の事前3テストが各runで成功。旧判定器の無音・別話者・雑音試験、実session profile試験も含む |
| 英語2種類 | Mac ↔ iPhone Simulator、Local、既定 / PCM16 / Opus、各20秒 | 最終6測定すべて不合格。発話中の低出力率8.4〜30.5%、最長140ms |
| 日本語2種類 | Mac ↔ iPhone Simulator、Local / 実WebRTC＋ローカルSFU、同じ3設定、各20秒 | 12測定すべて不合格。発話中の低出力率14.0〜40.0%、最長220ms |
| 通信なし・20ms入力 | iOS単独、Mixer → PCM16 encode/decode → Mixer → 実出力、VAD / Isolation無効、20秒 | 一致窓82.3%、低出力率15.0%、最長80ms。処理例外なし。実出力の予約リセット12回 |
| 通信なし・100ms入力 | 上記と同じ経路、iOS captureで観測した100ms単位の入力 | 一致窓79.0%、低出力率11.0%、最長100ms。処理例外なし。実出力の予約リセット23回 |
| ランナー回帰 | `python3 -m unittest discover -s scripts/tests -v` | 47件成功 |
| 文書・差分 | 文書リンク検査、`git diff --check` | 成功 |

低出力率は、時間整合した基準の発話区間において、音量比補正後の10ms RMSが基準の10%未満になる割合である。文字認識率や知覚品質の標準スコアではない。全体相関0.65未満の測定は時間整合自体も弱く、率を厳密な欠落量と解釈しない。結合試験の全体相関は0.779 / 0.825であり、時間整合した比較でも欠落を検出した。基準の自然な無音区間は低出力率から除外する。

## 従来テストの見逃しと変更

| 対象 | 従来の制限 | 今回の変更 |
|---|---|---|
| 発話照合 | 750ms断片のうち、良い3区間だけで合格できた | 従来の到達判定に加え、全文の固定時間整合と200ms窓の連続性を必須化 |
| 保存音声 | 判定後に再snapshotを取得してWAV化し、分析中に増えたsampleを含み得た | 判定に使った同じsnapshotを保存。証跡収集時に20本すべてのWAV sample数と測定JSONの一致を確認 |
| 入力音声 | 短い英語2種類 | 約14秒の異なる日本語2種類を追加し、20秒以上のidentityマトリクスで全文を含める |
| 失敗後の証跡 | 最初のassertionで残りの条件が測れない | 連続性不合格は全条件を記録後に失敗。接続断などは即時失敗のまま |
| 切り分け | 実通信E2Eだけでは通信と音声処理を分離できない | `--pipeline-only`で通信・VADなしの20ms / 100ms入力を比較 |

判定定義、音声原文、実行方法は[音声E2Eテスト](../../development/音声E2Eテスト.md)を正本とする。

最初の英語runと日本語runでは、全測定を保存した後の品質assertionに`continueAfterFailure=false`が適用され、品質不合格に加えてtest runnerの終了code 75も記録された。最後の集約判定前だけ`continueAfterFailure=true`へ戻し、英語6測定を再実行した。最終runでは両端末とも実行テスト数1件で、連続性assertionだけが失敗した。日本語runの測定WAV・JSONは全12条件が揃っており保持するが、XCTest summaryには上記終了エラーも含まれる。

## 原因の範囲と未修復

結合試験の20ms入力ではTX sourceの予約リセットは0回だが、RX sourceは36回、実出力は12回だった。100ms入力ではTX sourceが70回、RX sourceが9回、実出力が23回だった。sourceの値は起動からの累計、実出力の値は20秒の測定区間の増分である。

`MixerPCMSource`と`SystemAudioOutputStreamBackend`は、100msの予約予算を超えると`.interrupts`で既存予約を置き換える。実captureでは100ms分のframe、Mixer tapでは複数の20ms frameのまとまった配送が観測される。配送周期と予約予算の境界、およびsinkから再生へ渡す際の時間連続性が調査対象となる。リセット回数と欠落の同時観測は原因候補を絞る証拠であり、各欠落の原因が確定したことや、予算を広げれば解決することを意味しない。

製品の修復は未完了で、品質gateは赤のまま維持する。過去の132測定成功は当時の部分照合基準での到達確認であり、今回の連続性基準での合格実績に読み替えない。修復は[未実装課題](../../backlog/未実装課題.md)、iPhone同士での最終確認は[未確認事項](../未確認事項.md)へ引き継ぐ。
