# 検証アプリの起動前確認

2026-11-01、`a7786236`から隔離したworktreeでCLI検証入口を変更した。build引数だけで保存先の隔離を判断せず、生成されたxctestrunが参照するhostを起動前に確認する。[手順と拒否条件](../../development/自動検証.md#xcodeテストの起動前検査)を現行契約とする。App・packageの製品処理は本工程では変更していない。

| Python回帰 | mainへ統合した7scriptの差分で110件成功。入力は試験前後で一致。`.validation/host-isolation-delivery/python-tests.log`、`source-check.json` |
| Macの実入口 | 共通Runnerによるbuild・host検査・選択単体6件・xcresult受入・所有host回収が全成功。`host-isolation-macos/` |

各native runは399入力の実行前後一致を確認した。最終scriptsとの差は、Mac/iOSでは後から追加した構成検査とそのテストの2ファイル、StoreKitではなし。mainのprojectに以前からある参照13行と生成ビルド番号は差分に含めていない。対応は`evidence-source-relationships.json`に記録した。xcresultの原本は`/private/tmp/RideIntercom-account-verification/.validation/host-isolation-*`、集約はmainの`.validation/host-isolation-delivery`に保持する。

失敗・skip・runtime warningはいずれの最終xcresultでも0件。buildログにはMac test targetのAppIntents metadata省略、StoreKitTest SDKの非推奨型診断と複数destination候補の診断が残る。build warningゼロとは扱わない。途中のPythonテストの`/var`と`/private/var`の期待path差、構成名の期待失敗も保全し、最終成功で過去の失敗を書き換えない。

本工程はCLIの起動前確認であり、Xcode標準TestActionの検証用構成とUI復旧fixtureの自己完結は後続App工程で扱う。通常Run・Archive・Organizerの実提出、実機・実音声・実Cloudflareの受入を証明するものではない。
