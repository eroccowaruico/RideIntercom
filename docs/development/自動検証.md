# ビルド・起動と自動検証

## 目的と境界

放置後の復旧結果を同じ入口から再確認する。システムのxcode-select設定、利用者の実データ、Cloudflareのデプロイ状態は変更しない。実機の録音再生・無線通話・画面ロック・Bluetooth切替は自動テスト成功と区別する。

共有するXcode / VS Codeの入口とファイル自動同期は [開発環境](開発環境.md) を参照する。全modeで最初に開発設定と文書参照・到達性・Settings仕様の網羅を検査し、不整合も失敗として記録し、独立した検査を継続する。依存する前段が失敗した段階はblockedとして実行しない。

Simulatorは[音声E2Eの資源管理](音声E2Eテスト.md#再利用と後片付け)と同じlock・所有記録を使う。作成前に端末一覧を確認し、不要な停止済み専用端末を削除する。既存互換端末を優先し、実行中や一般用途の端末には触れない。

## 入口

| コマンド | 処理 |
|---|---|
| `scripts/build_and_run.sh` | この入口で作ったmacOSプロセスのみ停止し、build、通常起動、プロセス確認 |
| `scripts/build_and_run.sh --logs` | build・通常起動後にAppの統合ログを表示 |
| `scripts/build_and_run.sh --debug` | build後にLLDBで起動 |
| `scripts/validate.sh` | 全段階を実行。失敗を記録し他の独立した段階を継続、全体は非zeroで終了 |
| `scripts/validate.sh headless` | 9 package、native SDPと実SDK loopbackペア、Worker、Swift/Workerペア、scripts。UI・実マイクに依存しない |
| `scripts/validate.sh pair` | クリーンinstall、Worker回帰、実Swift client 2台のHTTP/WS/DO統合 |
| `scripts/validate.sh ios-ui` | 再利用する専用SimulatorのUIのみ。大きな文字・dark・landscape、隔離manifest破損からの復旧操作を含む |
| `scripts/validate.sh packages` | 9 Swift Package単体テストとRTCNativeWebRTCのnative交渉・loopbackテスト |
| `scripts/validate.sh worker` | npm ci、型検査、workerdでHTTP / WebSocketを検証。外部APIはtest側で代替 |
| `scripts/validate.sh macos` | macOS App単体テスト。利用者のgroupを削除するUIテストは実行しない |
| `scripts/validate.sh ios` | 共通の専用SimulatorでApp単体・UIテスト。終了時にshutdownして次回再利用 |
| `scripts/validate.sh scripts` | 文書検査と開発設定の回帰、WebRTC更新失敗時の旧成果物保持、不正成果物拒否、Cloudflare資格/費用試算 |

CodexのRunアクションは `.codex/environments/environment.toml` から `scripts/build_and_run.sh` を実行する。

## 環境と出力

| 変数・出力 | 内容 |
|---|---|
| `DEVELOPER_DIR` | 既定 `/Applications/Xcode.app/Contents/Developer`。各プロセスへ渡す |
| `VALIDATION_DIR` | 既定 `.validation/<実行日時>`。各runに新しいパスを使う。results.tsvが既存なら開始前に拒否し証跡を保持 |
| `VALIDATION_DERIVED_DATA` | リポジトリ外のXcodeビルドcache親directory。省略時はOS一時directoryへ実行ごとに作成。同期フォルダ内は拒否 |
| `DERIVED_DATA_PATH` | build_and_run専用。既定はOS一時directory内の `RideIntercom-RunDerivedData`。同期リポジトリ外を使い、symlinkを解決した物理pathで起動中の実行ファイルを照合 |
| `SIMULATOR_RUNTIME` | 省略時はインストール済みで利用可能な最新iOS runtime |
| `SIMULATOR_APPEARANCE` | 専用Simulatorの外観。既定 `dark`、`light`も指定可能 |
| `SIMULATOR_DEVICE_TYPE` | 既定 `com.apple.CoreSimulator.SimDeviceType.iPhone-17-Pro`。未導入なら利用可能な型へ明示変更 |
| `environment.log` | HEAD、作業状態、OS、Xcode / Swift / Node / npm |
| `results.tsv` / `results.json` | 段階名、passed/failed/blocked/timeout/interrupted、終了コード、所要秒数。JSONはコマンド・理由も保存。全段階passedだけが全体成功 |
| `*-summary.log` | xcresulttoolのJSON概要。0 tests・failed・skip・runtimeWarnings・testFailures・解析不能を失敗にする。Appと独立音声E2Eは同じ判定関数を使う |
| `*.log` / `*.xcresult` | コマンド出力とXcodeの詳細結果・UI添付画像 |
| `simulator-id.txt` | そのrunで再利用または作成した専用SimulatorのID |
| `RIDEINTERCOM_STORAGE_NAMESPACE` | 通常buildはRideIntercom。検証入口はRideIntercom.Validation.<run名>.<stage名>へ上書きし、Application Support・UserDefaults suite・各Keychain serviceを分離。run名は英数・ハイフン・アンダースコアを使う |
| `ios-recovery.xcresult` / `recovery-verify.log` | 復旧操作の独立したUI結果と、元bytes退避・空manifestの検査 |

Nodeはpackage.jsonの要件（22以上）を満たすこと。macOS入口はこのMacのarm64を対象とする。依存再取得が必要なクリーン環境ではネットワーク接続も必要になる。

## 成功判定と異常終了

`--clean`はSwiftPMのscratch path（Swift/Workerペアも含む）をリポジトリ外の実行専用directoryにし、`clean-build-root.txt`へ場所を記録する。Xcodeは通常も新規の外部DerivedDataを使う。既存cacheを削除する操作ではなく、OS SDK・グローバル依存cache・インストール済みツールまで消去した環境を意味しない。`--thread-sanitizer`はSwift packageとpairのThread Sanitizerを有効にする。App/UIの検査へ自動拡張しない。

Swift 6.3以上、Node 22以上を明示的に確認する。WebRTCは格納zipのSHA-256とmetadataを照合し、展開したframeworkのplatform/architecture/headerを検査する。更新用depot_toolsや外部の最新版照会は通常検証の前提にしない。

RTC packageは`--no-parallel`を明示する。SwiftPMの既定表示だけではSwift Testingのsuite並列実行を止められない。10分相当のcodec/暗号化を数秒で処理する耐久試験、制御actorを意図的に止める試験、50ms配送・100ms鮮度期限を持つ試験を同時実行しない。期限・欠落・波形の判定は緩めず、8名の同時配送は試験内部で維持する。

Swift/Python/Nodeの終了コードが0でも、実行件数0、失敗、skip、todoは成功としない。RTCのWorkerPairTestsはpackage単体から除き、pair modeでserverを起動して必ず実行する。UIのtestCorruptGroupStoreRecoveryも通常のios-testsから除外し、準備済みのios-recovery stageで必ず実行する。いずれも未実行のskipとして成功扱いにしない。`VALIDATION_TIMEOUT_SECONDS`は各段階の上限秒（既定1800）。明示的な準備・展開・Simulator操作はより短い上限を持つ。timeoutや中断ではこの入口が開始したプロセスgroupだけを終了し、利用者の別ビルドを名前検索で停止しない。

`inputs-before.json`と`inputs.json`は実行前後のtrackedおよび未ignoreソースのSHA-256。実行中に変更されれば検証結果を失敗にする。内容そのものはコピーしない。証跡の`*-derived-data.txt`で外部ビルド出力の場所を確認できる。未追跡の秘密ファイルはhash記録対象になるため、資格は所定のignore対象へ置く。

GitHub Actionsのpush・pull_request triggerは使用しない。既存workflowは明示的な手動dispatchのみ残し、この検証では起動しない。mainへのpush前にローカルで必要なmodeを成功させる。サーバー側の強制gateがないため、検証を省略したpushまでは防止できない。

## テストデータの扱い

| 対象 | 方針 |
|---|---|
| Simulator | unit / UI・音声E2E入口は共通の所有journalとlockで専用端末1台を再利用し、終了時はshutdownする。毎回既存端末を棚卸しし、不要な停止済み専用端末を削除する。既存端末をeraseしない |
| UIテスト | 専用Simulator内のTalk Groupを作成・削除する。利用者の端末で直接実行しない |
| App単体のhost起動 | macOSでも検証run専用namespaceでbuildする。host起動時の旧データ移行が利用者の保存先へ到達しない。終了時は当該DerivedDataの実行ファイルpathに一致するhostだけを終了する |
| 保存復旧fixture | 通常iOS試験の成功後にsimctlで自分が作成した端末のApp data containerを取得。別端末/namespace/symlinkを拒否し、groups.jsonのみを破損。元のDerivedData・namespaceでtest-without-buildingを行う。Xcodeによる再installでdata containerが移るため、照合前にも同じ端末・Appの場所を再取得 |
| App起動分岐 | 本番Appにテスト専用launch argumentや偽の通信・音声分岐を入れない |
| PCMテスト | AVAudioEngineのoffline render、偽の入出力backend、生成波形をTest Support側だけで使用 |
| 10分相当の検証 | 20ms PCMを各方向3万フレーム生成。Codec・暗号化・RTC受信待ち・重複破棄・復号の数と順序を検証。実時間10分や音響品質を示す結果ではない |
| Worker | Miniflare/workerdをローカル実行。Calls / TURN APIはoutboundServiceで代替。deployはdry-runだけ |

復旧UI試験はfixtureを必要とするため、Xcodeで全UITestsを直接選ぶ代わりに`ios-ui`入口を使う。通常suiteだけを調べる場合は`-skip-testing:RideIntercomUITests/RideIntercomUITests/testCorruptGroupStoreRecovery`を明示する。これは全体検証の代替ではない。証跡と外部build cacheは保持し、専用Simulatorは停止して再利用する。namespaceを通常版へ変更して検証アプリを利用データ上で起動しない。

## 結果の読み方

成功時でもSDK・vendorの警告はログで区別する。Simulatorのオーディオデバイス診断、XcodeのAppIntents metadata診断、WebRTC vendorの非推奨API警告を実機成功や警告ゼロへ読み替えない。復旧時の実績・採用版は [復旧検証記録](../validation/history/復旧検証記録.md)、中継前の履歴は [品質点検](../validation/history/品質点検.md)、現在の混在通話・機器切断と残件は [混在通話検証](../validation/history/混在通話検証.md) を参照する。

## 実音声のE2E

音声発話・通信・受話の試験は[音声E2Eテスト](音声E2Eテスト.md)で独立して実行する。`python3 scripts/audio_e2e.py`が短い検証の入口であり、通常のunit/integration検証へ同じ試験を重複登録しない。
