# ビルド・起動と自動検証

## 目的と境界

放置後の復旧結果を同じ入口から再確認する。システムのxcode-select設定、利用者の実データ、Cloudflareのデプロイ状態は変更しない。実機の録音再生・無線通話・画面ロック・Bluetooth切替は自動テスト成功と区別する。

共有するXcode / VS Codeの入口とファイル自動同期は [開発環境](開発環境.md) を参照する。全modeで最初に開発設定と文書参照・到達性・Settings仕様の網羅を検査し、不整合があれば終了する。

## 入口

| コマンド | 処理 |
|---|---|
| `scripts/build_and_run.sh` | この入口で作ったmacOSプロセスのみ停止し、build、通常起動、プロセス確認 |
| `scripts/build_and_run.sh --logs` | build・通常起動後にAppの統合ログを表示 |
| `scripts/build_and_run.sh --debug` | build後にLLDBで起動 |
| `scripts/validate.sh` | 全段階を実行。失敗を記録し他の独立した段階を継続、全体は非zeroで終了 |
| `scripts/validate.sh headless` | 9 package、native SDPと実SDK loopbackペア、Worker、Swift/Workerペア、scripts。UI・実マイクに依存しない |
| `scripts/validate.sh pair` | クリーンinstall、Worker回帰、実Swift client 2台のHTTP/WS/DO統合 |
| `scripts/validate.sh ios-ui` | 新規専用SimulatorのUIのみ。大きな文字・dark・landscapeを含む |
| `scripts/validate.sh packages` | 9 Swift Package単体テストとRTCNativeWebRTC build |
| `scripts/validate.sh worker` | npm ci、型検査、workerdでHTTP / WebSocketを検証。外部APIはtest側で代替 |
| `scripts/validate.sh macos` | macOS App単体テスト。利用者のgroupを削除するUIテストは実行しない |
| `scripts/validate.sh ios` | 新規の専用SimulatorでApp単体・UIテスト。終了時にshutdown |
| `scripts/validate.sh scripts` | 文書検査と開発設定の回帰、WebRTC更新失敗時の旧成果物保持、不正成果物拒否、Cloudflare資格/費用試算 |

CodexのRunアクションは `.codex/environments/environment.toml` から `scripts/build_and_run.sh` を実行する。

## 環境と出力

| 変数・出力 | 内容 |
|---|---|
| `DEVELOPER_DIR` | 既定 `/Applications/Xcode.app/Contents/Developer`。各プロセスへ渡す |
| `VALIDATION_DIR` | 既定 `.validation/<実行日時>`。各runに新しいパスを使う。results.tsvが既存なら開始前に拒否し証跡を保持 |
| `VALIDATION_DERIVED_DATA` | validate用のビルドcache親directory。証跡はVALIDATION_DIRへ毎回新規保存 |
| `DERIVED_DATA_PATH` | build_and_run専用。既定 `.validation/RunDerivedData` |
| `SIMULATOR_RUNTIME` | 省略時はインストール済みで利用可能な最新iOS runtime |
| `SIMULATOR_APPEARANCE` | 専用Simulatorの外観。既定 `dark`、`light`も指定可能 |
| `SIMULATOR_DEVICE_TYPE` | 既定 `com.apple.CoreSimulator.SimDeviceType.iPhone-17-Pro`。未導入なら利用可能な型へ明示変更 |
| `environment.txt` | HEAD、作業状態、OS、Xcode / Swift / Node / npm、swift-log lock、WebRTC metadata |
| `results.tsv` | 段階名と実際の終了コード。ひとつでも非zeroなら全体失敗 |
| `*-summary.json` | xcresult概要。0 tests・failed tests・成功0件を全体失敗にする |
| `*.log` / `*.xcresult` | コマンド出力とXcodeの詳細結果・UI添付画像 |
| `simulator-id.txt` | そのrunで作成した専用SimulatorのID |

Nodeはpackage.jsonの要件（22以上）を満たすこと。macOS入口はこのMacのarm64を対象とする。依存再取得が必要なクリーン環境ではネットワーク接続も必要になる。

## テストデータの扱い

| 対象 | 方針 |
|---|---|
| Simulator | runごとに新規作成し既存端末をeraseしない。再調査用に端末を保持し、終了時はshutdownのみ |
| UIテスト | 専用Simulator内のTalk Groupを作成・削除する。利用者の端末で直接実行しない |
| App起動分岐 | 本番Appにテスト専用launch argumentや偽の通信・音声分岐を入れない |
| PCMテスト | AVAudioEngineのoffline render、偽の入出力backend、生成波形をTest Support側だけで使用 |
| 10分相当の検証 | 20ms PCMを各方向3万フレーム生成。Codec・暗号化・RTC受信待ち・重複破棄・復号の数と順序を検証。実時間10分や音響品質を示す結果ではない |
| Worker | Miniflare/workerdをローカル実行。Calls / TURN APIはoutboundServiceで代替。deployはdry-runだけ |

## 結果の読み方

成功時でもSDK・vendorの警告はログで区別する。Simulatorのオーディオデバイス診断、XcodeのAppIntents metadata診断、WebRTC vendorの非推奨API警告を実機成功や警告ゼロへ読み替えない。復旧時の実績・採用版は [復旧検証記録](../validation/history/復旧検証記録.md)、中継前の履歴は [品質点検](../validation/history/品質点検.md)、現在の混在通話・機器切断と残件は [混在通話検証](../validation/history/混在通話検証.md) を参照する。
