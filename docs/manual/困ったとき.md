# 困ったときの確認

Callで利用者の状態、Settingsで希望値、Diagnosticsで実効状態を確認する。接続済み、Authorized、入力meterが動く、という一つの表示だけでは双方向通話成功を判断しない。

| 症状 | 確認する順序 | 判断と次の操作 |
|---|---|---|
| 自分の声が届かない | Input mute → マイク権限 → 入力meter → VAD → TX codec / effect report → peer認証 | 無音ならAudio Checkで入出力を分離。meterだけ動く場合はVAD presetを比較し、認証・経路を確認。VAD noise floor等の専用詳細行は現在未表示 |
| 相手の声だけ小さい | その人のOutput → master Output → OS出力先・音量 | 自分の受信設定から調整。中継者の音量ではない |
| 誰も聞こえない | Output mute → master音量 → Audio Paused → RX / Decode / Mixer / output report | パケット受信と実再生を分ける。機器消失後は出力先確認後にResume Audio |
| Bluetoothを外して無音になった | Audio Pausedと理由 | 意図した停止。接続・中継は維持。機器確認後、認証済みpeerがいる状態で明示再開 |
| Speakerへ変わってほしくない | Use Speaker / Output、Audio Paused | OSの実機通知は未確認。意図する機器を選び直してから再開 |
| Audio Checkを押せない | 接続中・接続開始中でないか | CallでDisconnect。タブ移動やGroupsへの戻りだけでは切断しない |
| Internetの設定保存に失敗 | HTTPS originか、空tokenでないか、Keychain errorか | 現在の通話と保存済み設定を維持。Cloudflare App Secretを端末token欄へ入れない |
| Device token savedだが接続できない | Diagnostics → Check Internet Service | savedは保存のみ。Authorizedは認証・利用枠確認のみ。媒体は別に試す |
| Internetが失敗してもLocalは話せる | connectivity noticeと経路表示 | 正常な部分通話を維持している。残る経路を切らずに資格・回線を確認 |
| This account already has an Internet call | 同じApple Accountで接続中の端末 | 既存のInternet通話を終了してから再操作する。旧端末が通信断の場合は接続予約の期限切れを待つ。この端末のLocal通話はそのまま使える。Connectが出ていれば押し、Local通話中なら続けるか、Disconnect後にConnectしてInternetも再試行する |
| Internet OFFの人が遠方と話せる | 近くの中継端末 | 想定動作。OFFは本人のサービス接続を止める設定 |
| 中継者が離れて全員に届かない | 最後の橋が失われていないか | 分断中は届く側だけ継続。別経路が成立する必要がある |
| 調整中に切断された | route変更、資格保存、Reset時のroute復帰か | いずれも切断し得る操作。groupを選んでConnect |
| 古い音が飛ぶ・欠ける | 混雑、予約上限、機器report | 音声は順序待ち・再送を避け、古い待ちを破棄する。追いかけ再生を避ける代わりに欠落があり得る |
| codec希望と実選択が違う | requested / selected / fallback reason | 利用不可時のfallbackを確認。PCMに戻ると通信量が変わる |

## 不具合を調べるために残す情報

| 残すもの | 含めないもの |
|---|---|
| App版、OS、端末、時刻、操作順、希望設定と実効report、失敗理由、再現頻度 | group secret、招待URL全文、端末token、Cloudflare秘密、録音payload |
| 自動テストのコマンド・終了コード・xcresult、実機確認の条件と結果 | 自動テスト成功を実機確認済みとする記述 |

診断項目は[状態の見方](状態の見方.md)、通信や音声の内部契約は[アーキテクチャ](../spec/アーキテクチャ.md)、再現用コマンドは[自動検証](../development/自動検証.md)を参照する。DataChannelの詳細RTT/loss等、未提供の値は推測で正常値に置き換えない。

## 保存情報を読めない・グループを作成できない

保存した一覧やローカルのrider identityが不正な場合は、空の一覧で上書きせずエラーを表示する。GroupsのSaved Groupsを確認し、通話中ならDisconnectしてからReload Saved Groupsで再読込する。端末がロックされている、別のAppプロセスが保存中、といった一時的な失敗も削除せず再試行する。

破損時に表示されるReset Saved Groups and Users…は、確認して実行すると読めない元データを退避して全groupとその鍵を初期化する。Cancelなら変更しない。退避に失敗すれば初期化を止める。自分のrider identity、音声設定、Internet資格は保持する。退避内容から自動修復する機能はなく、groupには新しい招待で入り直す。identity自体の破損はgroup初期化では修復しないため、その場合は保存情報を保全して調査する。

新しいApp版で作られた形式は、その版で開く。旧版での初期化は提供しない。鍵が欠けているgroupは一覧を残すが接続できないため、有効な招待を受け直す。通話中groupの鍵を変える招待は、切断後に開き直す。Unused group keysの案内は一覧の保存成功後の鍵回収待ちを示し、次回Reloadで再試行する。

処理待ちの上限を超えて通話が終了した場合は、RTCの停止完了後にConnectで接続し直す。設定変更は最新値へ集約するが、応答しない外部処理を強制終了はしない。
