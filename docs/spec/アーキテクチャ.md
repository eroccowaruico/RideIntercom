## 構成と依存方向

```mermaid
flowchart TD
    UI[SwiftUI: Call / Diagnostics / Settings] --> VM[ViewModel]
    VM --> State[GroupRepository / Settings]
    State --> Stores[UserDefaults metadata / Keychain secrets]
    VM --> Audio[App Audio composition]
    VM --> Transport[CallSessionAdapter]
    Audio --> Session[SessionManager: OSと機器]
    Audio --> Mixer[AudioMixer: graphとformat変換]
    Audio --> FX[Effectors: 個々の音声加工]
    Audio --> Codec[Codec: encode / decode]
    Transport --> RTC[RTC: 接続 / 認証 / 中継 / 待ち制御]
    RTC --> Local[Multipeer]
    RTC --> Native[RTCNativeWebRTC]
    Native --> SFU[Cloudflare SFU DataChannel]
    RTC --> Worker[Worker HTTP / WebSocket / DO]
    Session -. PCM語彙 .-> Core[AudioCore]
    Mixer -. PCM語彙 .-> Core
    Codec -. PCM語彙 .-> Core
```

RTCはAudio packageやDSPに依存しない。Appはpackageの生成・接続・設定・寿命を調整し、package内の音声加工や経路制御を複製しない。動的plugin loaderは設けず、既存のnode / backend / route factoryを差し替え口とする。

## 音声・通信の所有境界

```mermaid
flowchart LR
    HW[実hardware PCM] --> Input[SessionManager input]
    Input --> VAD[VADと送信判定]
    VAD --> TX[TX Mixer: Isolation / Dynamics / Limiter]
    TX --> Encode[Codec encode]
    Encode --> Send[RTC: Local / Internet / relay]
    Receive[RTC受信: 元の話者ID] --> Decode[Codec decode]
    Decode --> Peer[peer source gain / Isolation]
    Peer --> Master[mix / master Isolation / master gain]
    Master --> Limit[rx-output Limiter]
    Limit --> Output[SessionManager output: 実hardware format]
```

| 境界 | 不変条件 |
|---|---|
| format | hardware実format、Mixer 48kHz mono、RTC選択48/24/16kHz monoを区別し、Mixerで明示変換 |
| 話者 | 個別音量・effectはorigin peer ID。経路や中継者が変わっても同じ話者として扱う |
| 中継 | 符号化済み音声をRTCで転送。中継者の音声graphへ戻して再加工しない |
| 配送 | 音声は順序待ち・再送なし、制御はreliable。App/RTC/PCM予約に上限・期限。100msは各境界の期限で総遅延の保証ではない |
| VAD | Mixer nodeではなく入力の発話分析と送信判定。runtime reportとMixer effect chainを混同しない |
| 音声停止 | 機器消失では自分の送受話を止め、接続・他者中継を維持。明示Resumeまで戻さない |
| group選択 | selectedGroupとactiveGroupIDを分離。他group閲覧は通話を終了しない |
| 手動設定 | route変更・資格保存成功は明示切断。自然な経路消失時の継続と区別 |

## 拡張時の変更単位

| 変更 | 先に更新・検証するもの | 次に追従するもの |
|---|---|---|
| 新しいroute / backend / Effector / codec | 対応package仕様、実装、単体・契約テストを独立commit | AppのBindings、composition、UI、マニュアル、統合テスト |
| UI / 既定値 / 保存方式 | App仕様・実装・テスト | 課題・検証の状態、設定と効果、操作手順 |
| Worker API / 利用枠 | WorkerとRTCの契約・ペア試験 | 端末設定と運用手順、費用の前提 |
| 文書移動 | 移動対応・全文保持・相対リンク | READMEの導線、コード対応、文書自動検査 |

共通基盤の責務方針は[パッケージ要求](../requirements/パッケージ要求.md)、現行APIは対応するpackage仕様を正本とする。実装変更の計画は課題、確認待ちは検証へ置く。
