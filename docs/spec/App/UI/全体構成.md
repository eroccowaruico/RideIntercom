# RideCom UI 全体構成

## 目的

本書は、現行のRideCom App の画面全体構成を定義する。

画面内の個別項目は `docs/spec/App/UI/画面項目定義.md` を入口とし、画面ごとの正本は `docs/spec/App/UI/Call.md`、`docs/spec/App/UI/Diagnostics.md`、`docs/spec/App/UI/Settings.md` とする。

状態遷移は `docs/spec/App/UI/画面・状態遷移.md` を正とする。

## 画面構成

| 階層 | 画面 | 目的 | 主な package 連携 |
|---|---|---|---|
| Root | Apple Sign In | 未ログイン・資格取消時の入口。ログイン完了まで通話画面へ進まない | AuthenticationServices |
| Root | Set Up Your Account Again | 同じserviceの公開ID再登録を確認したとき、旧端末内データの消去・再設定へ進む。通常通話画面を出さない | AccountDeletion / AccountDataEraser |
| ログイン後 | `TabView` | 通話、ユーザー、グループ、診断、設定を切り替える | なし |
| Call | Groups | 接続対象 group を選ぶ | RTC credential 生成前の App 状態 |
| Call | Call | 接続、招待、ミュート、参加者音量を扱う | RTC / SessionManager / Mixer |
| Diagnostics | Diagnostics | package runtime report、metrics、fallback を確認する | RTC / SessionManager / Codec / Mixer |
| Settings | Settings | 通信 route、入出力、codec、VAD、Audio Check、reset を扱う | RTC / SessionManager / Codec / VADGate / Mixer |

## 画面コードの配置

[StandardとAdvancedの設計の絶対ルール](../../../policies/開発方針.md#standardとadvancedの設計の絶対ルール)に合わせ、`RideIntercom/UI/Call`は`Standard/`・`Advanced/`・`Common/`に分ける。

| 置き場所 | 置くもの |
|---|---|
| `Standard/`・`Advanced/` | そのモードだけの画面・行・詳細・確認。一方の部品・語・配置を他方から使わない |
| `Common/` | モードを選ぶ入口（例: `ContactInvitationSheet`がStandardとAdvancedの詳細を選ぶ）、両モードが同じデータ・操作として使う部品（共有のリンク、保存エラーのSection）、モード別のデザインがまだない画面 |

部品の中で`interfaceMode`を見て表示を分けず、入口でモードごとのViewを選ぶ。招待（`StandardContactInvitationViews.swift`・`AdvancedContactInvitationViews.swift`）はこの形に分けた。残りの分離は[UIファイルの分離と責務境界](../../../backlog/未実装課題.md#個人招待の修復と画面アーキテクチャの整理)で追う。

## タブ

Standardが初期表示で、Call / Users / Groups / Settingsを分ける。Usersは直接招待関係の一覧、Groupsは通常グループ一覧、Callは選んだ相手・グループの共通通話操作。SettingsのApp LayoutからAdvancedへ切り替えると、共通の4タブにDiagnosticsを加える。AdvancedのCallは詳細表示を使い、接続先の選択とグループ作成はUsers / Groupsタブへ集約する。Standardへ切り替えるときDiagnosticsだけCallへ戻し、通話や保存データを変更しない。


| タブ | 表示名 | 役割 | 通常利用での位置づけ |
|---|---|---|---|
| Call | `Call` | 通話操作と参加者確認 | 主画面 |
| Users | `Users` | 保存済みユーザーの選択・編集 | 共通の一覧 |
| Groups | `Groups` | 保存済みグループの選択・作成 | 共通の一覧 |
| Diagnostics | `Diagnostics` | 状態確認と切り分け | ログを読まず現在状態を一覧で確認する画面 |
| Settings | `Settings` | 利用前調整と自己診断 | 通話前後の設定画面 |

## App が UI に出す情報

| 情報 | 出す画面 | 方針 |
|---|---|---|
| 接続状態 | Call / Diagnostics | RTC の state と `RTCRuntimeStatus` を App 表示へ要約する |
| 通信 route 設定 | Settings / Diagnostics | Settings は有効 route のユーザー希望だけを扱い、active / available route は RTC runtime status と metrics を正とする |
| 音声入出力 | Call / Settings / Diagnostics | SessionManager の snapshot / report と AudioMixer snapshot を要約する |
| codec | Settings / Diagnostics | Settings はユーザー希望だけを扱い、実 codec / fallback は `CodecRuntimeReport` と RTC runtime status で確認する |
| effect chain / mixer graph | Diagnostics | `AudioMixerSnapshot` の bus、effect chain、route、graph を描画入力にする |
| route metrics | Diagnostics | RTC `RouteMetrics` を一覧カードへ要約する |
| ログ | 画面には直接出さない | `docs/spec/App/ログ仕様.md` に従い構造化ログへ出す |

## App が UI に出さない情報

| 情報 | 理由 |
|---|---|
| group secret / invite token | 機密情報 |
| 音声 sample / encoded payload | 機密かつ高頻度 |
| native WebRTC 型 | RTC package が隠す責務 |
| Audio Unit parameter の全量 | package 仕様を正とし、App 画面は必要な設定だけを持つ |

## ログイン画面

サインイン画面は公式glyph（`signInBrandGlyph`）とRideCom名、認証理由（`signInReason`）、標準Appleサインイン操作を表示する。横長ではブランドと操作を並べ、縦長では積み、保留招待・失敗時の案内と再試行を保持する。

| 項目 | 項目ID | 表示・操作 |
|---|---|---|
| Appleログイン | `appleSignInScreen` | RideComのglyph・見出しと認証の目的、メール・本名を使わないことを表示。テーマの背景と標準ScrollViewを使い、縦長では幅420pt以下で大きな文字・小さな画面を扱う |
| 標準認証ボタン | `signInWithAppleButton` | Sign in with Apple。OS標準の文言・VoiceOverを使用し、明暗に合わせて白／黒を選ぶ。処理中・保存読出失敗中は無効 |
| エラー | `accountMessage` | 中断はエラー扱いにせず再操作可能。認証失敗・保存失敗・取消は復旧案内を表示 |
| 再確認 | `retrySignInButton` | Try Againで保存状態と資格を再読込 |
| 保留中の招待 | `pendingInviteSignInLabel` | URLを受け取っても未ログインでは参加せず、ログインを案内する |

認証ボタンは[Apple HIG](https://developer.apple.com/design/human-interface-guidelines/sign-in-with-apple)の標準コントロールを採用する。実機でのOS認証sheet・VoiceOverの受入は別途行う。

## 再登録後の端末内データ整理

| 項目 | 項目ID | 操作・表示 |
|---|---|---|
| 復旧画面 | `accountDataResetScreen` | Set Up Your Account Again。旧データ・鍵の消去と新しい招待の必要性、新serverアカウント・Apple認可・購入を保持すること、Internet不要を説明 |
| 消去へ進む | `removePreviousAccountDataButton` | Remove Previous Account Data。削除とCancelを明示する標準alertを開く |
| 消去確認 | `confirmAccountDataResetButton` | Remove Data。Cancelなら旧保存内容を変更せず復旧画面へ戻る。確定後は再試行可能なローカル消去画面へ進む |
| サインアウト | `accountResetSignOutButton` | Sign Out。同じ本人へ再ログインしても未完の整理が再表示される |
| 完了・再試行 | `accountDeletionProgress` | 通常削除と同じ進捗・再試行・Return to Sign Inを使う。再登録時は追加Apple確認やApple手動解除を要求しない |

通話許可と復旧操作の許可を分離する。削除記録が残る間は消去を再開し、記録の完了後に再ログイン・Internet再設定へ戻る。標準ScrollView・Text・Button・確認alertを使い、見出しと操作名をVoiceOverへ渡す。
