# RideCom App ログ仕様

本書は現在発行するeventとmetadataを記述する。共通の目的・禁止事項は[ログ記録規約](../../policies/ログ記録規約.md)、追加案は[改善候補](../../backlog/改善候補.md)へ分ける。

## 基盤と値の扱い

| 項目 | 現在の動作 |
|---|---|
| 初期化 | App起動時にLoggingSystem.bootstrapを1回実行。lockとdidBootstrapで反復を防ぐ |
| 出力 | StreamLogHandler.standardOutput。Debugはdebug以上、Releaseはinfo以上 |
| Logger | com.yowamushi-inc.RideIntercomのapp / rtc / audio / security / settingsを定義。securityの現在の発行箇所はない |
| event | 固定文字列を本文とmetadataのeventへ設定 |
| 生ID | Logger.Metadata.eventがpeerID / groupIDを取り除き、SHA-256先頭12byte（24hex）のpeerIDHash / groupIDHashへ変換。安定した仮名であり完全匿名ではない |
| operationID | 現在はapp.lifecycle.startedとsettings.resetで付与。他eventには自動付与しない |
| 高頻度値 | 通常のフレーム・packet・tickは逐次ログにしない。Diagnosticsはpackage report / event / metricsを表示する |
| 機密値 | group secret、招待token、鍵、認証MAC、音声・復号payloadをmetadataへ渡さない |

## 対応する実装

[RideIntercomLogging](../../../RideIntercom/App/RideIntercomLogging.swift)、[App起動](../../../RideIntercom/App/RideIntercomApp.swift)、[ViewModel](../../../RideIntercom/Intercom/ViewModel)のAppLoggers呼出を正本として更新する。招待deeplinkのeventは`rideintercom://join`の受理操作（`acceptInviteURL`）で発行し、`contact`の相手招待は対象外である。`reason`は分類値だけを記録し、tokenや失敗文言を含めない。分類は`expired`、`unsupported_version`、`unverified`（URL・符号化・署名の検証失敗）、`wrong_recipient`、`incompatible_call`、`active_group_key_changed`、`account_verification_required`、`storage_unavailable`、`conflicting_direct_invitation`（互いに作成した個別通話の招待で既存の通話を維持した場合）、`other`とする。`app.permission.microphone.denied`は通話の音声開始（`audio.media.started`の発行時）にOSのマイク権限が拒否されている場合だけ発行する。OSは拒否中の録音を失敗とせず無音を返す場合があり、音声開始の失敗ログだけでは区別できないため、開始時に記録する。Audio Checkや権限の変化の監視では発行しない。pipelineのcapture / rebuild / receive失敗はpipeline単位のeventであり、codecやhandshakeの個別失敗eventとは別である。受信packetのcodec decode失敗（`CodecError`とpacket形式の検証失敗）は`audio.codec.decode_failed`、再生への投入など他の受信失敗は`audio.pipeline.receive_failed`とし、1つの失敗packetにどちらか一方だけを発行する。経路の維持状態はRTC runtime statusを用いる。
