# 利用権仕様

本書はApp内のStoreKit読取・復元・状態表示の契約を定める。[利用権とデータ保持の設計](../../backlog/利用権とデータ保持の設計.md)の通話開始条件とは区別する。この基盤だけでは通話・作成・招待を制限せず、StoreKitの取引をfinishしない。

## 提供設定と責務

| 対象 | 現行の動作 |
|---|---|
| 公開商品 | `StoreProductCatalog.production`は未設定。架空の商品IDやfixture価格で販売せず、StoreKitへ問い合わせず、未設定状態を表示する |
| 商品の意味 | 週券は個人用の非更新型を想定し、購入から604,800秒。月額は自動更新型でFamily Sharingを提供する方針。商品登録・共有設定・価格・試用日数は公開環境で別途設定する |
| App境界 | `SystemStoreKitAccessSource`がStoreKit 2を読み、`StoreKitAccess`が状態・復元・観測の寿命を所有。表示は`StoreAccessSection`へ渡す。packageへ課金条件を持ち込まない |
| 保存 | 検証済み取引をメモリで保持し、独立した購入台帳・購入済みフラグ・試用開始日時を保存しない。購入履歴の正本はStoreKit |
| 操作への適用 | 共通操作への権利判定はこの読取基盤の外で行う。未設定を購入済みに変換せず、既存の認証・所属・費用制限を免除しない |

## 読取と期間

| 状態・処理 | 契約 |
|---|---|
| 起動・前面復帰等の読取 | ログイン後の共通画面で`start()`を呼び、観測開始後に初回取得する。前面復帰時はAppleログイン確認後に`refresh()`で再取得する。StoreKitの端末内取引で検証済みの期限を先に反映し、購読状態の照会完了を待たせない。定期的なネットワーク照会は行わない |
| 動作中の更新 | `Transaction.updates`と購読状態のupdatesを対象商品だけに絞って再取得。読取中に来た変更はまとめて再読取し、変更を落とさない |
| 週券 | `Transaction.all(for:)`で同一商品の取引全件を独立評価。検証済みnonRenewableで購入日時以上・購入から604,800秒未満のみ有効。後の券の返金で、それ以前の有効券を消さない。復元時刻で延長・残期間加算しない |
| 月額 | 検証済みautoRenewableの取引と`SubscriptionInfo.status(for:)`の購読group内の全状態を使用。同じ商品の本人購入とFamily Sharingを単一の最新取引へまとめず、いずれか有効なら利用可能。取引履歴の仮評価もoriginalTransactionID・ownershipType・environmentごとの最新期間を残す。固定30日で計算せず、猶予はinGracePeriodかつ検証済みRenewalInfoの期限だけを使う |
| 失効 | 返金・取消、upgrade済みの旧取引、期限到達、猶予を伴わないbilling retry等から新しい権利を与えない。成立済み通話や再開猶予の破棄はこの層で行わない |
| 無料トライアル | StoreKit取引のoffer.paymentModeを保持。独自の再試用防止台帳を設けず、試用資格・日数・更新はApp Storeの標準設定に従う |
| 取引根拠 | transactionID、originalTransactionID、ownershipType、environment、appAccountToken、appTransactionID、購入日、期限、取消、upgrade、試用、検証済み猶予を保持。相手へ取引全体を送信せずログへ生ID・購入証明を出さない |
| 複数の権利 | いずれか有効なら有効。別の権利を消費せず、有効期限は有効な権利のうち最も遅いもの。取消された別取引だけで有効券を無効化しない |
| 時計 | 判定時の端末時刻を渡し、期限境界では再問い合わせなしで評価する。厳密な時刻改変対策の常時サーバー照会を追加しない |

## 復元・判定不能・ユーザー切替

| 対象 | 契約 |
|---|---|
| 復元 | 利用者がRestore Purchasesを選んだ場合だけ`AppStore.sync()`を実行し、その後に読み直す。標準のApple認証シートの入力待ちへ独自タイマーを設けず、利用者の標準取消またはAppのstopで待機を終了できる。起動・定期実行でsyncしない |
| 未検証 | 未検証取引を購入なしと同一視しない。他に独立して検証済みの有効権利があればそれを利用できる。未検証payloadは更新対象の絞込みにだけ使用し権利を与えない |
| 取得・復元失敗 | read/statusだけを15秒で区切り、応答がなくても待機表示を解除して復元・再取得できる。前回の検証済み状態・猶予と、新しく端末内で確認できた権利を署名済み期限の範囲で保持。新しく確認できた取消・upgradeを古い状態で上書きしない。遅延結果は完了済み要求・旧ログイン世代の両方で排除し、非協調APIのキャンセル完了を待ち続けない。期限後は取得不能となり、通信失敗だけで取消や永久有効にしない |
| 同じ端末の付替え | App所有者は現在のログインユーザーとaccountAccessIDの一致を`isCurrentUser`へ渡す。旧モデルは一致しなくなった時点で権利を返さず、復元も開始しない。stopで観測・待機表示・snapshotを破棄し、応答待ちの旧読取が残っていても新しいstartで再取得できる。旧読取の完了で新しい待機状態を解除せず、遅延結果もgeneration/所有者の確認で適用しない |
| 新モデルでの再取得 | 新しいログインユーザーのモデルがStoreKitを読み直す。StoreKitの購入履歴を削除しないため、再登録・復元の袋小路を作らない |
| 複数端末 | 独自購入台帳や端末間購入ロックを設けない。別端末への瞬時の排他移管は保証しない。未到達端末の状態待ちで復元を停止しない |
| Family Sharing | 月額の商品設定で有効にする方針。家族ごとに受け取った検証済み取引を通常の取引として評価し、familySharedの取消・更新を観測する。appAccountTokenがないことを失効条件にしない。週券の非更新型はFamily Sharingの対象外 |

[AppleのFamily Sharing説明](https://developer.apple.com/documentation/storekit/supporting-family-sharing-in-your-app)は自動更新型・非消費型を対象とし、家族ごとに独自取引を提供する。[WWDC25の識別子説明](https://developer.apple.com/videos/play/wwdc2025/249/)では家族ごとのappTransactionIDと、familySharedでappAccountTokenを使えない条件を説明している。この基盤はStoreKitの識別子からアプリ内ユーザーを推測せず、アプリの現在のログイン寿命で適用先を区切る。

## 状態表示

| 状態 | 表示・次の操作 |
|---|---|
| 未設定 | Not Available Yet。購入・復元は表示しない |
| 初回未取得・検証不能 | Could Not Verify。設定済みなら復元できる |
| 検証済み取引なし | No Purchases |
| 有効 | Availableと有効期限 |
| 期限切れ | Expired。設定済みなら復元できる |
| 全件取消 | Refunded or Revoked |
| 復元失敗 | App Storeアカウント確認と再試行を案内。既存の独立した有効取引は維持 |

画面は価格・公開商品未設定のため購入開始ボタンを提供しない。期限の表示更新は端末内の日時スケジュールで行い、表示更新をネットワーク照会へ結び付けない。実画面の配置は[画面項目定義](UI/画面項目定義.md)を参照する。

## ローカル検証の境界

`StoreEntitlementTests`と`StoreKitAccessTests`は標準unitで期間境界・未検証・重複・復元失敗・更新・アカウント退役を検証する。`LocalStoreKitTests`は`RIDEINTERCOM_STOREKIT_TESTING`指定時だけコンパイルし、専用`RideIntercom-StoreKitTests` schemeと`RideIntercomTests/Fixtures/LocalPurchases.storekit`で実StoreKit 2との対応を検証する。fixtureは販売設定ではない。実機、Apple sandbox、App Store Connect、TestFlightの配布条件・Family Sharingの実アカウント間連携は別の受入条件である。

再実行は、リポジトリ直下で`python3 scripts/validate_storekit.py --output .validation/storekit-日時`を使う。既存の出力先は上書きしない。DerivedDataの既定は`/private/tmp/RideIntercom-StoreKit`を再利用し、`--derived-data`でも既存の専用pathを指定できる。既存`exclusive_run`でそのpathのbuild・実行・証跡・所有testhost終了の全区間を排他にし、同じpathの別runを停止しない。macOSではStoreKitの端末検証を通すため標準のApple Development Debug署名を使用し、`CODE_SIGNING_ALLOWED=NO`やad-hoc署名へ置き換えない。ローカルfixtureの取引だけを試験内でfinishし、Appの未提供商品の取引はfinishしない。

実行条件と成功・失敗の境界は[StoreKit端末利用権のローカル検証](../../validation/history/StoreKit端末利用権のローカル検証.md)に記録する。

[AppleのStoreKit 2紹介](https://developer.apple.com/videos/play/wwdc2021/10114/)は、本人購入とFamily Sharingによって同じ商品に複数の購読状態が返ることを説明している。Appは購読状態配列を全件評価し、一方の取消によって独立した有効購読を隠さない。
