# RideIntercom App 通信仕様

## Appleログインと端末内データ

| 対象 | 現行契約 |
|---|---|
| 必須範囲 | Local・Internet・1対1・グループのすべての通話にAppleログインが必要。初回はApple標準の認証画面を使う。新規開発のためログイン導入前のデータの移行は行わない |
| 保存 | `AppleAccountSession`はAppleのuser識別子だけをKeychainへ保存する。メール・本名のscopeを要求せず、identity token・authorization codeを保存・ログ出力しない。requestのstateを一度だけ照合する |
| 再起動・圏外 | 成功済みの保存ログインは直ちに復元し、起動・前面復帰時にAppleのcredential stateを非同期確認。Local開始を応答待ちにしない。authorizedなら継続。確認エラーでは成功済みの保存ログインを維持し、近距離通話を毎回のInternet接続に従属させない。未ログインから確認エラーだけでログイン済みにはしない |
| 取消 | revoked・notFound・transferred、OSの取消通知で即時に通話を停止しログイン画面へ戻す。圏外で未知の取消を検出できるとは保証しない |
| サインアウト | 通話停止とログイン解除を行う。先に端末の再ログイン必須フラグを保存するため、Keychain削除失敗後の圏外再起動でも古い資格を自動復帰しない。削除失敗を表示する。グループ・保存ユーザーは削除しない |
| 読書き失敗 | Keychain読出失敗を未登録に置き換えず、元データを保持して再読込を案内。資格保存成功前にログイン完了にしない。中断・取消・サインアウトより古い非同期結果で権限を戻さない |
| アカウント分離 | `StorageNamespace.Account.<SHA256(Apple user)>`ごとにグループmanifest、鍵、保存ユーザー、端末member ID、設定、Internet資格を分ける。同じアカウントの再ログインは同じ保存先。別アカウントでは混在しない。SHA256値も公開ユーザーIDには使わない |
| 複数ウィンドウ | アカウントと通話モデルはAppが所有し、すべてのwindowで共有する。新しいwindowを開くだけでモデルを再生成・切断せず、サインアウトを全windowへ反映する |
| 呼出境界 | `IntercomViewModel`は生成時のログインアカウントとメモリ内の`accessID`を保持する。サインアウト・アカウント変更で世代を更新してから終了処理を呼び、同じユーザーの再ログインでも古いモデルを復活させない。通話・Audio Check開始、group／ユーザーの編集・再読込・reset、招待受理・鍵取得、設定保存・Internet資格設定と確認で照合する。ContentViewは世代変更に追従し、新しいモデルだけを使う。ログイン前の招待URLはメモリで保留し、ログイン後に既存の招待検証へ渡す。server資格失効の後始末はサインアウト後も継続する |
| サーバーとの境界 | 端末ログインとInternet用の登録を分ける。Internet設定でserver nonceを取得し、同じAppleユーザーのidentity tokenを[認証API](../server/Worker.md#apple認証と端末資格)へ送る。server確認済みの不透明なユーザーID・端末UUIDを含む資格をKeychainへ保存する。資格は入力欄へ再表示しない。Apple生IDや保存ユーザーIDだけでは認可しない |
| 登録の制限と再試行 | HTTP 429の`Retry-After`秒数を待機期限へ変換し、同じ認証画面・originへの再準備を期限まで送信しない。自動再送・pollingは行わず、期限後の利用者操作で新しいnonceを取得する。不正・欠落・非正数は60秒、上限は3600秒。表示名・Apple token・サーバーの自由文をエラーへ流用しない。画面終了・URL変更で破棄される端末内の補助制限であり、強制はserverが所有する |
| 登録端末数の上限 | session交換のHTTP 409 / `device_limit_reached`だけを8端末登録済みとして、別の端末でRideIntercomをサインアウトしてから再登録するよう案内する。待機だけで解消する頻度制限とは区別し、既存の資格・Localログイン・通話を変更しない |
| Internet登録の保護 | HTTPS originのみ、HTTP redirect拒否、応答最大32KiB。state・nonce・現在のAppleアカウントとログイン世代を照合し、URL変更・画面終了・キャンセルより古い応答を保存しない。保存失敗・遅延完了で不要になった発行済み資格は失効を試みる |
| Internetサインアウト | 通話を停止し、端末側の使用禁止を保存してからserverの端末資格を失効。通信・Keychain失敗時は再試行用の元資格を保持するが通常loadでは返さない。次にInternet設定を開いた際に再試行する。古い失効応答で新しい資格を削除しない。失効成功時は削除復旧用の最後の登録を同じアカウントのKeychain `deletion-account`へ保存してから`current`を消す。退避書込失敗なら元資格を残し、通常使用は禁止したまま再試行する |
| 登録応答の識別子 | 公開server userIDとBearer内の認証用locatorを区別し、一致を要求しない。公開ID・locator・秘密の形式、要求した端末IDと期限は検証する。削除後の公開ID更新はWorker側の契約に従う |
| 端末証明の取得 | Internet登録時にアカウント別KeychainのP-256秘密鍵を用意し、serverへ公開鍵とmember IDを送る。認証済みuserID/deviceIDに対するES256証明を検証後、資格と証明・信頼する発行公開鍵を同じKeychain項目へ保存する。署名・用途・origin・期限・要求したID／鍵の不一致なら資格を回収して保存を拒否する |
| 証明と鍵の保持 | サインアウトで資格と証明を使用禁止にし、再ログイン用の端末秘密鍵は残す。再起動では同じ鍵を使う。証明読込で鍵が欠けた場合に新しい鍵で置き換えず、読取・破損のエラーを返す。アカウント削除ではこの鍵・証明も消去対象。手動の別資格への置換は以前の証明を引き継がない |
| Localとの境界 | 証明取得はInternet登録時の追加処理であり、Localの通話開始・継続時にネットワーク要求や定期更新を追加しない。証明なし・期限切れの自己申告を同一ユーザーへ統合しない |
| 残る対応 | 通知先登録、削除対象サービスの範囲・別本人端末への反映は[後続課題](../../backlog/未実装課題.md#実装の接続点と残作業の再点検)。WebRTC予約のユーザー単位制限とserverの端末登録削除は[Worker契約](../server/Worker.md)を参照。端末資格の失効をApple連携解除と表示しない |

Apple標準の認証と起動時資格確認は[公式実装例](https://developer.apple.com/documentation/authenticationservices/implementing-user-authentication-with-sign-in-with-apple)を参照。実AppleログインにはApp IDと署名profileでSign in with Appleが有効である必要がある。ローカルfixture検証と実認証の受入は区別する。

## 目的

本書は、現行のRideIntercom App が RTC package をどう使うかだけを定義する。

接続、経路選択、Multipeer、WebRTC、packet audio、handover、暗号化の詳細は `docs/spec/packages/RTC.md` を正とし、本書では App 本体に残る責務だけを扱う。

## 責務境界

| 領域 | App 本体の責務 | 詳細仕様 |
|---|---|---|
| グループ | group ID、表示名、group secret の保存と選択 | 本書 |
| ローカルメンバー | local member ID、display name の生成と保存 | 本書 |
| 招待 | join URL の生成、共有、受理 | 本書 |
| RTC 接続 | RTC へ credential、peer、route 設定を渡す | `docs/spec/packages/RTC.md` |
| 音声 media | media 開始/停止を App の音声 pipeline と同期する | `docs/spec/App/音声処理仕様.md`、`docs/spec/packages/RTC.md` |
| App data | RideIntercom 固有 namespace と payload schema を管理する | 本書 |
| UI 表示 | 接続状態、参加者、エラー要約を表示する | `docs/spec/App/UI` |

## 基本方針

| 項目 | 方針 |
|---|---|
| RTC 詳細 | App は route、packet、handshake、WebRTC native 型を直接扱わない |
| 接続と media | 接続成立と音声開始を分ける |
| 認証 | group secret 由来の credential を RTC へ渡し、認証結果は RTC event として受け取る |
| 設定 | RTC へ渡す route / codec / credential 設定は本書に重複定義せず、`docs/spec/App/Configuration` に集約する。通信 route の opt-out は Settings の `enabledRTCTransportRoutes` を RTC package configuration へ渡す |
| runtime status | RTC の package-owned runtime status を App data より先に decode し、通信相手の package 状態として保持する |
| 機密情報 | group secret と invite token はログへ出さない |
| ログ | RTC event / route metrics は `docs/policies/ログ記録規約.md` と `docs/spec/App/ログ仕様.md` に従って構造化ログへ変換する |

## App が保持する通信状態

| 状態 | 内容 |
|---|---|
| local member | この端末の member ID と表示名 |
| group list | 参加済みグループの ID と表示名 |
| group secret | 新規作成時に256bit乱数を生成しKeychainへ保存・読戻し確認する。接続・招待・再接続は同じsecretを使う。group一覧には保存しない |
| selected group | 画面で選択中の group |
| active group | RTC 接続中または接続準備中の group |
| members | RTC event と App data から得た参加者表示状態 |
| connection summary | RTC の接続状態を UI 用に要約したもの |
| remote runtime statuses | `RTCRuntimeStatusTransport` で受信した peer ごとの package runtime status |
| enabled RTC routes | Settings で選択した RTC route の有効集合。既定は `.multipeer` と `.webRTC` の両方を有効にし、App は空集合を既定 route へ修復して RTC package へ渡さない |

## 設定値

RTC へ渡す route、credential、peer、codec UI 設定、Application Data namespace の設定は `docs/spec/App/Configuration/設定値一覧.md` を正とする。

RTC package の型名や内部設定の詳細は `docs/spec/packages/RTC.md` を正とする。

## 接続操作

### 通話先と操作対象の共通境界

`IntercomViewModel`の`startCall(to:accountAccessID:)`は、`CallDestination`の保存ユーザーUUIDまたはgroup UUIDを実行時に解決する。ログイン世代と`canStartCalls`を確認してから既存の接続lifecycleへ渡す。現在閲覧しているgroupを宛先として暗黙に使わず、同じ進行中通話への重複開始は接続を作り直さない。保存ユーザーを削除した後は、そのユーザー指定と保持済みの個別通話group指定の両方から新しい開始を拒否する。通常group内だけの相手を直接の通話先へ昇格させない。

`CallReference`はログイン世代、接続世代、対象groupを保持する。`endCall(_:)`は一致する通話だけを終了し、別通話への切替・切断後の再接続・再ログインより古い終了操作を無視する。終了時に保存ユーザーや新規開始権利を要求せず、相手削除後も進行中通話を終了できる。transportが停止した後の明示的な再接続は、同じgroupでも新しい接続世代とする。

`setCallMuted(_:for:)`は同じ参照を照合して明示的な真偽値を設定する。同じ値を重複して渡しても反転・再送しない。通話前のマイク設定も扱い、その古い設定操作が新しい接続へ遅れて適用されることを防ぐ。Call画面のConnect・Disconnect・マイク操作は描画時の対象と値をこの境界へ渡し、既存の一覧選択による開始も同じ処理へ接続する。閲覧だけで別の進行中通話を切り替えない動作は維持する。

この境界は端末内の共通操作であり、App Intents等のOS入口、利用権・24時間条件、通知送信の実装完了を表さない。操作要求のIDへ鍵・Bearer・保存モデル全体を複製しない。

### 直近の成立済み通話先

直近1件の`CallDestination`を、既存のアカウント別AppSettings保存先へ保持する。対象は保存ユーザーUUIDまたは通常group UUIDだけとし、表示名・相手鍵・通話記録を複製しない。現在の参加者署名を確認し、ローカル媒体も起動できた通話で更新する。選択・開始要求・transport接続・未確認のgroup鍵認証だけでは更新せず、媒体起動に失敗した場合も成立後の復旧まで前の記録を保つ。

個別通話は保持済みの直接相手へ解決してユーザーUUIDを記録する。通常groupの参加者をUsersへ追加せず、内部direct group UUIDを直近宛先として保存しない。`recentCallDestination`と`recentCallTitle`は現在のログインと保存一覧を照合して返し、名前変更は現在の名前へ追従する。`startRecentCall(accountAccessID:)`は取得時点の宛先を共通開始操作へ渡す。

対象の削除成功後は直近も無効化するが、進行中の個別通話は既存の規則で維持・終了できる。group読込や削除の失敗は対象消失と扱わず、記録を保持して再読込を待つ。不正な履歴データは未設定として扱う。サインアウト後は旧モデルから取得・更新・再開始できず、同じアカウントへの再ログインでは復元する。アカウント消去では同namespaceとともに削除する。音声設定の変更・Reset Allでは消さない。保存の永続化保証は既存UserDefaultsの設定保存と同じであり、この補助履歴のために通話を停止したり、server台帳・journal・端末間同期を追加したりしない。

### ショートカットとSiriの通話操作

App bundle内の`StartSavedCallIntent`、`StartRecentCallIntent`、`EndCurrentCallIntent`を`AppShortcutsProvider`から公開する。対象を指定した開始、直近の成立済み通話先への再開、現在通話の終了を扱う。`supportedModes = .foreground(.immediate)`と`requiresLocalDeviceAuthentication`を指定し、最初の実装は前面表示と端末の認証を必要とする。背景通知・ロック状態のまま送話を開始する経路や、新しい通話sessionを作らない。[Appleの実行mode](https://developer.apple.com/documentation/appintents/configuring-the-runtime-behavior-of-your-app-intents)と[認証policy](https://developer.apple.com/documentation/appintents/intentauthenticationpolicy)を参照。

`AppCallOwner`へAppの既存accountとViewModelの所有を移し、App初期化時に同じownerを`AppDependencyManager`へ登録する。画面はそのViewModelへのbindingを使い続け、Intentは`@AppDependency`から同じ実体を取得する。操作後はCallタブへ表示を戻す。[依存の登録](https://developer.apple.com/documentation/appintents/creating-your-first-app-intent)を参照。ログイン途中や古い世代の要求を保存・予約し、後のログインで自動実行する仕組みは置かない。

`CallTargetEntity`はID、表示名、ユーザー／groupの区別だけを渡す。IDはアカウント別の端末member ID、種別、宛先UUIDで構成し、同じgroup UUIDを別アカウントで使っていても古いshortcutの対象を引き継がない。生Apple ID、鍵、Bearer、購入証明を含めない。queryと実行時の両方で現在の保存一覧へ照合し、削除済みの相手、内部direct group、group内だけの参加者を候補へ出さない。名前検索は現在の端末内表示名を使う。[EntityQuery](https://developer.apple.com/documentation/appintents/entityquery)を参照。

外部開始は共通`startCall`へ`allowSwitchingCall: false`を渡す。別通話が進行中なら表示中の選択と通話を維持し、先に現在の通話を終了するよう案内する。同じ通話への再実行は既存接続を維持する。終了はperform内で現在の`CallReference`を取得して、awaitを挟まず共通終了へ渡す。相手の一覧削除後も終了できる。開始の結果は接続要求の受理を示し、相手の応答・接続成立や通知配送を保証する結果にはしない。

App単体でのperform/query検証と、OS経由のforeground起動・Shortcuts表示・Siri発話・端末ロック解除の受入は分ける。利用権・24時間条件は今後も共通操作へ接続し、Intent側へ独立判定を追加しない。

### lifecycleへの接続

| 操作 | App の動作 |
|---|---|
| group 選択 | active group がなければ選択 group を画面へ反映し、credential と local peer を RTC へ渡して接続を開始する。既存の active group は勝手に切り替えない |
| connect | 切断済みの選択 group を再接続する |
| route opt-out | Settings で Local Network / Internet toggle を変更した場合、App は更新後の `enabledRTCTransportRoutes` を `CallSession.setEnabledRoutes(_:)` へ渡し、active RTC connection があれば停止する。最後の有効 route は OFF にできず、旧設定などで空集合を読んだ場合は既定 route へ修復する |
| media 開始 | 全production routeでAppがSessionManager / Mixer / Codecを開始。WebRTCはDataChannelで符号化済み音声を運ぶ |
| codec 変更 | App の `preferredTransmitCodec` を RTC / Codec adapter へ反映し、route 未対応または codec unavailable の場合は fallback 結果を Diagnostics へ表示する |
| disconnect | RTC 接続と App の音声 pipeline を停止する |
| group 切替 | active group がある場合は明示操作で切断してから別 group へ接続する |
| 画面遷移 | 画面を戻るだけでは接続を切らない |

## RTC error の扱い

| RTC event | App の扱い |
|---|---|
| route scoped error | `connectionFailed(.webRTC, ...)` など route 単体の失敗は通話全体の `linkFailed` に変換しない。WebRTC の失敗理由を UI に表示し、RTC package の fallback / restore に任せる |
| `connectionBlocked(.webRTC, reason)` | `serviceBlocked`として手動復帰の意味を維持し、Callへ理由を表示する。「自動再試行中」と案内せず、他の有効なLocal通話は維持する。HTTP codeや理由の文字列判定はAppへ複製しない |
| `noEnabledRoute` | App 設定修復後も発生した場合は通話全体の失敗として扱う |
| `stateChanged(.reconnecting)` | `linkFailed(willRetry: true)`を通し、`connectionState = .reconnectingOffline`へ反映する。Internetが手動復帰待ちでも、Localの独立した再試行は妨げない |
| `stateChanged(.failed)` | `linkFailed(willRetry: false)`を通し、音声を停止してidleへ戻す。失敗理由は残し、CallのConnectから明示的に再操作できる。開始・切断・Internet接続復帰で古い理由を消す |

## 招待 URL

App はグループ参加用に `rideintercom://join?token=...` を扱う。

| 項目 | 仕様 |
|---|---|
| URL scheme | `rideintercom://join` |
| query | `token` |
| token 形式 | base64url JSON |
| 生成元 | 共有対象 group |
| 受理先 | App の deep link 入口 |
| 失敗時 | group へ参加せず、受理失敗として表示する |

### token 内容

| フィールド | 内容 |
|---|---|
| `version` | 現行は4。招待専用の確認情報を持たない旧1〜3は拒否し、新しい招待を受け取る |
| `groupID` | 参加先 group ID |
| `groupName` | 参加先 group 表示名 |
| `groupSecret` | RTC credential 生成に使う secret |
| `inviterMemberID` | 招待元 member ID |
| `inviterDisplayName` | 招待者本人の名前。Appは本人名を含める。省略時は既知の名前またはInviterを表示。UTF-8をbase64化して署名に含め、名前内の区切り文字を許す。相手側の別名は共有しない |
| `recipientMemberID` | 個別通話で必須。指定された端末member ID以外での受理を拒否し、署名の対象に含める |
| `issuedAt` | 発行時刻 |
| `expiresAt` | 失効時刻。Appの共有は7日間。招待確認情報の期限とも一致させる |
| `directInvitation` | 招待ID・group ID・招待者member ID・宛先member ID（個別通話）・期限と、その組合せ専用の32byte秘密。JSONのkey順を固定してbase64化し、group署名にも含める。招待URL外へ秘密を再送・保存しない |
| `signature` | 改ざん検知用署名 |

### 受理フロー

| 手順 | 動作 |
|---|---|
| decode | URL から token を復元する |
| validate | version、signature、expiresAt を検証する |
| store | GroupRepositoryで新しい参照UUIDの鍵をKeychainへ保存・読戻し確認し、参照を含むmanifestをatomic replaceする。旧鍵はcommit後に回収する |
| select | 受理した group を選択状態にする |
| report | 成功または失敗を UI に表示する |

## App data

RTC の `ApplicationDataMessage` は任意 payload の配送だけを担当する。RideIntercom 固有の namespace と payload schema は App が管理する。

| namespace | delivery | 所有者 | 用途 |
|---|---|---|---|
| `rideintercom.rtc.runtimeStatus` | RTC package が決める | RTC package | 接続、route、media、codec、local control、他 package runtime report を同期する |
| `rideintercom.keepalive` | reliable | App | 参加・設定変更時にpeerのlightweight metadataを同期。無音frame数による定期送信はしない。接続維持のpresenceはRTCが所有 |
| `rideintercom.profile-challenge.v1` | reliable | App | group認証済みのpeerごとにランダムUUIDの確認値を要求。group ID・宛先・最大1KiBを確認。接続中の端末署名確認に使い、一覧登録の根拠にしない |
| `rideintercom.display-name.v2` | reliable | App | group・送信member・宛先member・確認値・単調増加revision・本人名へ端末署名を付ける。最大8KiB。受信側の確認値、署名、保存済み端末鍵、利用可能な本人証明を照合する。v1の未署名更新は受理しない |
| `rideintercom.peerMuteState` | reliable | App | ローカルマイクミュート状態を相手画面へ同期する |

RTC package-owned namespace は App 固有 schema より先に `RTCRuntimeStatusTransport.decode(_:)` で判定する。decode できた場合は `remoteRuntimeStatuses[peerID]` へ保持し、App data として再解釈しない。

### `rideintercom.rtc.runtimeStatus`

| フィールド | App の扱い |
|---|---|
| `connectionState` / `isMediaStarted` | remote peer の control / media 状態として保持する |
| `routeSnapshot` / `routes` | active route、media route、route capability、media ownership を package 情報として保持する |
| `audioPolicy` / `routes.selectedAudioCodec` | remote peer の codec policy、送信 format、実選択 codec として保持する |
| `localMute` / `outputMute` / `remoteOutputVolumes` | remote peer が公開した local control 状態として保持する |
| `packageReports` | SessionManager、Codec、AudioMixer、Effectors など他 package の report として保持する |

### `rideintercom.keepalive`

| フィールド | 内容 |
|---|---|
| `activeCodec` | peer が最後に選択した codec。受信側の `GroupMember.activeCodec` に反映する |

### `rideintercom.peerMuteState`

| フィールド | 内容 |
|---|---|
| `isMuted` | 送話ミュート状態 |

未対応 namespace は無視する。未認証 peer からの App data 受理可否は RTC package の責務とする。

## Package runtime report 送信

App は RTC 以外の package runtime report を集め、`CallSession.updateRuntimePackageReports(_:)` で RTC へ渡す。RTC は payload を解釈せず、`RTCRuntimeStatus.packageReports` として package-owned runtime status に同梱する。

ローカル診断画面を表示中の0.5秒更新とネットワーク送信を分離する。診断画面を閉じている間のsnapshot作成は5秒間隔とし、開いた時点と設定操作時は即時更新する。RTCは最新reportを保持し、既定5秒のstatusまたは接続・操作の即時statusへ同梱する。診断値の更新回数に比例したnative通信統計の取得や送信は行わない。mute・codec設定など利用者操作の通知は待機させない。

| package | report kind | payload |
|---|---|---|
| AudioMixer | `snapshot` | `AudioMixerSnapshot` |
| Codec | `runtimeReport` | `CodecRuntimeReport` |
| VADGate | `runtimeSnapshot` | `VADGateRuntimeSnapshot` |
| SoundIsolation | `transmitConfiguration` / `receiveMasterConfiguration` | `VoiceIsolationConfiguration`（要求値） |
| DynamicsProcessor | `transmitConfiguration` | `DynamicsProcessorConfiguration`（要求値） |
| PeakLimiter | `transmitConfiguration` / `receiveMasterConfiguration` | `PeakLimiterConfiguration`（要求値） |
| SessionManager | `audioSessionConfigurationRequest` | `AudioSessionConfiguration` |
| SessionManager | `audioSessionConfigurationReport` | `AudioSessionConfigurationReport` |
| SessionManager | `inputStreamOperationReport` / `outputStreamOperationReport` / `voiceProcessingOperationReport` | `AudioStreamOperationReport` |

| 送信契機 | App の動作 |
|---|---|
| 接続開始 / 認証 / 切断 | report を強制更新し RTC へ渡す |
| media start / media stop | 音声 pipeline の開始停止結果を report に反映して渡す |
| 設定変更 | codec、bitrate、VAD、mute、ducking、output mute、master volume、peer volume、SoundIsolation を変更した時点で渡す |
| SessionManager report 受信 | session / stream / voice processing report を保持して即時渡す |
| 通話 tick | 診断表示中は最短0.5秒、非表示は5秒間隔で最新reportを渡す |

RTC package は接続開始、route変更、media開始/停止、local control変更、定期周期で `rideintercom.rtc.runtimeStatus` を送る。package report更新は周期へ集約し、周期を無効にした明示配信方式だけ更新時に送る。App はこの status を、通信相手の設定や操作状態の正本として扱う。音声設定そのものの適用は即時であり、遠隔診断の更新周期によって音声処理を待機させない。

## 混在グループと利用者への表示

| 状態 | 動作と表示 |
|---|---|
| Local / Internet両方 | `Local + Internet / Relay`。Local専用参加者と遠隔参加者を接続可能な参加者経由で中継 |
| InternetをOFF | 自端末はSFUに接続しない。他の参加者経由で遠隔音声を受けられる。Settingsで意味と電池・通信量を説明 |
| Internet失敗 | 通常は自動再試行を案内。既存Local通話を停止せず、失敗詳細はDiagnosticsへ表示。既存アカウント通話との競合はCallに手動復帰の理由を表示し、自動再試行と混同しない |
| 一部離脱 | 該当peerを除外。代替経路があれば残りの通話を継続。presence失効まで最大8秒 |
| 最後の中継者が離脱 | 分断された相手には届かない。同じ連結成分の通話は維持。再接続・再認証後に自動合流 |
| 音声機器が消失 | 自分の送受話を一時停止して再開を案内。中継は維持 |
| 手動route設定変更 | 現在の通話を停止する操作であることをSettings footerへ明示。自然な経路喪失とは区別 |

接続グラフ上の経路が存在し、認証・lease・OS実行・通信品質の条件が成立する間の到達性を対象とする。経路の切替瞬間の無音ゼロ、ネットワーク分断中の全員通話、予算上限後の無期限継続は保証しない。

試験範囲と確認状況は[検証](../../validation/README.md)を参照する。

## 本人名と端末内の呼び名

| 対象 | 契約 |
|---|---|
| 自分の名前 | Settingsで自由に設定。空白のみ・制御文字・UTF-8で320byte超は拒否。アカウント別UserDefaultsへ保存し、IDは変えない。招待と認証済みgroup通信で本人の名前を共有する |
| 再起動と通話継続 | 自分の名前はlocal identityを正本とし、保存groupを開く際にも反映。編集中の通話や鍵を作り直さず、新しい名前を通知する |
| 保存ユーザー | 呼び名はこの端末のユーザー一覧と所属groupで共通。本人名も常に確認できる。変更・復元を相手へ送信しない。受信した本人名の更新には、直接招待で保存した端末鍵との一致が必要。同じ鍵でも双方に確認済みprincipalがあり異なれば更新しない |
| 接続中の証明 | peerごとの新しい確認値とgroup・相手・宛先・revision・名前を`shareDisplayName`用途で署名する。`VerifiedPeerProfile`だけを保存処理へ渡し、未知group・別鍵・別の確認済み本人は更新しない。アカウント宛てdirectの未知memberは、相手principalの有効な証明がある場合だけgroup内へ追加する。不正な入力は保存障害にせず無視する。利用可能な自分の登録先の発行鍵で証明を検証し、証明がないLocalでは端末鍵を確認する |
| 音声許可 | RTCの現在の参加参照と接続ごとの署名確認結果を対応させ、アカウント宛てdirectでは相手principalまたは保存済み端末鍵も確認し、自分の確認済みprincipalは除外する。許可した参加者だけを`RTCAudioPolicy.peerPolicy.admittedMemberships`へ渡す。接続前・確認前は空集合。codec/format更新でも同じ確認状態を合成し、既定の全group参加者方式へ戻さない。受信待ちと音声配送の判定は[RTC](../packages/RTC.md#参加単位の音声許可)へ委ね、AppのUIイベントで音声を後から除外しない |
| 再送と順序 | 未確認の相手への確認要求は既存の通話tickを使い、1・2・4・8・16・32秒、以後60秒へ間隔を広げる。確認後は定期要求を停止。相手からの要求への返信はpeerごとに毎秒1回までとし、同じ確認値・名前なら同じ署名済みbytesを再送する。本人の名前編集時は新しいrevisionで送る。受信済み以下のrevisionは保存せず、古い名前への巻戻しを拒否する |
| 証明状態の寿命 | 最大7peerの確認値・署名応答・確認結果をメモリだけに保持。peer消失・通話切替・切断・全経路失敗・サインアウトで破棄し、再接続では新しい確認値を使う。別groupの閲覧だけでは進行中の通話の証明を破棄しない |
| group内だけの相手 | 呼び名は対象group内だけに保持。署名付き本人名を受けてもSaved Usersへ追加せず、別groupの名前や操作権限を増やさない。同じ接続中に確認した端末鍵の差替えを拒否する。直接招待で保存した鍵がない相手の自己提示鍵を、group外の権限に使わない |
| server | 名前の中央保存は追加しない。接続中の名前更新も既存の暗号化application dataを使用する |

この確認は端末署名と保存鍵の対応に基づく音声許可である。group内だけの相手は今回提示された端末鍵を使い、別groupへの権限を持たせない。RTCのgroup共有鍵による暗号化を維持しており、音声packet個別の署名・送信先別暗号化を追加するものではない。

| ユーザー更新 | 受け取った本人名と自分用の呼び名を別々に保存し、同じmanifest内の該当group memberへ反映する。本人名の更新で呼び名を上書きせず、Use Shared NameでlocalNameを消すと最新の本人名を表示し、以後の本人名更新にも追従する。一覧からの削除はusersと参照だけを除き、group内のID・表示名・所属・鍵・進行中の通話を保持する。通常のgroup再保存で削除ユーザーを再登録しない |
| 直接招待の登録 | 有効なversion 6招待URLの受取時に招待者を登録し、招待専用秘密から受取証明を作る。受取証明は`rideintercom.direct-invitation.v3`の認証済みapplication dataで送る。招待者は自分の非公開鍵から同じ招待専用秘密を導出し、期限・group・送信peer・宛先・受取ID・受取人公開鍵を含むHMAC・受取端末署名を照合した`VerifiedDirectInvitation`だけを保存処理へ渡す。group所属や未確認の自己申告から保存ユーザーへ昇格させない |
| 端末署名 | 発行・受理・ACK・接続中の本人名を異なる用途としてP-256署名する。`rideintercom.device-proof.v1`のdomain、用途、member ID、端末公開鍵、任意の証明と発行公開鍵、対象payloadを順に、各UTF-8/byte列の4byte big-endian長とともに署名する。発行は招待全体のHMAC、受理は一意な招待・受取IDと内容、ACKは受取署名を含む内容を対象とする。一意な招待IDが使い回しを拒否するため、一覧保存のためだけの追加challenge往復は行わない |
| 信頼とLocal | 端末の秘密鍵はInternet登録と共通のアカウント別Keychainで管理し、Localだけでも用意できる。自分のHTTPS登録先から取得済みの発行鍵で検証でき、member ID・端末鍵が一致した証明だけをprincipalへ対応付ける。証明未取得・期限切れ・別サービスの証明は同一ユーザーの根拠にせず、直接招待の端末鍵の確認だけでLocal利用を継続する。相手の証明を信頼する起点には使わない |
| 鍵と名前の衝突 | 保存済みmember IDの鍵が違う、同じ端末鍵でも確認済みアカウントが違う場合は既存の相手を上書きしない。同一人物への統合では既存UUID・呼び名を維持する。別々の項目の呼び名が衝突する場合は自動で片方を消さず、一覧の名前整理・削除後の新しい招待で解決する |
| 受信の失敗 | 不正な署名は保存障害として扱わず破棄し、一覧編集を使用不能にしない。ACKは元の招待発行端末の署名を必要とする。再送・ACK作成時に元の鍵が欠けていたら新しい鍵で代用しない |
| 招待発行者の鍵 | アカウント別namespaceの`.DirectInvitations` service、`author` accountへ32byte乱数をKeychain保存する。初回はSecItemAddで既存値を置換せず、同時作成時は先に保存された鍵を読み直して使う。読取不能・不正な既存値を別の鍵で上書きしない。group ID・招待ID・招待者とその公開鍵・宛先・期限を区別したHMAC-SHA256から招待専用秘密を導出する。非公開鍵はURL・manifest・application dataへ出さない |
| 再送と削除 | 未応答の受取証明だけをmanifestへ保持し、招待者との認証成立後・既存keepalive時に期限内だけ再送する。招待専用秘密は保存しない。受取IDは招待IDと受取人member IDから固定し、同じURLの再受理も同一の受取となる。招待者は処理済みIDを保存してから応答し、一覧削除後に再送・再受理・任意IDへの付替えで再登録しない。新しく発行した招待は別の受取となる。受理側も同じ処理済みIDを保存し、削除した招待者を古いリンクから復活させない。schema 5への更新では旧形式の未応答receiptだけを終了し、group・ユーザー・鍵を維持する。旧形式の無署名ユーザーをmember IDだけで確認済みの相手へ昇格させない |
| 招待の発行時点 | 画面と診断の可否表示はメモリ上の状態だけを使い、鍵の読込・作成・署名を行わない。OS共有画面がURLデータを要求した時点で、表示時のgroup ID、現在のログイン世代、保存状態、所属、個別通話の宛先を再確認し、鍵を取得して新しい招待IDを発行する。画面切替・相手削除・再ログイン・保存競合後の古い共有要求は拒否する。新しい共有要求を過去の招待URLの無期限キャッシュに置き換えない |
| 招待確認の境界 | 通常groupのURLは所持者が受け取れる招待情報であり、転送すれば招待情報も渡る。個別通話は署名対象の端末／アカウント宛先を照合するが、URL内のgroup秘密情報そのもののコピーを防ぐものではない。group内で受取証明だけを見た第三者は別の受取人・招待・期限・受取IDの有効な証明を作れない。本人名も受取端末署名で保護するが、名前の一致ではIDを統合しない。直接招待の本人対応と、通知先の用途別許可・解除は別契約であり、この確認値を公開通知APIの認可へ流用しない |
| group内だけの相手 | 直接招待関係がない参加者のID・表示名はgroup内で保持するが、独立ユーザー一覧へ登録せず、一覧を使う別groupへの追加対象にも解決しない。ユーザー指定の個別通話にも解決しない。通知は未実装であり、今後もgroup共有や相手IDの知識をgroup外操作の権限にしない |
| 旧保存形式の読取 | schema 1・2のgroupはkind=group、schema 3〜5は既存kindを維持し、ID・member・最後の保存名・鍵参照・受取記録・usersを保ってschema 6をatomic commitし読戻す。旧形式の未署名の送信待ち受取証明は破棄する。失われた本人名・未確認の旧ユーザー鍵は推測せず、本人確認のうえ一覧から削除して新しい直接招待で登録し直す。schema 1の所属からusersを登録しない。失敗時は旧bytesと鍵を保持。schema 2以降のusers不整合、schema 3以降のkind欠落・不正は読込失敗。schema 5の署名済み送信待ちreceiptは維持する。schema 5以前でaccountPairを宣言した入力は拒否し、旧版はschema 6を拒否する |
| KeychainGroupCredentialStore | RideIntercom.GroupCredential.v2 service内の新しいUUID accountへ鍵を保存。参照先の鍵を上書きしない。保存後に同じ値を読めることを確認してからmanifestへ参照を追加 |
| commit境界 | 同じdirectoryでのJSON atomic replaceを唯一の確定点とする。replace前の中断は旧一覧と旧鍵、replace後の中断は新一覧と新鍵を選ぶ。途中で残った未参照鍵は正常読込後または次のcommit後に回収 |
| 多重起動 | 読込・移行・commit・回収・resetを同じflockで排他。取得できなければ待ちTaskを増やさず失敗。読込時のgenerationを含むsnapshotが変わっていれば書込を止め、Reloadを要求 |
| 復元 | groupは1–8人、ID重複なし。member IDはASCII英数/ハイフン/アンダースコアの1–63 byte、表示名は空白のみ不可・制御文字不可・UTF-8最大320 byte。local memberを先頭へ配置し、不在なら読込失敗 |
| 読込失敗 | 空の初期データと区別。元データと鍵を保持し上書き・回収を禁止。GroupsのReload Saved Groupsで再試行。通話中は先にDisconnect |
| 保存失敗 | group作成・参加・削除をUIで成功としない。replace後の読戻し失敗では実際にはcommit済みの場合があるため、旧状態へrollbackせず再読込で確定する |
| 更新候補の不正 | identity/人数のdomain違反はcommit前で拒否し既存snapshotを保持。保存済みデータの破損とは区別してReloadを案内し、reset操作は出さない |
| 鍵の欠落 | Keychainのnilと読取errorを区別。nilはgroupを残して再招待を案内。アクセスerrorは読込を止め、端末ロック解除などの後にReload |
| 鍵回収失敗 | commit成功を取り消さない。回収待ちを表示し次の正常読込・commitで再試行。削除groupは復活しない |
| 旧形式の移行 | 新manifestがない場合だけ旧UserDefaultsのRideIntercom.groupsと旧Keychain serviceを読む。新鍵を準備しmanifestを確定してから旧鍵・旧一覧を削除。失敗時は再試行可能。二重書込と旧版へのdowngradeはサポートしない |
| 破損のreset | Reset Saved Groupsでユーザーも削除することを確認後、読めないJSONと残存する旧defaultsを同directoryへ退避してusers・groupsが空のmanifestをcommit。退避できなければ削除しない。group鍵のみ回収し、rider identity・音声設定・Internet資格を保持 |
| 未知schema | versionを先に確認し新しい形式は対応版で開くよう案内。旧形式へfallbackせず、resetも拒否する |
| runtime更新 | voice level、talking、codec、認証・接続通知、frame counterの変化では保存しない。参加者追加・置換など永続情報が変わった場合だけ保存 |
| 人数 | 自分を含む最大8人。満員後の新規参加者は未接続の保存メンバーを置換する。接続済みメンバーを追い出さない |
| 削除 | manifestからgroup参照を除いた後にKeychainの未参照鍵を回収。独立usersは残す。配布済み招待や別端末の鍵は失効しない。別groupの参加者削除でactive groupの認証・音声状態を変更しない |
| Internet設定 | composition時に一度読み、Adapterへ注入。Keychain読込/JSON不正は未設定と区別して表示。transport層から保存先へ直接アクセスしない |

この設計はプロセス中断時の旧/新snapshotの整合性を対象とし、電源断・媒体故障に対する耐久性を保証しない。fsyncを含む永続transaction、履歴の選択復元、破損内容の推測修復は設けない。退避ファイルは自動復元しない。Keychainとmanifest自体が別々に消去された場合は再招待が必要。UserDefaultsに残る設定・identityのset成功もディスク同期保証ではない。

## App command待機の所有

| 所有者・境界 | 契約 |
|---|---|
| CallSessionContracts | AppのCallSession portとイベント語彙。RTCへの依存変換はadapterが所有 |
| CallCommandQueue | typed commandを最大64件、application payload合計256 KiB・単件64 KiBまで保持。待機ごとのTaskは作らない |
| 集約 | 同一接続世代かつ最後の順序境界より後にあるconfiguration、mute、output mute、runtime reports、既知の状態通知だけ最新値へ置換。置換値は末尾へ移動 |
| 順序境界 | connect / startMedia / stopMedia / disconnect、一般application messageはFIFO。別世代や境界を跨いで設定を消さない |
| 実行 | adapterの単一workerがRTCをawaitする。設定commandが実行される時だけRTC sessionを生成し、中間設定ごとの重い生成を避ける |
| 上限超過 | 待機commandを破棄し停止commandを確保、送話受付を止め、UIへ明示通知。実行中処理が戻った後に停止。利用者の明示再接続で最新の希望設定を再適用 |
| 音声送信 | commandとは別の1 worker、待機は最新1packet・100ms期限。mute/切断で待機を破棄し、非協調の送信awaitが残る間も新workerを重ねない |

実行中の非協調RTC処理を強制終了する仕組みは設けない。待機メモリとTask数は制限するが停止完了時刻は保証できず、処理が戻るまで再接続を拒否する。一般messageの過負荷は黙って欠落させず切断として扱う。64件は待機分で、実行中1件は別枠である。

## 招待受理の追加制約

URLは最大8192 UTF-8 byte、token queryは一つだけ。userinfo・port・path・fragmentを拒否する。復号後にversion、非空secret（最大256 byte）、name/ID、有限かつ非負のissuedAt、issuedAt以上のexpiresAt、signatureを確認する。署名入力の曖昧さを避けるためname/secretの`|`は拒否する。

同じgroup・同じ鍵の再招待は保存メンバーを置換しない。自分が招待元なら重複メンバーを追加しない。active groupの鍵を変える招待は、先にDisconnectするよう案内して拒否する。共有secretのHMACに加えて発行端末署名を照合する。アカウント宛て招待では信頼済みserviceの証明も必須とし、共有secretだけを本人証明にしない。

## 保存ユーザーを指定する個別通話

| 対象 | 現行の契約 |
|---|---|
| 通話先の解決 | `selectUser`は独立usersのUUIDを受け取り、直接招待関係として保存した相手だけを解決する。画面はgroup IDや鍵を作らない。削除済みUUID・group内だけの相手は拒否する |
| 同じ二人の再利用 | 双方の確認済みprincipal（service originと公開userID）を順序によらないUUIDへ変換し、kind=directの内部groupを保存する。端末の追加・変更で通話IDは変わらない。公開IDは識別子だけに使い、鍵は256bit乱数で別途Keychain保存する。同じ二人の再選択・再起動では同じIDと鍵を再利用。既存の通常groupを個別通話へ転用しない |
| 対象の単位 | 直接招待で保存した相手だけが対象。同じprincipalの複数端末は一つの相手として選択でき、自分の別端末はUsersの個別通話対象から除外する。相手にprincipalがないLocalでは従来の二つのmember IDを使い、複数memberの宛先を推測しない。確認済みの相手に対して本人principalが欠ける場合はInternet Connectionでの確認を案内し、端末宛ての別通話を作らない。端末宛てとアカウント宛ての保存通話は自動統合しない |
| 初回の共有 | 本人名と招待確認情報を含む相手宛てのversion 6招待を明示共有する。アカウント宛てでは発行者・受取人のprincipalを招待HMACと端末署名へ含め、双方の有効な証明・宛先・pair ID・期限・既存kindを確認する。同じ相手の別端末は受理でき、第三者は一覧・groupを保存しない。新しいアカウント招待に証明が足りなければInternet Connectionでの確認を案内する。通知・端末の自動起動は行わない |
| 同時作成 | 両側が先に同じ二人の通話を作った場合は、principalの固定順（originのbase64とuserID）で先の側の招待へ鍵を揃える。端末IDの順に依存しない。端末宛てLocalはmember ID順を維持。active groupの鍵を替える受理はDisconnect後に行い、新しい内部groupを増やさない |
| オフライン | 自分の確認済みprincipalは、member ID・公開鍵・originと同じKeychainレコードに保持し、証明期限後も保存済み通話を解決する。相手はgroup内に保存した端末公開鍵で新しい接続確認値への署名を照合する。期限切れ証明で未知端末を登録しない。資格の差替え・サインアウトで自分のキャッシュを解除する |
| 表示と切替 | 通常のRecent Groupsには内部groupを出さず、Usersで相手名を選ぶ。画面タイトルも相手名を使う。別通話中の選択は閲覧だけで、Connectが明示的な切替。Current Callから進行中の個別通話へ戻れる |
| 参加者の範囲 | アカウント宛てdirectは二人のprincipalに固定し、端末rosterと鍵対応を最大8件（自端末を含む）保持する。未知端末はgroup認証だけでは音声を許可せず、接続ごとの署名と相手principalの有効な証明が必要。確認済み端末鍵の差替え・別principal・自分の別端末を拒否する。満杯時のprofile登録は未接続の相手端末だけを置換し、全件接続中なら拒否する。招待再受理は既存rosterを追い出さず、追加枠がなければ拒否する。端末宛てLocalは2member固定で、想定外peerなら停止する。UIから第三者の追加・削除・通常groupへの変換は認めない |
| 一覧削除 | usersから削除しても内部group・鍵・進行中の通話は維持する。Current Callの終了操作を残すが、削除UUIDによる新しい解決と招待リンクの共有は認めない。新しい直接招待で再登録すれば保存済み内部groupを再利用する |
| 後続との境界 | StoreKit・24時間の共通利用権判定・呼出し通知は未実装。Appleログイン必須化と直接招待でのserver userID・端末member ID・保存ユーザー対応は実装済み。アカウント宛て個別通話でも端末間の保存・鍵の自動同期は行わず、新しい端末には招待を共有する。二人のIDだけを通知権限や購入確認に使わない。確定条件は[利用権とデータ保持の設計](../../backlog/利用権とデータ保持の設計.md)を引き継ぐ |


## アカウント削除と端末内消去

`AccountDeletion`は通常のサインアウトと独立した削除記録をbase namespaceのKeychain `.AccountDeletion/pending`へ保持する。記録の保存成功後にログイン世代を失効し通話を停止する。この間はサインアウト用の`DELETE /api/auth/session`を送らず、削除記録が所有するBearerを`DELETE /api/auth/account`の再送に使う。記録はnative Apple ID、接続先・端末ID・Bearer・削除対象の公開ID、未送達の再認証proof、serverの受理／Apple取消／媒体回収状態、端末内消去の完了を保持する。秘密・識別子をログへ出さない。

serverの`deleted:true`を受け取って永続化してから端末内データを消去する。Apple取消または媒体回収がpendingでもserverのアカウント削除が受理されていれば端末内消去を進め、再試行のBearerと未完状態を別記録へ残す。受理済みのproofは除去する。HTTP 401は通常の端末サインアウトでは再送完了にできるが、アカウント削除では拒否とする。削除結果の矛盾・不足、通信／保存エラーを成功に変換しない。server未受理時のApple証明更新・証明なしへの変更は本人の明示操作に限る。起動時に一度再開し、失敗後は操作による再試行とする。401で取消待ちの受領記録を確認できなくなった場合も、端末内消去済みという状態は保持し、明示的なApple再認証へ戻す。再認証proofには保存済み公開IDを`expectedUserID`として含め、別世代の登録を削除しない。serverの`newerAccountPreserved`は保存済みの削除対象IDがある場合だけ受理し（fresh proofによる復旧と、確認済み受領記録への再送の両方）、取消済み／取消待ち／媒体回収待ちとの矛盾を拒否する。この応答では新しいアカウントのApple認可を保持したと表示し、手動解除を勧めない。

`appleRevocationPending`と`mediaCleanupPending`のいずれかがtrueなら完了操作を出さず、残る処理を案内する。どちらも再起動後の再試行対象とし、片方だけ完了しても残りを失わない。再登録の`409 deletion_pending`は削除開始端末での完了を案内し、8端末上限とは区別する。未知の409 codeを端末上限と決めつけない。

`AccountDataEraser`はnative Apple IDから導いた既存のaccount namespaceだけを対象とする。Groupsの非ブロッキングlockを取得し、新しいgenerationの空manifestへ置換して古いrepositoryの書戻しを拒否する。同じアカウントのGroupCredential v2／旧形式、Internet資格・端末署名鍵・証明、招待発行者鍵、UserDefaultsを消去し、破損時の退避ファイルも除去する。個人データを含まない空manifestとlock inodeは残す。別アカウントを走査・削除せず、対象namespaceまたはGroupsがsymlinkなら拒否する。中断・部分失敗は同じ消去を再実行する。

サインアウト成功後も最後の登録の接続先・公開ID・端末ID・失効済みBearerを保持する。`deletionAccess`は削除復旧に使い、新しいApple本人確認を必須にする。同じ退避の確認済みprincipalと発行者の公開検証鍵は、nativeログインとアカウント別保存領域の境界内でLocal通話の本人識別・相手証明の検証にも使う。保存破損・読取失敗を「Internet未登録」と扱わず、通常の資格load・端末証明・開発fallbackには復帰させない。退避もアカウント消去時のKeychain列挙で削除する。

現在資格にも削除復旧用の退避にも公開Internet登録がなければ、端末内消去とApple手動解除を案内する。開発用fallback資格をアカウント削除APIへ送らない。未知の別サービス登録、他端末のオフライン保存、共有済みのグループ情報、購入解約まで消去したとは扱わない。server契約は[Worker](../server/Worker.md#アカウントの端末登録削除)、操作は[Settings](UI/Settings.md#アカウント削除)を参照する。

## 公開IDの再登録後に残った端末内データ

同じサービスへのApple再認証で、確認済み公開IDが以前と変わった場合は、旧アカウントの端末内関係を新アカウントへ引き継がない。本人の公開IDが同じ通常の再ログイン・資格更新はこの処理に入らない。オフラインのLocal開始をserver照会待ちにせず、登録時に確認できた変更だけを扱う。

| 段階 | 動作 |
|---|---|
| 検知 | `InternetConnectionSettingsStore.save`は現在の確認済み登録、なければ最後の退避登録と、新しい確認済み証明のissuer・公開IDを比較。同じissuerで公開IDが違えば上書き前にアカウント別UserDefaultsの`InternetAccount.requiresDataReset`を立てる |
| 停止 | 通話を切断しInternet確認世代を更新。通話・招待・保存変更と資格差替えを止める。nativeログイン世代の有効性は別判定とし、復旧操作を残す。再起動・手動設定・別issuerへの保存ではflagを解除しない |
| 明示的な消去 | Rootの復旧画面で確認すると、既存`AccountDeletion`へ`localReset`と端末登録IDを永続記録してからサインアウト。server削除や追加Apple証明は要求せず、`AccountDataEraser`で旧Users・groups・member ID・署名鍵・招待鍵・設定を消す |
| 端末枠 | 再設定で同じ端末登録枠を更新できるよう、`device-id`だけ書き戻す。Bearer・本人principal・所属・秘密鍵は残さない。新資格のbest-effort失効が通信断で失敗しても、次の登録で同じdeviceIDのtokenHashが更新され、端末枠を増やさない。失効の即時完了を保証するものではない |
| 失敗・再起動 | ローカル消去と端末ID書戻しが成功するまで完了にしない。記録を使って再試行し、通信を待たない。完了後だけ再ログインとInternet再設定へ戻り、新しい招待・鍵で関係を作り直す |
| 通常削除との違い | 新serverアカウントとApple認可は保持し、Apple手動解除を案内しない。通常のDelete Accountは従来どおりserver削除を行い、端末登録IDも消す |

手動資格の保存前にも現在の確認済み登録を退避し、未確認の手動資格のサインアウトでそれを上書きしない。退避失敗・破損は既存登録を残してエラーにする。これは現在または最後に退避した確認済み登録の比較であり、過去の複数サービス全履歴を管理する機能ではない。
