# 配布環境の利用権仕様

TestFlightで購入操作なしに試用できるよう、購入とは別の「テスト配布の利用権」を端末内で判定する。[StoreKit利用権](利用権仕様.md)の週券・月額・復元を置き換えない。厳密なTestFlight識別や不正改変への課金強制のための署名解析、XPC、独自サーバー照会、購入台帳は設けない。

## 判定条件と許容する範囲

| 条件 | 配布由来の権利 |
|---|---|
| DEBUG、RIDEINTERCOM_VALIDATION、RIDEINTERCOM_STOREKIT_TESTING、Simulator | 自動確認を作らず、AppTransactionへの要求も行わない。権利なし・期限切れ・通常StoreKitの試験を維持 |
| 上記以外でAppTransactionが検証済み、bundleIDが現在のAppと一致、environmentがsandbox、アプリ取得が取消されていない | テスト配布の購入者相当として有効 |
| productionまたはStoreKit Testingのxcode環境 | 配布による付与なし。購入由来の通常判定を使用 |
| 未検証、bundleID不一致、空のbundleID、未知のenvironment | 判定不能。配布による権利を新しく与えない |
| AppTransactionのrevocationDateあり | 配布による付与なし |

sandboxはTestFlight専用の識別子ではなく、開発署名のアプリも使用する。この方式はRelease開発版や審査を含み得る、意図的に緩い配布条件である。Releaseで権利なしを検証する場合も、既存のRIDEINTERCOM_VALIDATIONを付けた検証経路を使う。開発版全体を購入者扱いする切替や製品画面からの迂回は追加しない。

[Appleのsandbox説明](https://developer.apple.com/documentation/storekit/testing-in-app-purchases-with-sandbox)は開発署名版とTestFlightの両方を対象とする。[AppTransaction.environment](https://developer.apple.com/documentation/storekit/apptransaction/environment)は署名したサーバー環境であり、配布経路の認証結果とは扱わない。

## 購入との分離と読取

| 対象 | 契約 |
|---|---|
| 出所 | StoreAccessEvaluation.originでpurchaseとtestDistributionを区別。配布権利を架空の商品・取引ID・購入日・週券期限へ変換しない |
| 商品未設定 | 公開catalogが空でも配布環境だけ独立確認できる。商品・購入取引・価格は照会せず販売しない。Debug/Validationでは配布確認もなく、従来どおり要求0 |
| API | AppTransaction.sharedのverified結果のみ使用。StoreKitが保持・更新する署名済みのアプリ取得情報を正本にする。raw payloadやreceiptファイル名から推測しない |
| 開始と前面復帰 | 既存のStoreKitAccess.start/refreshに接続。購入のread/statusと独立に進め、一方の応答待ちが他方の検証済み権利を隠さない |
| 更新の頻度 | 起動・前面復帰・利用者の復元で確認。購入updatesは購入だけを読み直し、配布確認の定期pollingや取引ごとの追加確認を行わない |
| 応答待ち | 既存StoreKitReadAttemptとreadTimeout（15秒）を使用。非協調APIのキャンセル完了を待ち続けず、stopと期限で待機を解除できる |
| 復元 | 通常の購入復元と認証シートの挙動を維持。配布確認のためにAppTransaction.refreshによる認証シートを自動要求しない |
| 期限 | AppTransactionにはTestFlightの利用期限がないため、署名日時から90日等の独自期限を計算しない。配布権利のactiveUntilはnilとし、購入権利の期限は従来どおり保持 |

AppTransaction.sharedは取得不能やApp Store未認証で失敗し、通信が必要な場合もある。初回・圏外でも必ず判別できるとは約束しない。[Appleのshared説明](https://developer.apple.com/documentation/storekit/apptransaction/shared)

## ログイン寿命と判定不能

| 対象 | 契約 |
|---|---|
| 対象ユーザー | 現在のisCurrentUserとログイン世代の範囲だけ有効。アプリ取得のApple AccountとRideIntercomのAppleログインを同一IDと推測しない |
| stop | 購入・配布の両待機を解除し、配布状態を未判定へ戻す。既に始まっていたstart/refresh/restoreから、stop後に新しい配布確認を開始しない |
| 遅延結果 | 完了済み要求と旧ログイン世代の結果を破棄。新しいstartで再確認でき、旧結果で新モデルを上書きしない |
| 一時的な取得エラー | 同じ実行プロセスの同じログイン世代で確認済みのテスト配布権利は保持できる。購入済みの期限内権利も独立して維持 |
| 新しい判定結果 | production等の検証済み通常環境や未検証結果を取得した場合は、過去の配布権利を維持しない |
| 保存 | TestFlight/paidフラグ、独自のアプリ取得台帳、配布状態の永続cacheは作らない。新しいAppモデル・起動時に、過去のメモリ状態だけで権利を復活させない |

## 状態表示と再確認

| 項目 | 表示・操作 |
|---|---|
| 利用権の状態 | StoreAccessSectionのAccess / Access Statusで共通表示し、既存のstoreAccessSection / purchaseStatus識別子を維持 |
| テスト配布で有効 | originがtestDistributionの場合は「テスト配布で利用可能」と表示。購入不要の配布権利と説明し、購入したように表示しない。架空の有効期限を付けない |
| 購入で有効 | 従来のAvailableとAvailable Untilを維持 |
| 判定不能 | Check Access（利用権を確認）でrefreshだけを実行し、App Storeの購入復元・認証シートを開始しない。商品未設定でも再確認できる |
| 購入復元 | 商品設定済みではRestore Purchasesを維持。配布の再確認と、購入取引を復元する明示操作を区別 |
| 処理中 | isCheckingAccessは購入処理または配布確認が進行中の場合。両ボタンを無効にし、Check Accessは確認中と表示。既存の実行中handleから導出し、別のUI待機状態・queue・lockを作らない |

同時要求は既存の処理へまとめる。購入read中のrefreshは既存のpendingRefreshで後続readへ反映し、配布確認中の追加refreshは進行中の結果を使って新規照会を作らない。処理中のrestoreも新しいsyncを開始しないため、画面は操作を無効にして完了後の再操作へ戻す。同時呼出しのreturnを、個別の新しい確認が完了した証拠にはしない。stateの更新を結果とする。stopでは両処理を退役させ、新しいstartを可能にする。

## 自動検証と実配布の受入

| 対象 | 確認すること |
|---|---|
| 単体 | 署名検証・bundle・environment・取消の判定、商品未設定で購入要求0、出所の分離、取得失敗と通常環境への切替、stop・再開・遅延結果、購入と配布の独立、購入updatesで再照会しないこと |
| 既存回帰 | StoreKitの7日期限、全週券、返金updates、明示復元、月額の署名期限・検証済み猶予、標準認証待ちを維持 |
| 実配布 | iOS/macOSのTestFlight初回・再起動・圏外・取得失敗、App Store版への上書き、審査、Release開発版の実environmentを個別に確認。ローカルのfixture成功をTestFlightだけの識別成功に読み替えない |
| 通話操作 | この変更は利用権の取得と評価まで。グループ作成・招待・開始への適用範囲は共通操作の仕様で扱い、認証・所属・利用枠・費用上限を解除しない |

UIの変更はStoreAccessSectionの表示と再確認だけに限定する。Settings、ContentView、通話先履歴、App Intents、server、packageの処理は変更せず、共通モデルのoriginを用いて実購入と配布由来の状態を区別する。
