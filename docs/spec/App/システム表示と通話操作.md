# Widget・Controlと通話状態表示

## 操作の所有者

Widget extensionは通話やアカウントのモデルを生成しない。Appとextensionに同じ`OpenCallControlIntent`を含め、前面実行と端末認証を指定する。Appが登録した`CallSurfaceActions`は既存の`AppCallOwner`であり、保存先・ログイン・共通の利用権条件を実行時に再確認する。OS経由の受入は[未確認事項](../../validation/未確認事項.md)で管理する。

| 入口 | 現行動作 | 対象の境界 |
|---|---|---|
| 特定通話先Widget | Widgetの編集で保存ユーザー／通常groupを選び、Start callでAppの共通開始操作を実行 | 現在の選択用投影を読み直し、削除・破損・未選択ならAppの通話画面へ戻る。古いconfiguration内の名前や対象をfallbackとして使わない |
| 小サイズWidget | Choose a callでAppの通話画面を開く。Resume recent callでAppが保持する直近の成立済み通話先へ開始する | extensionは宛先・資格を保存しない。直近なし・削除済みはAppで説明し、別の進行中通話へ切り替えない |
| iOS Control | 通話画面表示／直近再開の独立したボタン | 同じ共有IntentとApp所有者を使用 |
| Live Activityの終了 | 表示中の通話参照を渡して共通`endCall`を実行 | ログイン世代・接続世代・group IDを照合し、古い表示から新しい通話を終了しない |
| Live Activity本体 | `rideintercom://call`で通話タブを表示 | URLだけでは開始・終了しない |

WidgetはiOS/macOS、ControlとLive ActivityはiOS targetに含む。最低OSは26.4を維持する。WidgetをCarPlayへ優先表示せず、CarPlay用アプリやWatch音声の対応とは扱わない。特定通話先Widgetも同じ共有IntentからAppへ実行を渡す。

## 通話状態の投影

| 項目 | 現行仕様 |
|---|---|
| 初期値と保存 | `liveActivityEnabled=false`。アカウント別UserDefaultsの`RideIntercom.settings.liveActivityEnabled`へ保存し、音声設定保存・Reset All Settingsでは維持する。アカウントデータ消去では消す |
| 表示内容 | 現在通話中のgroupに対する共通`callStatus(for:)`とミュート値だけ。閲覧中の別groupの状態へ切り替えず、本人・相手・groupの名前を出さない |
| 開始 | 設定ONかつApp前面で有効な通話投影がある場合、ActivityKitへ要求する。背景では新規要求しない |
| 更新 | 同じ投影の再送を抑止。状態変更時は背景でも更新し、Appの通話状態を正とする |
| 停止 | OFF、サインアウト、対象通話消失で表示を終了。表示側から媒体処理を停止しない |
| OSによる終了 | 利用者による消去・OSの終了（Live Activityの8時間上限を含む）では同じ通話の表示を自動再生成しない。次の通話または明示OFF→ONで再試行する |
| 失敗・再起動 | 表示要求失敗はSettingsで案内し、通話を継続。次回プロセスは前回の表示を先に終了し、それを通話復旧の証拠にしない |
| 非表示の意味 | OFFはAppが追加するLive Activityだけを対象とし、OSのマイク利用表示などを隠さない |

Appの`CallLiveActivityPresenter`が表示更新を直列化する。延滞した旧開始が完了しても、旧表示を終了してから次の通話へ更新する。`CallSurfaceReference`は対象照合のUUIDだけで、Apple識別子・秘密鍵・group鍵・通知資格を含めない。

Appleの[Widget操作](https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities)、[Control](https://developer.apple.com/documentation/widgetkit/creating-controls-to-perform-actions-across-the-system)、[Live Activity](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities)の契約を適用する。

## 特定通話先の選択用共有

| 境界 | 現行仕様 |
|---|---|
| App Group | `group.com.yowamushi-inc.RideIntercom.CallWidgets`をAppとWidgetのentitlementへ指定。`containerURL(forSecurityApplicationGroupIdentifier:)`配下の`call-destinations.json`を使用。実profile・Developer portalの登録は[受入条件](../../validation/未確認事項.md)で別管理 |
| 書込所有者 | Appの`WidgetDestinationPublisher`だけ。ログイン中の既存`callTargets`から保存ユーザー／通常groupを投影し、atomic write。extension targetにはwriter実装を含めない |
| 共有する内容 | schema versionと宛先ID・表示名・user/group種別だけ。既存宛先IDの端末本人識別子でアカウント境界を保つ。Appleの生識別子、署名鍵、group鍵、購入状態、通知capabilityを共有しない |
| group内だけの参加者 | Usersへ登録せず、Widget候補にも出さない。通常group自体は候補に含める |
| 候補と表示 | `WidgetConfigurationIntent`と`EntityStringQuery`で現在投影を読む。描画時もIDを再解決し、名前更新に追従。選択済み宛先名は`privacySensitive()`を付ける |
| 失効 | サインアウト、モデル変更、ユーザー／group削除で投影を更新し、該当timelineのreloadを要求する。OSの既存snapshotが即時消えるとは保証しない |
| 実行時 | App所有者が現在のログイン・宛先一覧でIDを再解決し、`startCall(...allowSwitchingCall:false)`へ渡す。共有JSONや過去のWidget表示を認可の根拠にしない |
| 読込失敗 | 共有container不在、ファイル破損、未知version、重複ID、1MiB超は空一覧。端末内の正本を削除せず、Appへ戻る操作を残す |
| 書込失敗・復旧 | 過去投影の削除を試み、次の前面復帰／一覧変更で再公開する。成功済みと同じ一覧でもファイルが破損・欠落していれば修復し、値もファイルも同じならreloadしない。通話を停止しない |

Appleの[設定可能なWidget](https://developer.apple.com/documentation/widgetkit/making-a-configurable-widget)と[App Group設定](https://developer.apple.com/documentation/xcode/configuring-app-groups)を使用する。OS27専用のquery実行先指定には依存しない。

## iPadとMacへの表示

iOS AppとWidgetの対応familyはiPhone・iPad。iPadでは対応するロック画面など、OSが提供する場所へ表示し、Dynamic Islandの有無で通話動作を変えない。Widgetはnative macOS targetにも含む。

27.2 SDKのActivityKitはmacOSからのActivity開始をunavailableとする。iPhoneで開始したLive Activityは、[Appleの共有条件](https://support.apple.com/en-ca/120684)を満たすMacのメニューバーへOSが表示する。この表示が表すのはiPhone側の通話であり、Macアプリの通話状態ではない。Mac自身の状態表示は[残作業](../../backlog/未実装課題.md#対応端末とos設定の追加点検)として扱う。最低OSはこの追加要望だけで変更しない。
