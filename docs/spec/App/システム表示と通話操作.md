# Widget・Control・Macメニューと通話状態表示

## 確定したWidgetの範囲

2026-11-01の利用者指定により、Widgetは**配置・設定時に指定した登録済みユーザーまたはグループへの通話専用リモコン**とする。Widgetからの通話先の新規登録・グループ作成・メンバー追加は提供しない。配置したWidgetの開始操作で、その設定先へ通話を開始できることを必須とし、毎回iPhoneで先に通話を開始することを求めない。

| 項目 | 契約 |
|---|---|
| 通話先 | Widgetの配置・設定時に保存済みユーザー／グループを選ぶ。通常操作で直近の別通話先へ自動変更しない |
| 操作 | 設定した相手への開始・終了・ミュート。別の通話先のリモコンへ自動的に変化しない |
| 未設定・削除済み | 設定先が必要であることを示す。別の相手・直近先で代用しない |
| Watchとの差 | Watchは保存済み一覧から通話先を選択できる。Widgetには通話先一覧や管理画面を持たせない |

実装済み。Widgetは設定先だけを開始し、現在通話の終了・ミュートは同じ設定先の通話であることを確認して表示する。未設定・削除済み・投影欠落・別ログインでは別通話の操作を出さない。直近再開はWidgetから除き、iOS ControlとSiri／Shortcutsの独立した入口に残す。

## 表示の構成

選択通話Widgetは`systemSmall`で、共通のbackgroundTop（ダークはdeepNavy）からbackgroundBaseへのグラデーション、上段左に設定先の種別の記号と語（「ユーザー」「グループ」）、上段右に全状態でアプリアイコンの画像`ridecom.appicon.small`（22pt、外観に合わせてライト／ダーク、色付きの外観でも元の色）を置き、名前、現在状態・操作を表示する。名前は1行に収まる大きさ（縮めて切らない）。未設定は上段左にアプリアイコンと「RideCom」、「長押しして接続先を設定」と「接続先を選ぶ」、待機は接続先の名前と全幅の「接続」だけを表示し、つながっていない状態の語（「未接続」）は出さない。Widget・Controlを追加したときの接続先は、Appが共有データ（`WidgetDestinationSnapshot`の`recentDestinationID`。省略可能で古いデータも読める）に書いた前回の接続先を既定値にする（`WidgetCallDestinationQuery.defaultResult()`）。前回の接続先がない、または削除された場合は未設定で始まる。通話中の名前は、同じ投影で設定先IDと現在通話先IDが一致した場合だけ表示し、名前を`privacySensitive`として扱う。状態は文字と記号を併用し、Watch操作中はマイク案内を折り返す。色付き・クリア外観やOSによる秘匿はWidgetKitに従う。

Live ActivityはRideCom、状態の記号と状態の語（会話中・接続中・音声停止中など。理由の補足は出さない）だけを表示し、ミュート中は通話のアクセサリと同じ「会話中・ミュート中」にする。「マイクオン／オフ」の文は置かない（compact trailingの記号だけはマイクの状態を示す）。切断操作を置かない。ロック画面はdeepNavyの標準background tintと白文字、状態記号だけを意味色にする。Dynamic Islandのleading・center・trailingとcompact／minimalを維持し、展開bottomの切断も表示しない。compactの接続中はwarningの静止した`progress.indicator`記号（WidgetKit・Live Activityは静止画で、回転する`ProgressView`を表示できないため）、ミュートはdangerの記号、keylineはaccentを使う。WidgetとActivityの表示はOSホストと同じSwiftUI Viewを共用する。アプリの識別には共有Asset Catalogのアプリアイコンの画像`ridecom.appicon.small`（`RideComAppMark`）を使う。背景が暗いロック画面とDynamic IslandはDarkの画像に固定する。ロック画面と展開leadingは「RideCom」の文字と並べ、compact leading・minimalは画像だけにする。

Widgetの開始は`borderedProminent`、補助操作は`bordered`を使う。WidgetKitのOSホストでglass系スタイルのラベルが表示されないため、操作可能な標準スタイルを使用し、独自のぼかしでガラスを再現しない。開始・補助の意味と44pt以上の操作範囲は維持する。

### 表示状態と操作

| 状態 | 選択通話Widget | Live Activity／Island |
|---|---|---|
| Ideal | 同じ設定先の通話状態と名前。標準borderedのミュートToggleと、離して置いた切断 | 名前なしの状態文・マイク状態。タップでAppへ |
| Empty | 設定先なし／投影から消失した場合は、長押し設定の案内とChoose a call。別の宛先を代用しない | 通話がなければOS表示を開始しない |
| Loading | connectingはwarningの`progress.indicator`記号と文字、切断だけを残す | 接続中の文言と進行表示。破壊操作なし |
| Partial | 音声停止はwarningの記号と文字。Watch所有中はマイク操作を表示せず「Apple Watchで操作中」と切断 | 音声停止／Watchのマイク所有を文字と記号で示す |
| Error | 音声利用不能はdangerの記号と文字、現在通話を終了できる。保存先消失は設定し直す案内へ戻る | 音声利用不能を記号と文字で示し、Appを開いて確認できる |

操作は同じIntentへ表示中の参照と明示Boolを渡し、開始・終了・再接続のライフサイクルをUIへ増設しない。未設定から設定後の待機、開始から接続待ち／成立／音声停止、終了後の待機へ既存投影で戻る。Controlは、追加するときに接続先を選ぶ宛先Control（`RideIntercom.DestinationCall`、`SelectControlCallDestination`）と直近再開の2つ。宛先Controlは未設定で「接続先を設定」（`plus`、Appを開く）、待機中で接続先の名前と「接続」（`phone.fill`、`OpenCallControlIntent(destinationID:)`で端末認証の後にAppを開いて開始し、別の通話を切り替えない）、その接続先と接続中で名前と「会話中」（`waveform`をsuccessで着色、タップで通話を開く）、接続先が削除されたら「接続先を設定し直してください」を示す。状態はAppが公開する宛先と現在通話の投影（`CallControlState`）から決め、Controlから切断しない（コントロールセンターはロック中も開けるため）。systemMediumはこの単位に含めない。

## 操作の所有者

Widget extensionは通話やアカウントのモデルを生成しない。選択通話Widgetの操作には`BackgroundCallControlIntent`を使い、`.background`と`allowedExecutionTargets = .main`でApp本体へ実行を渡す。端末解除を要求するIntentではなく`.alwaysAllowed`を指定するが、AppのAppleログイン・保存関係・利用条件は免除しない。Control・Live Activityの既存操作には前面実行と端末認証を要求する`OpenCallControlIntent`を維持する。Appが登録した`CallSurfaceActions`は同じ`AppCallOwner`であり、保存先・ログイン・共通の利用権条件を実行時に再確認する。OS経由の受入は[未確認事項](../../validation/未確認事項.md)で管理する。

| 入口 | 現行動作 | 対象の境界 |
|---|---|---|
| 特定通話先Widget | Widgetの編集で保存ユーザー／通常groupを選び、Start callでAppの共通開始操作を実行 | 現在の選択用投影を読み直し、削除・破損・未選択ならAppの通話画面へ戻る。古いconfiguration内の名前や対象をfallbackとして使わない |
| 特定通話先Widgetの通話中操作 | Widget編集で選んだ保存ユーザー／通常groupの終了・ミュートを表示する | 現在通話の宛先IDが設定先IDと一致し、現在の投影にも設定先がある場合だけ終了・ミュートを表示する。別通話・未設定・削除・別ログインでは表示しない |
| iOS Control | 宛先Control（設定した接続先へ接続、接続中は通話を開く）／直近再開の独立したボタン | 同じ共有IntentとApp所有者を使用。切断は置かない |
| Live Activityの操作 | ロック画面・展開Islandに切断を置かず、タップで通話（iPhoneはシート）を開く | 既存の終了Intent/APIはWidget等の他入口のために維持する |
| Live Activity本体 | `rideintercom://call`で通話を表示 | URLだけでは開始・終了しない |

WidgetはiOS/macOS、ControlとLive ActivityはiOS targetに含む。すべての製品targetの最低OSは27.0。選択Widgetは、投影された現在通話の宛先IDが設定先と一致するときだけ終了・明示ミュート／解除を表示する。開始は設定先をAppで再解決し、進行中の別通話を切り替えない。終了・ミュートは表示した`CallSurfaceReference`を照合し、古い表示では実行しない。ミュートは反転操作ではなく明示Boolであり、重複して届いても反転しない。

### CarPlayのボタン操作

| 条件 | 現行の扱い |
|---|---|
| 27.0以降・タッチ対応CarPlay | 小型Widgetの開始・終了・ミュート／解除を背景Intentへ渡す。対応OS共通の経路を使う |
| 表示幅と読み上げ | 各操作を44pt以上とし、ミュートは記号と短い語（caption・semibold、収まらなければ縮める）を横に並べたカプセルにする。ミュートと切断の間は12pt離す（[デザインシステム](../../design/デザインシステム.md#端末ごとの補足)の下限で、ミュートの語の幅を優先する）。ミュートはネイティブToggle（`.button`）の同一`mic.slash`記号とMute／Mutedの状態文で、ミュート中だけdangerの塗りに白い文字、解除中は中立の`.fill.tertiary`のカプセルとする。切断はdestructiveのButtonで、赤い記号を中立の塗りに置き、縁をdanger 45%の細線にする（ミュートがあるときは44ptの円、接続中・Watch所有中は文字付きのカプセル）。ミュート中の赤い塗りと並べても見分けられる。大きさと塗りを見本どおりに固定するため、どちらも`.plain`のボタンに標準の形（`Capsule`）の背景を付ける。見本のガラスは画面外の描画（試験の画像）に出ないため、中立の塗りで代える。読み上げ名・ミュート値と宛先の一致を保持する |
| 未設定・削除済み | Choose a callはHome画面・Mac向けの前面導線。専用CarPlay Appのない車載で機能する背景操作とは扱わない。CarPlayでの利用前にiPhoneのWidget編集で保存先を選ぶ |
| 非タッチCarPlay | WidgetのButton／Toggle操作はOS非対応。表示できることを操作可能とは扱わない |
| CallKit・専用CarPlay App | 採用しない。電話型の発着信UI・VoIP Push・communication entitlementを追加せず、既存インカムを操作する |
| マイクと実行時間 | `.main`は実行先の指定であり、背景マイク開始や接続成立までの実行時間を付与するAPIではない。新規開始、停止後の解除、cold launchは実車／実機の別受入。失敗時に電話型の経路へ切り替えない |

[AppleのCarPlay Widget条件](https://developer.apple.com/documentation/widgetkit/adding-standby-and-carplay-support-to-your-widget)と[App Intentの実行先](https://developer.apple.com/documentation/appintents/intentexecutiontargets/main)を適用する。Live ActivityのCarPlay表示は非対話であり、Widgetボタンの代替にしない。

### 画面を開かないアカウント確認

Apple credential失効通知の購読と、ログイン世代変更時のVM停止・置換は`AppCallOwner`が所有する。ContentViewの生成を前提にしない。背景での開始・ミュート解除前に保存状態の再読込とApple credential確認を行い、await前後で本人・access ID・同じVMと通話参照が一致することを確認する。確認待ちの間に終話・切替があれば古い開始要求を拒否する。終了・ミュートは外部のcredential確認を待たず、既存の現在ログインと通話参照の検査から共通停止操作へ渡す。サインアウト・削除・別ログインへ遅れた旧操作を渡さない。Appleの確認通信が失敗した場合の、以前成立したログインをオフラインで使える方針は維持する。

iOSの通話用Keychain資格は初回解除後に利用できる`AfterFirstUnlockThisDeviceOnly`とし、既存itemは読込成功時に属性だけを揃える。MacのKeychain保護は変更しない。group manifest・lock・Widget投影は初回解除後のファイル保護を使う。初回解除前や読込不可は失敗として戻し、鍵の再生成・空データへの置換で回復した扱いにしない。

## 通話状態の投影

| 項目 | 現行仕様 |
|---|---|
| 初期値と保存 | `liveActivityEnabled=false`。アカウント別UserDefaultsの`RideIntercom.settings.liveActivityEnabled`へ保存し、音声設定保存・Reset All Settingsでは維持する。アカウントデータ消去では消す |
| 表示内容 | 現在通話中のgroupに対する共通`callStatus(for:)`とミュート値だけ。閲覧中の別groupの状態へ切り替えず、本人・相手・groupの名前を出さない |
| 開始 | 設定ONかつApp前面で有効な通話投影がある場合、ActivityKitへ要求する。背景では新規要求しない |
| 更新 | 同じ投影の再送を抑止。状態変更時は背景でも更新し、Appの通話状態を正とする |
| 停止 | OFF、サインアウト、対象通話消失で表示を終了。表示側から媒体処理を停止しない |
| OSによる終了 | 利用者による消去・OSの終了（Live Activityの8時間上限を含む）では同じ通話の表示を自動再生成しない。次の通話または明示OFF→ONで再試行する |
| 失敗・再起動 | 表示要求失敗はSettingsで案内し、通話を継続。次回プロセスは前回の表示を先に終了し、それを通話復旧の証拠にしない |
| 非表示の意味 | OFFはAppが追加するLive Activityだけを対象とし、OSのマイク利用表示などを隠さない |

Appの`CallLiveActivityPresenter`が表示更新を直列化する。延滞した旧開始が完了しても、旧表示を終了してから次の通話へ更新する。`CallSurfaceReference`は対象照合のUUIDだけで、Apple識別子・秘密鍵・group鍵・通知資格を含めない。

Appleの[Widget操作](https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities)、[Control](https://developer.apple.com/documentation/widgetkit/creating-controls-to-perform-actions-across-the-system)、[Live Activity](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities)の契約を適用する。

## 特定通話先の選択用共有

| 境界 | 現行仕様 |
|---|---|
| App Group | `group.com.yowamushi-inc.RideIntercom.CallWidgets`をAppとWidgetのentitlementへ指定。`containerURL(forSecurityApplicationGroupIdentifier:)`配下の`call-destinations.json`を使用。実profile・Developer portalの登録は[受入条件](../../validation/未確認事項.md)で別管理 |
| 書込所有者 | Appの`WidgetDestinationPublisher`だけ。ログイン中の既存`callTargets`から保存ユーザー／通常group、現在通話の宛先・状態を投影し、atomic write。iOSではUntilFirstUserAuthenticationのファイル保護を指定する。extension targetにはwriter実装を含めない |
| 共有する内容 | schema version、宛先ID・表示名・user/group種別、現在通話の宛先ID・参照・状態・ミュート値。既存宛先IDの端末本人識別子でアカウント境界を保つ。現在通話に名前を付けず、Appleの生識別子、署名鍵、group鍵、購入状態、通知capabilityを共有しない |
| group内だけの参加者 | Usersへ登録せず、Widget候補にも出さない。通常group自体は候補に含める |
| 候補と表示 | `WidgetConfigurationIntent`と`EntityStringQuery`で現在投影を読む。描画時もIDを再解決し、名前更新に追従。選択済み宛先名は`privacySensitive()`を付ける |
| 失効 | サインアウト、モデル変更、ユーザー／group削除で投影を更新し、宛先と通話操作の両timelineのreloadを要求する。OSの既存snapshotが即時消えるとは保証しない |
| 実行時 | App所有者が現在のログイン・宛先一覧でIDを再解決し、`startCall(...allowSwitchingCall:false)`へ渡す。共有JSONや過去のWidget表示を認可の根拠にしない |
| 読込失敗 | 共有container不在、ファイル破損、未知version、重複ID、1MiB超は空一覧。端末内の正本を削除せず、Appへ戻る操作を残す |
| 書込失敗・復旧 | 過去投影の削除を試み、次の前面復帰／一覧変更で再公開する。成功済みと同じ投影でもファイルが破損・欠落していれば修復し、一覧・直近・現在状態とファイルが同じならreloadしない。通話を停止しない |

Appleの[設定可能なWidget](https://developer.apple.com/documentation/widgetkit/making-a-configurable-widget)と[App Group設定](https://developer.apple.com/documentation/xcode/configuring-app-groups)を使用する。OS27専用のquery実行先指定には依存しない。

## iPadとMacへの表示

iOS AppとWidgetの対応familyはiPhone・iPad。iPadでは対応するロック画面など、OSが提供する場所へ表示し、Dynamic Islandの有無で通話動作を変えない。Widgetはnative macOS targetにも含む。

27.2 SDKのActivityKitはmacOSからのActivity開始をunavailableとする。iPhoneで開始したLive Activityは、[Appleの共有条件](https://support.apple.com/en-ca/120684)を満たすMacのメニューバーへOSが表示する。この表示が表すのはiPhone側の通話であり、Macアプリの通話状態ではない。Mac自身の状態表示には、同じApp所有者に接続した標準`MenuBarExtra`を使用する。これはplatform APIの差であり、OS最低版を分ける理由にはしない。

## Macメニューバー

| 境界 | 現行仕様 |
|---|---|
| 設定 | `menuBarEnabled=false`。アカウント別UserDefaultsの`RideIntercom.settings.menuBarEnabled`へ保存。Settingsの共通Call status display sectionにMac用の1スイッチを表示し、音声設定リセットでは保持、アカウントデータ消去では消す |
| 表示 | ログイン中かつ設定ONの間、標準`MenuBarExtra`のmenu styleで表示。アイコンはAppのカスタムシンボル`ridecom.glyph`を`.hierarchical`で描き（吹き出しの層が半透明になり下の道が見える）、ミュート中だけ`mic.slash`（label「RideCom」）。通話がない場合もAppへ戻れる。氏名・group名・資格は出さない |
| 状態 | `AppCallOwner.currentLivePresentation`から現在の通話の`callStatus(for:)`とmuteを取得する。つながっていない状態（`ready`）は通話がないときと同じ「通話していません」で、ミュート・切断を出さない。接続待ち・成立済み・音声停止を同じ状態で区別し、閲覧中の別groupへ追従しない |
| ミュート | メニューに表示した通話参照と明示Boolを共通`setCallMuted`へ渡す。重複操作で反転せず、古いログイン／接続の操作は拒否 |
| 終話 | 表示した`CallSurfaceReference`を既存の共通終了操作へ渡す。古いメニューの操作で、新しい通話を終了しない |
| Appへ戻る | Open RideComで既存のmain WindowGroupと通話を表示。別のVM・通話セッションを生成しない |
| OFF・サインアウト | 表示を外すだけ。OFFで通話を終了しない。サインアウト時の通話終了は既存のアカウントlifecycleが所有する |
| 更新 | SwiftUIの既存Observationで現在状態を読む。ネットワーク照会、周期timer、別の通話状態保存は追加しない |

Appleの[MenuBarExtra](https://developer.apple.com/documentation/swiftui/menubarextra)と[Menus HIG](https://developer.apple.com/design/human-interface-guidelines/menus)を使用する。ActivityKitをMacで起動せず、iPhoneから共有されたLive Activityとは別にMac自身の通話を示す。iPhoneのLive Activityが対応Macのメニューバーへ共有されること（[Live Activities HIG](https://developer.apple.com/design/human-interface-guidelines/live-activities)、[Macへの共有条件](https://support.apple.com/en-ca/120684)）は、Mac自身の通話を表示する仕組みや最低OSを引き上げる理由として扱わない。通常のDock／main windowを維持し、メニューだけのアプリには変えない。OSの実メニュー操作とVoiceOverの受入は[未確認事項](../../validation/未確認事項.md)へ分ける。

## 検証構成の隔離

システム表示は生成Infoの`StorageNamespace`が通常版の`RideIntercom`と完全一致する場合だけ許可する。欠落・未展開・検証用保存先はApp Groupの解決前に拒否し、Widgetの読取・書込・reload、Live Activityの開始・更新・終了一覧へのアクセスを行わない。Debugのcompile条件に限定せずRelease構成の音声E2Eにも同じ判定を適用する。Watch連携とOS通知も共通の判定に従う。
