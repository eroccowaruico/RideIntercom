実装する必要がある残作業。現在の動作は[仕様](../spec/アーキテクチャ.md)、実装後の確認待ちは[未確認事項](../validation/未確認事項.md)を参照する。

| 課題 | 現状との差・対象 | 完了条件・制約 |
|---|---|---|
| 公開identity・端末資格管理 | Workerの個別端末registryは招待制試用向け（約4.5KiBまで）。公開登録・自動発行・失効を行うidentity backendがない | SFU transportとgroup招待形式を維持して入口認証を拡張する。本人確認・資格発行・失効を公開運用できること。追加する認証・ユーザー管理の方針は[Appleでのログインと通知先の識別](#appleでのログインと通知先の識別)を参照 |
| 公開時のabuse・請求監視・停止運用 | SDP制限と参加者秒予約だけでは改変クライアントの過剰送信を金額で遮断できない | edge rate limit、実egress計測、請求通知、障害時停止運用を整備する。実運用の効果は検証側で確認する |

RTC診断とTURN資格lifecycleはこの一覧の実装作業ではない。現在の契約は[RTC](../spec/packages/RTC.md)・[Worker](../spec/server/Worker.md)、実サービス受け入れは検証側が所有する。

音声の連続性の実装修復と28測定の結果は[修復記録](../validation/history/音声の連続性修復.md)へ移した。物理iPhone同士の最終確認は検証側で管理する。

### グループ作成権と24時間の発信条件

| 課題 | 目的・範囲 | 完了条件・確認点 |
|---|---|---|
| グループ作成を購入者に限定する | 購入した人だけがグループを作成できるようにする。お試し・無料チケット・TestFlight・内部テストの例外も扱えるようにする | 作成者の有効な利用権を確認する。購入以外の権利で同等の操作を許可する範囲を整理し、画面以外の入口でも同じ条件で判定する |
| 購入者の確認または発信を24時間の発信条件にする | グループ内ユーザーは、24時間以内に購入者の確認または発信がない場合、そのグループで発信できないようにする | グループに関係する購入者の確認・発信と時刻を扱い、発信時に条件を確認する。「確認」が何を指すか、確認主体、対象となる購入者、期限の起算点と更新条件を着手前に確定する。複数購入者、購入者の離脱・利用権失効、購入以外の権利を持つ人の扱いも決める |

### 依存関係と取り組む順序

以下は既存の追加要望と認証・課金を合わせた依存順であり、実装開始や販売開始を決定するものではない。全体点検を踏まえ、権利・24時間条件の意味の決定と、通知・Watch等の成立性調査を実装より前へ置く。各段階の判断事項は[実装前整理](機能拡張の実装前整理.md)を参照する。

| 取り組む対象 | 先に整理すること | 後続へ渡すもの・並行できること |
|---|---|---|
| 要望の意味とデータ保持の決定 | 購入者と同等権利の範囲、発信・確認・24時間・1対1への適用、保存しない個人情報、Local・オフラインの扱い | 権利と操作の判定表、データ保持表。これを課金・認証の実装に先行させる |
| OSと端末機能の成立性調査 | 希望する通知・応答体験、CarPlayでの操作、iPhone依存のWatch音声、対象OS | 資料確認と、後に必要となる実機検証条件。要望の整理と並行し、成立しない前提を画面完成後まで持ち越さない。今回は調査・文書整理まで |
| ユーザー・グループ・通話の共通設計 | 権利・発信の意味、保存範囲、既存のID・グループ・鍵 | 共通ユーザーID、所属・作成者・購入者の関係、1対1の内部グループ、呼び出し・応答・接続・再接続・終了の状態。移行と削除もここで設計する |
| Appleログインとユーザー・グループ管理 | 共通設計、既存データの扱い、認証取消・アカウント削除 | ユーザー一覧、グループ所属、既存ユーザーの再利用。通知宛先の管理と利用権の基盤は、この識別の基盤を共有して並行できる |
| 利用権と課金・テスト連携 | 共通ユーザーIDと操作判定表、有料・試用・無料配布・TestFlightの権利の範囲 | 1週間チケット・月額課金の検証・復元・失効と権利反映、内部テストの迂回、迂回なしでの確認。価格の確定と販売開始は別に判断する |

| グループ作成・発信・終了の共通操作 | 利用権、24時間条件、1対1の条件、通知と通話の状態 | 全入口が使う操作と実行時の可否判定。失効・再確認・オフライン・同時操作を含め、一般向け画面や外部操作の個別実装より先に揃える |
| 一般ユーザー向け画面と言語 | 共通操作、通知・購入・復旧の状態 | 個別発信とグループ通話を分けた英語画面。翻訳対象の切出しは初めから行い、一般向けの画面・通知・外部操作の日本語を揃える。画面案・文言の検討は先行できる |
| ショートカット・Siriとウィジェット・上部表示 | 共通の通話先指定・開始・終了、利用権判定、直近相手・古い操作対象の扱い | 特定・直近のユーザー／グループを扱う外部操作。上部の状態表示とON/OFF設定は共通の通話状態を用い、操作の実装と並行できる |

低ビットレートの品質切り分けと、グループ内の音声設定統一による電池消費の比較は、この認証・課金の依存関係とは並行して検討できる。設定統一を採用する場合は、グループ管理との接続を設計する。

各段階でpackageの変更が必要なら、package単独の変更・検証とApp追従を別工程にする。既存のiOS・macOS支援、経路間の操作の意味、音声の連続性を共通の確認対象とする。
