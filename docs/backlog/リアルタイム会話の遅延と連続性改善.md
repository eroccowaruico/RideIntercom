# リアルタイム会話の遅延と連続性改善

## 指示と目的

バイク・スキーのインカムで滑らかな会話を成立させる。低遅延の通信条件では口から耳まで約125 msを快適性の上限とし、アプリ内部で固定待機を積み増さない。既存の音声同一性判定を緩めず、1%未満でも発生する欠落・重複・境界のポップノイズを検出して減らす。修正と自動テストをコミットする。

## 対象

- 入力、音声処理、符号化、送受信、復号、混合、出力と、それぞれの接続における待機時間を測る。
- 小さい通信遅延では早く再生し、揺れがある場合は必要な分だけ吸収する。各相手の時計・経路を独立して扱う。
- 8人、複数経路、異なる遅延・コーデック・ビットレートの組合せを検証する。
- AACは代替PCMの成功で済ませず、実際のAAC符号化・復号・出力を確認する。
- 1〜3秒の無音、短い「うん」「ふん」、同時発話、無音後の再開を含む会話を検証する。
- 設定切替で避けられない不連続は対象・無音時間を明示し、古い音を遅れて再生しない。それ以外の設定は待機を加えず適用する。
- 音声にはTCP相当の信頼性あり配送・再送・reliableコピーを使わない。制御のみ別契約とし、低遅延の即時配送で修復する。
- 欠落・重複・時間ずれ・クリックを意図的に加えた負例が失敗することも検証する。
- 実装はpackageとAppの責務を保ち、置換した経路を削除する。packageを検証してからAppを変更する。

## 現状と検証の境界

開始時点では入力とミキサーのtapが約100 ms単位にまとまり、送信100 ms・受信200 msの待機を要する。従来の全文照合は音声の連続性を検査するが絶対遅延と微小なクリックを保証しない。AAC ELD v2のモノラル条件ではOS変換が失敗してPCM16へ代替される。

自動化では実AVAudioEngine・実コーデック・Simulator・通信経路の出力と入力時刻を保存する。物理iPhone同士、Bluetooth、無線環境の口から耳の遅延は別途実機測定が必要であり、自動検証だけで達成扱いにしない。
