**主分類:** 機能（OS・データ移行）。

**状態:** 最低対応OSの統一と下位OS専用分岐の除去は完了し、現行の契約・設定はrequirements／policies／target仕様が正本。必須アップデートの判定・案内・制限・復旧と、個別データ／通信契約の移行は未決・未実装。

## 指示と範囲

2026-11-01の追加指示。下位OSだけの互換経路を持たず、今後のデータ等のマイグレーションと必要な更新案内を用意する。2026-11-02の追加指示により、現行の最低対応OSを全製品target・Swift Packageで27.0へ統一し、27.0未満だけのavailability分岐とWidget fallbackを除去した。現在の正本は[製品要求](../requirements/製品要求.md#共通の品質方針)、[開発方針](../policies/開発方針.md#技術選定方針)、各platform仕様とする。過去の26.4を前提とした検証は当時の履歴として保持し、現行対応OSの根拠にはしない。

利用者の回答により、強制アップデート機能の実装は行わず、方式・判定・案内・復旧を本書に未確定課題として残す。データ・設定・通信契約の移行も、対象変更時に必要範囲を設計・実装・検証する。旧OS対応の削除を理由に既存データや認証情報を無条件に消去しない。

## 必須アップデートを促す仕組み

| 課題 | 求める動作 | 実装時に決めること・受入条件 |
|---|---|---|
| 必須更新の判定 | インストール済みのアプリが更新必須かを判定できるようにする | 最低利用可能版をどこで管理・取得するか、OS／配布環境別の対象、公開バージョンとビルド番号のどちらを何のために比較するかを決める。通常の更新案内と必須更新を区別し、桁数や文字列順の違いで誤判定しない |
| 更新の案内 | 必須更新の理由が分かり、正規の更新先へ進める | 更新が必要なことと更新先への操作を一般向け画面で示す。iOS／macOS等の配布先に合う導線を決め、更新・再起動後に再判定する。 |
| 必須更新時の操作制限 | 古い版を使い続けることで起きる問題を避ける | 開始・再開・参加・既存通話の継続のどこへ制限を適用するかを決める。更新前後のデータ・資格・購入の復元を保ち、互換不要を理由に無条件のデータ消去を行わない |
| 更新できない場合の復旧 | 更新案内から戻れず、利用も復旧もできない状態を避ける | 圏外・判定情報の取得失敗・更新先への接続失敗・対応OSへ更新できない場合の表示、再試行、利用可能範囲を決める。近距離の圏外利用要求との整合を確認する。判定不能を「更新不要」と確定した扱いにしない |
| 移行・配布との整合 | 更新必須を出す時点で、対象者が更新できる | 移行が必要な版との対応、更新版の配布確認、最低版の切替タイミング、誤設定時の復旧を決める。判定と案内のローカル検証、実際のストア／配布環境の受入を分ける |

必要最低限の仕組みとし、独自の版管理サーバーや常時ポーリングを先に前提としない。具体的な管理・取得方式と利用制限は未確定であり、実装着手時に選定する。
