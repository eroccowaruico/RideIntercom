# 対応OSと移行・必須アップデート

## 指示と範囲

2026-11-01の追加指示。OS差分がある機能は原則バージョン27以降のみ対応し、現在の後方互換機能はすべて不要とする。一方、今後はマイグレーションが発生することを前提とし、必要な更新を利用者へ促す仕組みを用意する。

利用者の回答により、今回はバックログへの追加までとし、強制アップデート機能の実装は行わない。対応OS・互換性・移行の開発方針は[開発方針](../policies/開発方針.md#技術選定方針)を正本とする。現行の最低対応OS、保存・通信処理、更新画面を変更済みとは扱わない。

## OS差分と互換処理の整理

| 課題 | 方針・背景 | 完了条件 |
|---|---|---|
| OS差分がある機能の対応範囲 | 原則として対象のApple OSのバージョン27以降のみを対象とする | 機能ごとの使用APIと対象OSを棚卸しし、下位OSのためだけの代替実装・availability分岐を整理する。OSバージョン差の互換分岐と、iOS・macOS等のプラットフォーム固有処理を混同しない |
| 現時点の後方互換機能をなくす | 現在は後方互換機能がすべて不要。旧版維持のための複雑さを持たせない | 旧OS・旧アプリ版・旧API・旧保存形式のためだけの互換層・旧経路を棚卸しして整理する。削除対象と現在必要な処理を区別し、現在の正常な保存・破損時復旧・認証を壊さない |
| 将来のマイグレーションを前提にする | 今は互換処理を持たせなくても、公開後の版更新では移行が発生する | データ・設定・通信契約等を変更するときに、移行対象・適用条件・失敗時の復旧と更新手順を定める。未来の全形式を先回りして実装せず、必要な移行を変更と同時に設計・検証する |

## 必須アップデートを促す仕組み

| 課題 | 求める動作 | 実装時に決めること・受入条件 |
|---|---|---|
| 必須更新の判定 | インストール済みのアプリが更新必須かを判定できるようにする | 最低利用可能版をどこで管理・取得するか、OS／配布環境別の対象、公開バージョンとビルド番号のどちらを何のために比較するかを決める。通常の更新案内と必須更新を区別し、桁数や文字列順の違いで誤判定しない |
| 更新の案内 | 必須更新の理由が分かり、正規の更新先へ進める | 更新が必要なことと更新先への操作を一般向け画面で示す。iOS／macOS等の配布先に合う導線を決め、更新・再起動後に再判定する。 |
| 必須更新時の操作制限 | 古い版を使い続けることで起きる問題を避ける | 開始・再開・参加・既存通話の継続のどこへ制限を適用するかを決める。更新前後のデータ・資格・購入の復元を保ち、互換不要を理由に無条件のデータ消去を行わない |
| 更新できない場合の復旧 | 更新案内から戻れず、利用も復旧もできない状態を避ける | 圏外・判定情報の取得失敗・更新先への接続失敗・対応OSへ更新できない場合の表示、再試行、利用可能範囲を決める。近距離の圏外利用要求との整合を確認する。判定不能を「更新不要」と確定した扱いにしない |
| 移行・配布との整合 | 更新必須を出す時点で、対象者が更新できる | 移行が必要な版との対応、更新版の配布確認、最低版の切替タイミング、誤設定時の復旧を決める。判定と案内のローカル検証、実際のストア／配布環境の受入を分ける |

必要最低限の仕組みとし、独自の版管理サーバーや常時ポーリングを先に前提としない。具体的な管理・取得方式と利用制限は未確定であり、実装着手時に選定する。
