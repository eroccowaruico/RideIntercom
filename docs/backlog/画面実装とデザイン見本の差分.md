# 画面実装とデザイン見本の差分

## 指示と背景

2026-11-06の利用者指示「細かい違いもバックログに親子関係を維持して追加」「他の画面も実装とHTMLの差を総点検」「しっかり差分を洗い出さないとHTML通りの実装にならない。監督するのもデザイナーの責務」により、実装の画面とHTML見本の差を画面ごとに洗い出した。

**主分類:** デザイン（実装へ渡す差分）。**関連分類:** 機能・改善。**状態:** 差分を記録。実装未着手。

本書の構造は「画面（親）→ 画面の部分（子）→ 個々の差（表の行）」とする。1つの差は1行にし、同じ差を別の場所に重ねて書かない。複数の画面にまたがる差は[全画面に共通](#全画面に共通)に置き、各画面からは参照だけにする。別の課題で追っている機能（通知、招待の同期、削除の同期、グループタブの表示設定、ウインドウの大きさ）は、その課題を正本とし、本書には画面に現れる差だけを置いて参照を付ける。

### 進め方

優先度は、取り消せない操作の安全（高）、画面の印象と状態の読み取りを大きく変えるもの（高）、部分的な見た目と文言（中）、まれな画面と細部（低）の順とする。各行は、該当画面を実画面（iPhone・iPad・Mac、文字サイズ標準とAX5、ライトとダーク）で見本と並べて確認して閉じる。見本との差が残る場合はその理由を行に追記し、デザインの判断が必要ならデザインの正本を先に直す。実装と同じ変更で[Call](../spec/App/UI/Call.md)・[Settings](../spec/App/UI/Settings.md)・[Diagnostics](../spec/App/UI/Diagnostics.md)の仕様を更新する。閉じた行は優先の列を「済」にし、実装の列に対応日と内容を書く。
