# 利用権とデータ保持の設計

## 指示と背景

2026-10-30の「やることリストの上から順に進めて」に従い、[依存関係と取り組む順序](未実装課題.md#依存関係と取り組む順序)の先頭から、利用権・発信条件・データ保持を具体化する。本書は実装前の設計であり、課金・利用権による発信制限の実装完了を示さない。端末のAppleログインは[現行契約](../spec/App/通信仕様.md#appleログインと端末内データ)を参照。

利用者の意図は、基本的には購入者がグループを作り、最初の会話に参加することを期待しつつ、使い方を厳しく縛らないことである。グループ内で半数程度に購入してほしいという期待はあるが、人数・割合の強制条件にはしない。24時間は購入者が毎回そろわなくても再開できる猶予として扱う。

追加の回答により、通信断からの復帰も同じ再開条件を使う。24時間以内は自動再開し、超過後は購入者相当がいる状態で再開する。通信断がなく継続している通話を24時間で切らない。完全終話の分散合意、購入証明の端末間検証、独自の購入検証サーバーを追加しない。認証・通信保護・既存のサービス利用枠は維持する。

## 回答で確定した条件

| 対象 | 決定と理由 |
|---|---|
| お試し | 月額サブスクリプションの標準の無料トライアルを使い、StoreKitの購読状態として扱う。有効中はグループ作成・グループへの招待／追加・「購入者ありの開始」で購入者と同等とする |
| 無料チケット | 購入と独立して配布する権利。有効中の操作は購入者と同等とし、実際の購入記録とは区別する |
| グループへの招待・追加 | 操作する本人に購入者相当の権利を必要とする。追加される全員への購入強制ではない。有効な試用・無料チケット・TestFlightも同等とする。24時間の再開猶予だけでは追加権限を与えない |
| ユーザー保存と削除 | 直接招待した・された相手を自動保存し、後から一覧で削除できる。同じグループにいるだけの相手をユーザー一覧へ自動登録しない。削除後も既存グループと通話は維持する。直接招待関係のない参加者のID・表示名はグループ内に残すが、グループ外の個別呼出し・通知・別グループへの追加の対象にはしない |
| TestFlight | 購入操作なしで購入者相当。実購入・試用・無料チケットと区別する。配布環境の判別方法は課金・テスト連携で確認する |
| 1週間チケット | 購入日時から連続7日間。復元時も購入日時から確認しやすいことが理由。復元日時や初回使用日時から7日を与え直さない |
| 期限切れ・返金・購入者の離脱 | 成立済みの通話と残り24時間は維持する。無効な権利で新しいグループを作成したり起算点を更新したりはできない。離脱だけなら本人の利用権自体は失効しない |
| 1対1 | グループと同じ条件。初回は少なくとも片方に有効な権利を必要とする。未購入者から購入者への呼出しを認め、応答・接続後に開始する。同じ二人の内部グループを再利用し、24時間以内なら両者が未購入でも再開できる |
| 開始成立と起算点 | 有効な権利を持つ人を含む参加者同士の認証と通話接続が成立した時点。呼出し・無応答・失敗では更新しない。継続中の購入者の途中参加でも更新しない |
| 会話相手がいなくなる場合 | 終了扱いにする。1人だけの待受で通話を永続的に継続させない。一時切断を特別に追跡する仕組みは加えず、復帰時にも同じ24時間条件を使う |
| 購入者の割合 | 半数程度の購入を期待するが、割合・人数のチェックや強制停止は実装しない |
| 保存しない情報 | メールアドレス・本名を保持しない。ハンドルネームは本人が選ぶ表示情報として扱い、本名を要求しない |
| サーバー保存の範囲 | ログインとID宛て通知に必要な最小限の識別子・端末資格・通知先の保存を認める。表示名・ユーザー一覧・グループ情報・購入状態は端末側を中心に保持する。既存の通話用サーバー状態は別途棚卸しする |

当初は「一時的な通信切断を完全終話から除く」という回答を得たが、その後、複雑な仕組みを避けるため「通信断からの復帰も24時間以内は自動再開、超過後は購入者ありで再開」と具体化された。前の回答を根拠に、超過後の無条件再接続や分散した終話判定を追加しない。

## 開始・再開の共通判定

「購入者相当」は、実購入に加えて有効な試用・無料チケット・TestFlightを含む。判定は各画面・通知・Siri・Watch等へ複製せず、共通の開始処理に置く。

| 状態・操作 | 可否と開始日時の扱い |
|---|---|
| グループを作成 | 作成に用いる有効な利用権が必要。購入者相当でない人は購入・復元・参加依頼へ進める |
| グループへ招待・追加 | 操作者本人に有効な購入者相当の権利が必要。作成後のメンバー追加・招待URLの発行／共有を同じ境界で判定する。既に受けた招待への参加とは分ける |
| 購入者相当を含めて新しく開始・再開 | 認証と通話接続の成立後に、新しい「最後の購入者ありの開始日時」を保存・共有 |
| 購入者相当なしで開始・再開、保存した開始日時から24時間以内 | 許可。開始日時は更新しない。ちょうど24時間も許可する |
| 購入者相当なしで開始・再開、24時間を超過 | 不許可。購入者相当への呼出し・参加依頼、購入、復元の導線を残す |
| 起算点がない状態から購入者相当なしで開始 | 不許可。現在時刻を起算点として新しい猶予を与えない |
| 通信断からの復帰 | 同じ判定を使い、24時間以内なら自動再開。超過後は購入者相当がいれば再開できる。失敗・再試行のたびに起算点を更新しない |
| 通信断なく通話を継続して24時間を経過 | 継続。24時間のタイマーで切断しない |
| 通話中に購入者相当が途中参加 | 参加できるが起算点は更新しない |
| 購入者の期限切れ・返金・離脱 | 成立済み通話と保存した起算点を維持。別の参加者同士が話している限り継続できる。会話相手がいなくなれば終了扱い |
| 無音・ミュート・画面移動・音声機器の一時停止 | それだけで新規開始の判定をしない。接続と音声状態の区別を維持 |
| 未購入者から購入者への1対1の呼出し | 呼出し可能。初回は相手の応答と有効な権利を確認し、共通処理で内部グループを用意して開始 |
| 同じ二人の1対1の再開 | 同じ内部グループと開始日時を再利用。未購入者同士でも24時間以内なら許可 |
| 自分の終了・退出 | 自分の参加を終了。残った参加者間の会話を切らない。残りが1人なら終了扱い |

経路が一つ切れても別の経路で通話が続いているなら、再開ではなく継続である。購入者相当の確認・通知だけのために利用枠・所属・認証を免除しない。終了操作は利用権の有無で妨げない。

## 後続へ渡す最小構成

| 所有するもの | 実装の方針 |
|---|---|
| 自分の利用権 | 無料トライアルを含むStoreKitの検証済み利用権、独自の無料券、TestFlightを出所・期限とともに端末で保持。任意の購入済みフラグを正本にしない |
| 相手の購入者相当状態 | 既存の認証済み制御通信で必要な状態を交換する。相手の取引全体を送信して再検証する仕組みを加えない。正規アプリ同士の協調を前提にし、改変クライアントへの厳密な課金強制とは区別する |
| グループの開始日時 | グループごとに最新の購入者ありの開始日時を端末で保存し、既存の制御通信で共有する。通話履歴サーバーや合意protocolは作らない。重複通知は同じ値として扱い、古い日時で新しい保存値を上書きしない |
| ユーザーと端末 | 安定したアプリ内ユーザーIDと端末のmember IDを区別する。Appleログインで同一ユーザーへ対応付ける。表示名一致で別人を統合しない |
| ユーザー一覧とグループ | 直接招待関係のある相手だけをグループから独立して端末へ自動保存し、保存した相手は安定したIDで参照する。グループ削除でユーザーを削除しない。ユーザー一覧からの明示削除はグループ・通話を維持する。両系統の画面は同じ一覧を使う |
| 1対1の通話先 | 画面はユーザーを指定し、共通処理が同じ二人の内部グループを解決する。一般向け画面で内部グループを選ばせない |
| 通話の状態 | 呼出し・接続準備・通話中・再開待ち・終了を区別する。現在の接続と参加者の情報を使い、全端末の完全終話を確定する別の仕組みは設けない |
| 同一ユーザーの複数端末 | 複数端末へのログインとWebRTC接続を区別し、WebRTCはグループをまたいでもユーザー単位で原則1端末にする。障害回避・復旧のため一時的に2端末になることには検討余地を残す。通常の複数接続は認めず、例外の条件・上限時間・どちらの接続を残すかは実装時に具体化する。Localだけの接続へ同じ制限を追加する要求ではない。相手の人数と接続端末数を区別し、自分の端末だけが複数残った状態を「会話相手あり」にしない。現在のRTC同時接続枠を黙って増やさない |
| 共通操作と画面IF | 開始・終了・対象指定・明示的なマイク状態設定を既存のlifecycleへ接続。一般向け・既存画面・Diagで通話処理や判定を二重化しない |
| ログイン必須範囲 | すべての通話でAppleログイン必須。新規開発のため既存ユーザーへの移行処理は行わない |
| Local・オフライン | 保存済みの資格・権利・開始日時を使い、毎回のログイン、購入復元、サーバー応答を要求しない。通信できないだけで購入取消にしない |
| 保存失敗・判定不能 | 読めない保存を空に変えず、期限切れと取得失敗を区別する。欠落・不正な日時から新しい24時間を与えない。端末時刻を使う通常の判定を基本とし、不正時計への厳密な耐性のために常時サーバー照会を追加しない |

商品の意味は本書で確定した条件を使う。通信・音声・OS差分は既存packageの責務を維持し、RideIntercomの購入条件をRTCやCodecへ混ぜない。package変更が必要な部分は単独検証とApp追従を別工程にする。次工程ではこの構成を既存の保存・認証・接続処理へ具体的に割り当てる。

## 期間と復元

| 対象 | 期間と更新の扱い |
|---|---|
| 1週間チケット | 購入日時から604,800秒。購入日時以上・期限未満を有効とする。タイムゾーンや復元日時で期間を変えない |
| 月額 | StoreKitの検証済み期限と購読状態を使い、固定30日で算出しない。更新失敗・猶予の扱いは課金連携で具体化 |
| お試し | 月額サブスクリプションの無料トライアルをApp Store Connectで設定する。期間・期限はStoreKitの購読情報、対象可否はStoreKitの判定に従い、独自の試用開始日時や再試用履歴を持たない |
| 重なる権利 | いずれかが有効なら利用可能。別の権利を消費・停止しない。同一商品の追加購入を許す条件や残期間との扱いは課金連携で決める。購入時起算の回答だけから期間加算まで決定済みと扱わない |
| 復元 | 同じ取引を繰り返し復元しても同じ期限。利用者操作で復元し、毎日の手動確認を要求しない |
| 失効の反映 | 取得できた取消・返金・期限を新しい操作に反映する。単なる通信失敗を取消や永久有効へ変換しない。成立済み通話と残り24時間は維持 |
| 内部テスト | 必要な判定だけを試験単位で置き換える。製品版へ迂回を公開せず、権利判定そのものの試験では迂回しない |

Appleの[currentEntitlements](https://developer.apple.com/documentation/storekit/transaction/currententitlements)には終了済みの非更新型取引も含まれるため、存在だけで有効とは判定しない。[purchaseDate](https://developer.apple.com/documentation/storekit/transaction/purchasedate)を期限計算の根拠とし、1週間チケットには非更新型の商品を候補にする。2026-10-30に資料を再確認した。商品登録・価格・試用日数・無料配布方式は未決で、今回の条件整理を販売開始と扱わない。

| [UsageGuard](../../server/src/UsageGuard.ts) | 月の予約秒数、active leaseと認証用内部アカウントIDの対応、owner別の日次開始数。更新時に日付と期限を整理 | ユーザー対応は解放・期限切れ整理で削除する。無操作時に全記録を自動削除する処理はない。公開準備で実サービスの保存・削除と合わせて確認 |

## データ保持表

以下は新設計の保存範囲と削除契機である。既存Workerの差分は上表で管理する。iCloudは採用未決のため保存先に追加しない。

| データ | 目的と保存先 | 保持・削除・共有の条件 |
|---|---|---|
| メールアドレス・本名 | アプリ・自社サーバー・ログへ保存しない | Appleログインで追加要求せず、応答に含まれても永続化しない |
| Apple認証識別子とアプリ内ユーザーID | 再ログイン・機種変更の同一ユーザー解決。認証サーバーに最小限保存 | アカウント削除で対応を削除。生のApple識別子を相手・通知本文・ログへ公開しない |
| 端末ID・端末資格・認証token | 同一ユーザーの端末管理と紛失時の失効 | 端末秘密はKeychain。サーバーは必要な検証・取消用情報だけ保持。端末解除・認証取消・アカウント削除で失効させる |
| 通知tokenと環境・topic・端末の対応 | ユーザーIDから端末への配送。通知サーバー | 更新で置換し、無効応答・端末解除・サインアウト・アカウント削除で配送対象から除外。ログにtokenを残さない |
| ハンドルネーム・ユーザー一覧 | 未接続でも相手を選ぶため直接招待関係のある相手だけを端末で保持。グループで見つかっただけの第三者は登録しない。認証済み通信で必要な表示情報を交換 | 相手の削除は自分の一覧からの除去。相手のアカウント削除ではない。名前変更でIDを変更しない。本人名と受け取り側の端末内呼び名を分け、本人名を確認・復元できる |
| グループ情報・1対1の対応・開始日時 | 端末の一覧・相手の再利用・再開条件 | グループ削除でユーザー一覧を消さない。削除と退出・失効を区別し、他端末のデータを消したと扱わない。履歴喪失時に現在時刻で猶予を作り直さない |
| グループ鍵・招待 | Keychainと参加に必要な通信。直接招待の発行者鍵も本人アカウント別Keychain | ログ・通常設定・通知本文に秘密を載せない。保存移行で鍵を失わない。アカウント削除では招待発行者鍵も消去し、以前の招待確認を新しい登録の権限へ引き継がない |
| 購入・試用・無料券・TestFlightの状態と期限 | 端末の利用権判定。購入の正本は検証済みStoreKit情報 | StoreKitの購入・無料トライアルと、独自の無料券・配布環境の権利を区別。ユーザー切替や復元の対応は課金連携で具体化。独自の購入台帳サーバーを必須にしない |
| 呼出し状態 | 呼出し・取消・重複抑止・応答先の管理 | 呼出しの期限内に必要な情報へ絞る。任意IDへ無制限に通知できる設計にしない。保存を増やす場合は認証・通知に必要な範囲を明示 |
| 音声・Audio Check・診断 | 現行の音声処理と利用者による確認 | クラウド録音や音声収集を追加しない。[ログ規約](../policies/ログ記録規約.md)の秘密・音声内容・生IDの禁止を維持 |
| providerのアクセス記録・backup・cleanup待ち | Cloudflare・Apple等の運用 | コードだけでは実設定や保存期間を確定できない。公開準備で確認し、アプリの削除完了とprovider側の物理削除を混同しない |

アカウント削除、端末だけの削除、グループ退出、購入復元、サブスクリプション解約は異なる操作として設計する。アカウント削除を解約成功と表示しない。保存復旧用の退避・旧形式に残る情報も、削除設計の対象に含める。

## グループ内の関係とグループ外操作の境界

直接招待する相手は友人とみなせるが、その日に同席した参加者は友人の友人かもしれない、という利用者の意図を適用する。同じgroupへの所属・認証・相手IDの取得だけでは、group外で接触する権限を与えない。直接招待関係のない相手はgroup内の表示・通話に限定し、ユーザー一覧、新しいgroupへの追加候補、個別呼出し、通知宛先へ昇格させない。

将来の通知は画面で候補を隠すだけでなく、共通操作と送信先の認可でもこの境界を守る。任意のユーザーIDを指定すれば送信できるAPIにしない。現在の端末内連絡先・group共有鍵は、公開サービスの通知認可を証明するものではない。通知の認可に必要な関係の確認・解除・最小識別情報は認証／通知実装時に具体化し、表示名やgroup名を中央に集める理由にはしない。

## 受入へ渡すケース

| ケース | 期待する結果 |
|---|---|
| 有料・試用・無料券・TestFlight | 有効中は作成・購入者ありの開始で同じ結果。出所は保持 |
| 購入から7日直前・ちょうど・直後、同一取引の反復復元 | 直前だけ当該チケットが有効。復元で延長しない。期限後も成立済み通話と残り24時間は保持 |
| 月曜08:00に購入者ありで成立し、月曜20:00と火曜07:00に未購入者だけで再開 | 起算点は月曜08:00のまま。火曜08:00までは再開可、超過後は購入者相当が必要 |
| 火曜07:00から通信断なく継続し08:00を超える | 通話を切断しない |
| 通信断からの復帰が火曜08:00の直前・ちょうど・直後 | 直前・ちょうどは購入者なしで自動再開。直後は購入者相当が必要 |
| 複数経路の一部だけ消失 | 他の経路で通話が続いていれば継続として扱い、24時間条件で切らない |
| 返金・期限切れ・購入者離脱 | 通話と残り24時間を維持。会話相手がいなくなれば終了扱い。失効した権利で新しい起算点を作らない |
| 呼出し取消・無応答・接続失敗・途中参加・重複通知 | 起算点を更新しない |
| 未購入者から購入者への1対1と同じ二人の再開 | 応答と接続成立後に初回開始。内部グループを再利用して同じ24時間条件を適用 |
| 購入者の人数や割合が少ない | 半数の条件で拒否・停止しない |
| Local・Internet・混在、画面・通知・Siri・Watch | 同じ状態なら同じ判定。新しい画面ごとに別のルールを作らない |
| 保存破損・時刻欠落・古い通知・相手削除 | 取得不能を隠さず、猶予を作り直さない。古い終了操作で別の新しい通話を切らない |

これらは実行前の期待値であり、テスト成功の記録ではない。後続の共通設計では既存コードへの割当て、ユーザー・グループの保存移行、通知相手の同意、購入とアプリ内ユーザーの対応を具体化する。課金連携で試用期間・無料配布・商品の重複を決め、実機受入で配布環境・通知・音声を確認する。
