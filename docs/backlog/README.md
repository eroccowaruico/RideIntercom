# 課題と候補

要求・現行仕様とは別に、これから行う作業を管理する。実装の有無と確認の有無を混同しない。

| 区分 | 文書 | 扱い |
|---|---|---|
| リアルタイム会話 | [遅延と連続性改善](リアルタイム会話の遅延と連続性改善.md) | 実装・厳格な音声E2Eを進行中 |
| 実装する残作業 | [未実装課題](未実装課題.md) | 現状との差、対象、完了条件、阻害条件 |
| 着手した先頭工程 | [利用権とデータ保持の設計](利用権とデータ保持の設計.md) | 回答で確定した条件、操作判定表、現行保存の棚卸し、保持・削除方針、受入条件 |
| 追加要望の全体点検 | [機能拡張の実装前整理](機能拡張の実装前整理.md) | 抜け・矛盾、実装前の決定事項、公式資料の成立条件、受入条件。端末内ユーザー管理・個別通話先の解決は実装済み |
| 採用を判断する案 | [改善候補](改善候補.md) | 未採用・保留を明示。実装予定と断定しない |
| 実装後の確認 | [未確認事項](../validation/未確認事項.md) | 新規実装ではなく実サービス・実機等の確認 |

低ビットレートの許容、ユーザーとグループの分離、一般ユーザー向け画面と英語・日本語対応、通知、ウィジェット、CarPlay、上部表示、ショートカット・Siri、iPhone連携のApple Watchは[今後追加する機能と利用体験](未実装課題.md#今後追加する機能と利用体験)に記録している。グループ内の音声設定統一は[電池消費を条件に判断する案](改善候補.md#電池消費を条件に判断する案)で扱う。当初は記録だけを行ったが、同日の「上から順に進めて」により、依存順の先頭から設計を開始し、グループから独立した端末内ユーザー保存・再利用と、個別通話先の解決・再利用をAppへ実装した。認証・通知・利用権を含む工程全体の完了ではない。

低帯域向けの候補は48kHz・32kbps、24kHz・16kbpsとし、8〜12kbps付近も含めて聞こえと実通信量から推奨下限を決める。現在の波形を維持できる推奨は残す。数値は未検証の候補であり、[評価条件と依存順](機能拡張の実装前整理.md#低帯域向けの候補と推奨の決め方)を記録した。

Appleでのログインと個人情報を保持しない方針、ユーザーIDへの通知、1週間チケット・月ごとのサブスクリプション、お試し・無料配布・TestFlight・内部テストの利用権、購入者によるグループ作成と24時間の発信条件も[未実装課題](未実装課題.md#appleでのログインと通知先の識別)に記録している。既存の要望を含む[依存関係と取り組む順序](未実装課題.md#依存関係と取り組む順序)を参照する。価格と未決の判定条件は実装前に具体化する。

24時間の起算点は[最後の購入者ありの開始](機能拡張の実装前整理.md#完全終話後の24時間条件)とし、未購入者だけの再開では延長しない。完全終話後にこの期限を超えて再開するときは購入者を必要とする。[購入検証の調査](機能拡張の実装前整理.md#端末での購入検証とテスト環境)には、端末での購入状態・期限の保持と手動復元、独自検証サーバーを必須にしない低コスト方針、TestFlightの自動判別候補と開発テストの限定迂回をまとめた。

自分の設定・グループ・ユーザー情報をiCloudへ保存して自分の端末間で共有する案は、[改善候補](改善候補.md#自分の端末間で情報を保存共有する案)に追加した。採用は未決。保存対象・アカウント対応・競合・削除・復旧の論点は[実装前整理](機能拡張の実装前整理.md#icloudへの保存と自分の端末間同期)、採用時の工程は既存の依存順で管理する。

画面追加前の[IF抽象化と情報設計](機能拡張の実装前整理.md#画面とのif抽象化と一般向けの情報設計)も先行工程として追加した。既存のアドバンスド・開発者向け画面とDiagも含めて画面と処理を分離する。ユーザー一覧・グループ一覧は両系統に必要とし、一般向けは必要最小限の情報と分かりやすい説明にする。特定ユーザーとの通話では内部グループを意識させず、その解決を共通処理に置く。Diagは既存画面側で扱い、一般向け画面へ含めない。

実装したら同じ変更で[仕様](../spec/アーキテクチャ.md)を実態に揃え、課題一覧から除く。経緯は検証履歴へ保存し、確認が残る場合は検証側へ引き継ぐ。目的・共通方針は[要求](../requirements/README.md)へ戻して管理する。
