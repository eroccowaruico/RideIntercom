# バックログの優先順位と引継ぎ

本書は、区分をまたぐ着手順と未完了の引継ぎを追う入口である。課題の目的・経緯・未決事項・受入条件の詳細はリンク先を正本とし、ここでは重複して管理しない。実装済みの契約は仕様、実行結果と受入待ちは検証文書を参照する。

優先順位は利用者が明示した順、コア体験への影響、重大な不確実性、依存関係と利用者価値で判断する。状態や依存が変わったら本表も更新する。区分は「改善」「デザイン」「機能」を主分類とし、複数区分にまたがる課題は主分類を明示して相互参照する。

## 引継ぎ一覧

引継ぎは、受け渡す先・残る状態・次に渡すもの・受入先を記録し、設計案や実装記録に埋もれたままにしない。詳細条件と証跡は参照先に保ち、状態が変わったら本表と詳細の両方を更新する。

| 引継ぎ項目 | 受け渡し先 | 状態 | 次に渡すもの・閉じる条件 | 詳細・証跡 |
|---|---|---|---|---|
| 個人招待とStandard／Advancedの画面・操作 | UI/UX判断担当（未割当）→ App実装・受入 | 要求は記録済み。デザイン判断と実装は未着手 | 未接続から連携成立までの再現結果を起点に、対象メンバー詳細の返信／再送、仮名・名前、専用グループ表示、設定変更を対応づける。古い画面案をそのまま採用せず、画面仕様・現行動作を照合してUI判断とE2Eを閉じる | [個人招待課題](未実装課題.md#個人招待の修復と画面アーキテクチャの整理)、[操作の流れ](../design/操作の流れ.md)、[一般向け画面案](../design/一般向け/画面構成とレイアウト.md) |

| 近距離の制御接続と音声媒体の不達テスト | RTC移行・検証担当 → App音声E2E／実環境受入 | 条件と既存テストの不足を記録済み。新テストは未実装 | 移行を実施する場合は新しい制御経路上で制御接続と媒体到達性を独立操作できる試験を設計し、双方向の音声・fallback・復旧を確認する。実Wi-Fiの分離条件はvalidationへ渡す | [媒体不達テストの追加条件](未実装課題.md#multipeer接続成立後のセグメント分離テストの追加)、[近距離制御移行](未実装課題.md#近距離制御のmultipeerからの移行) |
