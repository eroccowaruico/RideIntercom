# 課題と候補

これから行う実装・判断を管理する。現行動作は[仕様](../spec/アーキテクチャ.md)、実装後の実機・実サービス・配布の確認は[未確認事項](../validation/未確認事項.md)を正本とする。着手前に現行仕様と実装を照合し、残る差分を作業対象とする。

実機での確認だけが残る範囲は[実機確認待ち](../validation/実機確認待ち.md)、実機以外にも残るテストと阻害条件は[確認待ちの振り分け](../validation/未確認事項.md#確認待ちの振り分け)から確認する。未着手・未解決の項目と着手順は本バックログに維持する。
