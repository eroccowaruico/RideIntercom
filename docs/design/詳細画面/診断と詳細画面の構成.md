# RideCom 診断と詳細画面の構成

## 指示と背景

2026-11-01の利用者指示により、詳細表示（Advanced）の診断・通話・設定画面を、仕様を知らない人でもぱっと見でトラブルシューティングできる構成へ設計し直す。診断画面では、音声の流れ（パイプライン）・ミキサー・各処理が「何がどう流れ、今何が動いていて、どこで止まっているか」をすぐ読めることを最優先にする。一般向けではないため配色は一般向けほど作り込まないが、細かい情報を分かりやすく並べる。

同日の追加指示により、次を条件とする。

| 条件 | 内容 |
|---|---|
| 主な端末 | iPhone |
| 言語 | 英語だけ。日本語訳を持たない。正式な英語とし、画面の説明は現行の注記程度に留める |
| 語 | 現行コードの表示語（`Live TX Pipeline`、`TX Bus`、`Peer Buses`、`Mix Down`、`RX Master`、`Connect`、`Participants`、設定のSection名など）をそのまま使う |
| 多人数 | 相手ごとにばらばらな送信条件・自分側の設定が、1つのミックスへ合流する流れを入れ子で見せる。複数の経路を明示する |
| 一覧性・まとまり | 全体の構成・まとまり・順番が分かるようにする。設定はリセットまでの全体と、グループの構成を示す |
| タブ | Call・Users・Groupsは一般向けと同じく分ける。通話は1対1でもグループの実体として見せる |

本書は実装前の設計案。現行の項目・識別子・更新周期は[Diagnostics画面](../../spec/App/UI/Diagnostics.md)・[Call画面](../../spec/App/UI/Call.md)・[Settings画面](../../spec/App/UI/Settings.md)を正本とし、実装と同じ変更でそれらを更新する。音声経路の事実は[音声処理仕様](../../spec/App/音声処理仕様.md)、各packageの値は[packages](../../spec/packages/Overview.md)を正とする。一般向け画面は[一般向けの画面構成](../一般向け/画面構成とレイアウト.md)で扱い、本書と混ぜない。見た目は[詳細画面見本](詳細画面見本.html)で確認する。

## 現行の診断画面で分からない理由

2026-11-01時点のコード（`DiagnosticsView`・`TransmitPipelinePresentation`・`ReceivePipelinePresentation`・`IntercomViewModel+Diagnostics`）を確認した結果。

| 現象 | 現行の実装 | 困ること |
|---|---|---|
| 結論がない | Live TX Pipeline 6段・Live RX Pipeline 7段の各行に状態色を付けるだけ | どこで止まっているかを、全行を読み比べて自分で推測する必要がある |
| 略号が説明なしで並ぶ | `C 2 / A 2 / RX 341`、`Run / 48k/1ch / F 12345`、`RX / JIT / PLAY`、`DEC` | 接続数・認証数・受信packet数・処理frame数・再生待ちの意味が分からない |
| 累計しかない | 送受信packet・frame数は通話開始からの累計 | 「今」流れているのか、さっき止まったのかが分からない |
| 概要カードが空疎 | Audio Pathは常に固定文と灰色。Callは`GROUP 1a2b3c4d / MEMBERS 4`。Inviteは招待可否だけ | 概要として役に立たない |
| Networkが1つの長文 | `networkDiagnosticsSummary`を改行区切りの1つのTextで表示 | 経路ごとのRTT・送信待ち・drop・中継経路を見比べられない |
| VADが行にない | 見出しの説明文には`VAD`とあるが、段の行がない。noise floor・threshold・gainはruntime snapshotにあるのに未表示 | 「話しているのに送られない」の原因（感度・騒音）を確認できない |
| 相手側の条件が見えない | 相手から届く`remoteRuntimeStatuses`（相手のマイク、codecの要求と実際・fallback、VAD、effect）を表示していない | 相手ごとに条件が違うときに、どこが原因か分からない |
| 要求値と実効値が見えない | Codecは要求→選択とFallbackの語だけ。SessionManagerの`resolvedConfiguration`・`unsupportedSettings`は未表示 | 設定が反映されたのか、OSに無視されたのかが分からない |
| 機器が見えない | `currentInput`・`currentOutput`の機器名、出力の`bufferedOutputDuration`・`playbackResetCount`は未表示 | Bluetooth・有線・内蔵のどれで鳴っているか、再生が途切れ直しているかが分からない |
| Apple Watch経路が見えない | `watchAudioLink`の有無を表示しない | 音声がWatchへ行っているのか、iPhoneで鳴っているのかが分からない |

## 設計方針

| 方針 | 内容 |
|---|---|
| 結論を最初に | 先頭に、TX・RXそれぞれの判定（Running／止まっている段と理由／Waitingの理由）を出す。判定は各段の状態から機械的に導き、推測の文章を作らない |
| 流れを図として見せる | TXは段の縦の並びと経路への分岐、RXは相手ごとのブロックが`Mix Down`で1つに合流する入れ子の木として描く。止まっている段より先は`Idle`として灰色で示す |
| 今の値と累計を分ける | 各カウンタは毎秒値（今の流量）を主、累計を補助に置く。毎秒値が0なら今は流れていないと一目で分かる |
| 一覧性 | 5ページに分けて各ページの密度を保つ。同じ種類の値は同じ桁位置にそろえ、ラベル付きの短い行で並べる。4症状から見るべき段へ直接移動できる |
| packageの値だけを描く | 段・effect stageの順序は`AudioMixerSnapshot`・`MixerGraphSnapshot`・`AudioEffectChainSnapshot`から導く。固定の段名列・既定値をUIの正本にしない（[Diagnostics](../../spec/App/UI/Diagnostics.md)の固定文字列禁止を維持）。effect stageの名前はpackageが返す名前のまま表示する |
| 共通の規則 | 色・背景・余白・寸法・コントロール・UI Stack・レイアウトは[デザインシステム](../デザインシステム.md)に従い、一般向けと同じ[カラーテーマ](../カラーテーマ.md)を使う。部品は[共通コンポーネント](../デザインシステム.md#共通コンポーネント設計案)の「状態ドット列」「段の行」「合流する木」を使う。本書はAdvanced固有の内容だけを定める |

### 表記

| 対象 | 規則 |
|---|---|
| 言語 | 詳細画面（診断・詳細の通話・詳細の設定）は英語だけで表示し、String Catalogに日本語訳を持たない。現行の[Settings画面](../../spec/App/UI/Settings.md#利用者向け案内の言語)の「Advancedの診断文言の全訳は対象外」を維持する |
| 段・画面の語 | 現行コードの語を使う。TXは`Session`・`Input`・`VAD`・`TX Bus`（`TX Bus Effects`）・`Codec`・`RTC`、RXは`RTC RX`・`Decode`・`Peer Buses`・`Mix Down`・`RX Master`・`Master FX`・`Output`。見出しは`Live TX Pipeline`・`Live RX Pipeline`・`Network`・`Internet Service` |
| 状態の語 | `Connected`、`Offline`、`authenticated`、`Unmuted`／`Muted`、`Connected / Audio Paused`など、現行の`connectionLabel`・`callPresenceLabel`・`routeLabel`の語を使う。VADは`Speech`／`Silence`（`VADGateState`）。機器の既定値は`Auto` |
| 略号 | 説明なしの略号を使わない。`RX`・`TX`は段の名前としてだけ使い、値には`packets/s`・`frames/s`・`ms`・`dBFS`・`B`／`KB`の単位を付ける。`JIT`は`Jitter buffer`、`F`は`frames`、`C`／`A`は`connected`／`authenticated`と書く |
| ID | snapshotのbus ID（`tx-bus`・`rx-master`・`rx-output`）を等幅の補助表記として併記する |
| 説明文 | 現行の注記・通知の文をそのまま使う（例: `RTT measures this device's ICE connection, not audio delay. Event drops occur inside this device. Paths show the last authenticated reception, not guaranteed reachability.`）。新しい説明は1項目1文までとする |
| 利用者のデータ | 相手名・グループ名は保存されたまま表示し、翻訳しない |

### 状態の語彙

[状態の表し方](../デザインシステム.md#状態の表し方)のAdvancedの語（`Running`・`Waiting`・`Muted`・`Blocked`・`Idle`・`Unsupported`）を使う。内部状態は現行の`PipelineStepState`（passing・waiting・blocked・idle）に対応させ、waitingのうち本人のミュートによるものは`Muted`として表示する（現行は`isMuted`・`isOutputMuted`をwaitingに含めている）。Idleは、音声が開始していない場合と、上流が止まって未到達の場合の両方を表す。

## 診断画面

### ページ

上部の標準`Picker(.segmented)`で5ページに分ける。結論は`Overview`だけで分かるようにする。iPadとMacでは`Overview`と選択中のページを2列で並べる。

| 順序 | ページ（表示名） | 目的 | 主な内容 |
|---|---|---|---|
| 1 | Overview | 結論と全体の一覧 | TX・RXの判定、Pipelineの全段を状態ドットで1行ずつ、Participantsを1人1行、Networkを1経路1行、症状ボタン |
| 2 | TX | 自分の声がどこまで、どの経路へ出ているか | Live TX Pipelineの段、TX Bus Effects（入れ子）、RTCから経路ごとへの分岐（入れ子） |
| 3 | RX | 相手ごとの条件がどう1つのミックスになるか | 相手ごとのブロックがMix Downへ合流し、RX Master → Master FX → Outputへ続く木 |
| 4 | Network | 経路ごとの品質と中継 | Local・Internetのカード、相手ごとのPath、Event drops、更新からの経過 |
| 5 | Applied | 設定が効いているか | Requested → Applied、Call、Internet Service |

現行の`Current Overview`のカード（Audio Path／Call／Network Quality／Invite）は各ページへ分解する。固定文だけのAudio Pathカードは廃止する。Inviteの可否はAppliedのCallへ移す。

### Overview

| 状態 | 判定の表示例 | 導出 |
|---|---|---|
| 両方向に流れている | `TX: Running`／`RX: Running` | 両方向の全段がpassing |
| TXが待機 | `TX: Waiting at VAD — Not speaking` | TXで最初にwaitingになった段と、その段の理由 |
| TXが停止 | `TX: Blocked at Input` ＋ 現行の通知文（例: `Audio device disconnected. Your microphone and playback are paused; the group connection and relay continue. Check your audio device, then resume.`） | 最初にblockedになった段と、その原因の既存の通知文 |
| RXが待機 | `RX: Waiting — Not speaking` | RXの最初の非passing段 |
| 出力がミュート | `RX: Muted at Output` | Output段が本人のミュートで止まっている（`speaker.slash`、Danger） |
| 音声停止で未到達 | `RX: Idle` ＋ `Connected / Audio Paused` | 音声が止まり、RXの段へ到達していない。接続と中継の維持を`callPresenceLabel`で示す |
| 未開始 | `TX: Idle`／`RX: Idle` ＋ `Media Idle` | 全段idle |

Pipelineは`TX`と`RX`の2行に、段名と状態ドットを並べる（例: `TX ● Session ● Input ● VAD ● TX Bus ● Codec ● RTC`）。Participantsは「名前・経路・RXの毎秒値・状態」、Networkは「経路名・相手数・RTT・状態」を1行ずつ出す。

症状ボタンは該当ページの該当段へ移動して展開する。

| 症状ボタン | 移動先 |
|---|---|
| `Others can't hear me` | TXの最初の非passing段 |
| `I can't hear someone` | RXの対象の相手のブロック |
| `Audio drops out` | RXの`Decode`の破棄・`Jitter buffer`と、NetworkのLoss・Event drops |
| `Audio is delayed` | RXの`Jitter buffer`、Outputの予約量、NetworkのRTT |

### TX（Live TX Pipeline）

段を縦に並べ、各段は「段名／状態／主な値／毎秒値」を1〜2行に収める。`TX Bus`と`RTC`は中身を入れ子で示す。

| 段（表示名） | 主な値 | 毎秒値 | Waiting・Blockedの理由の例 | 展開で出す値 |
|---|---|---|---|---|
| Session | `Burst mode`／`Stream mode`と有効状態 | — | `Configured`（未活性）、`Error` | 要求設定と実効設定（category・mode・options・echo cancellation・sample rate・IO buffer）、`unsupportedSettings` |
| Input | 機器名（`currentInput`）と実形式（例: `AirPods Pro · 48 kHz mono`）。Apple Watch選択中は`Apple Watch` | frames/s | `Starting`、機器の切断（ミュート中は状態を`Muted`にする） | 要求形式と実形式、処理frame累計、voice processingの要求と実効、`inputDeliveryMuted` |
| VAD | `Speech`／`Silence`、感度preset | — | `Not speaking` | Noise floor・Threshold（dBFS）、gate gain、直近の分析値 |
| TX Bus | `tx-bus`、source数・effect数 | — | `Snapshot waiting` | 入れ子の`TX Bus Effects`（下記） |
| Codec | 実際の形式（例: `AAC-ELD · 48 kHz · 48 kbps`）。fallbackなら要求→実際と`Fallback` | packets/s | 発話待ち、`Fallback` | 要求設定と実効設定、利用可能なcodec一覧 |
| RTC | `routeLabel`（例: `Local + Internet / Relay`） | packets/s | `Control Waiting`、`Media Idle` | 入れ子の経路ごとの分岐（下表） |

`TX Bus Effects`は`tx-bus.effectChain`の登録順に、packageが返すstage名と状態をそのまま並べる。現在の実配線では`SoundIsolation → DynamicsProcessor → PeakLimiter`の順になるが、この順は表示の正本ではない。VADはミキサーの前段で動くため、effectではなく独立した段として描く（[Diagnostics](../../spec/App/UI/Diagnostics.md#診断と適用状態の区別)）。

RTCの分岐は、経路ごとに1行とし、その経路で直接届けている相手と、中継で届く相手を並べる。

| 分岐の行 | 内容 |
|---|---|
| Local | 状態、宛先（例: `Haruka · direct`、`Kenta · relayed by Haruka`） |
| Internet | 状態、宛先（例: `Mika`）、Send queue |

全員へ近距離で届く場合にインターネットへ送らないこと（[製品要求](../../requirements/製品要求.md)）は、Internetの行を`Idle`（neutral）として示し、故障に見せない。

### RX（Live RX Pipeline）

相手ごとの条件がばらばらなまま届き、相手ごとのPeer Busで自分側の設定が掛かり、`Mix Down`で1つに合流する流れを入れ子の木で描く。左端の縦線を各相手のブロックから`Mix Down`へ合流させ、合流点に`3 routes → rx-master`のように数を示す。

相手ごとのブロックは、見出し1行（名前・状態・経路の要約）と、段名付きの4行を同じ桁位置にそろえる。

| 行（表示名） | 内容 | 入力 |
|---|---|---|
| Sender | 相手の端末で掛かっている送信条件。codecと形式・bitrate（fallbackなら要求→実際と`Fallback`、低帯域は`Lower Quality`）、相手のマイク（`Unmuted`／`Muted`）、相手のVAD（`Speech`／`Silence`）、相手のTXのSoundIsolation。15秒を超えた値は経過秒を付けて薄くする | `remoteRuntimeStatuses[peer]`の`localMute`・`audioPolicy`・`packageReports`（Codec・VADGate・SoundIsolation）、`generatedAt` |
| RTC RX | `Connected`／`Connecting`／`Offline`と`authenticated`。届いた経路（直接・中継・Internet）。別の経路が使えない場合はその旨（例: `Local unavailable`） | `connectionState`、`authenticationState`、`RTCNetworkDiagnostics`の相手ごとの経路 |
| Decode | 復号しているcodec、RXの毎秒値、破棄数 | `activeCodec`、`receivedAudioPacketCount`の差分、drop |
| Peer Bus | 自分側の設定。Volume（%）、SoundIsolation（Active／Bypassed／Unsupported）、Jitter buffer（ms）、レベルメーター | peer volume、`receivePeerEffectChainSnapshot`、`queuedAudioFrameCount`、`voiceLevel` |

Offlineの相手は見出しだけを薄く表示する。

合流後の段は、`Mix Down`の下に縦に並べる。

| 段（表示名） | 主な値 |
|---|---|
| Mix Down | 合流するroute数 → `rx-master`（`MixerGraphSnapshot`の`busRoute`） |
| RX Master | `rx-master`、入力数、OUT（%）。100%超は`Boost`。frames/s |
| Master FX | 入れ子で、`rx-master.effectChain`＋`rx-output.effectChain`の順（現在は`SoundIsolation → Master fader → PeakLimiter`）。PeakLimiterは`rx-output`を併記 |
| Output | 機器名（`currentOutput`）と実形式、Buffered（`bufferedOutputDuration`）、resets（`playbackResetCount`）、出力レベル。Apple Watch選択中は`Apple Watch`とし、iPhoneの出力が消音であることを併記 |

上流が止まっている相手のブロックは、止まった行を強調し、それより下の行を`Idle`として薄くする。下流の0を故障として見せない。

### Network

経路（Local・Internet）ごとにカードを分け、`networkDiagnosticsSummary`の1つの長文を廃止する。

| 項目（表示名） | 内容 |
|---|---|
| RTT | ICE接続のRTT（ms）。取得できない場合は`Not available` |
| Loss | `RouteMetrics.packetLoss`・`jitter`。未取得は`Not available`とし、0%として扱わない |
| Send queue | DataChannelの送信待ち（B／KB） |
| Event drops | session・route・engine・transportごとのoverflow・expired |
| Paths | 相手ごとに`Direct group path`／`Relayed`と短縮IDの経路 |
| Updated | 生成からの経過秒。15秒を超えたら古い値として薄くする |

カードの下に現行の注記をそのまま置く（`RTT measures this device's ICE connection, not audio delay. Event drops occur inside this device. Paths show the last authenticated reception, not guaranteed reachability.`）。

### Applied

| 項目（表示名） | Requested → Applied | 入力 |
|---|---|---|
| Codec | 設定のcodec・sample rate・bitrate → 実際の符号化設定 | `CodecRuntimeReport.requestedConfiguration`／`activeConfiguration`、`isFallback` |
| Session | `Burst mode`／`Stream mode`、Use Speaker、Echo Cancellation → 実効のcategory・mode・options | `AudioSessionConfigurationReport.requestedConfiguration`／`resolvedConfiguration` |
| IO buffer・Sample rate | 要求値 → 実効値 | 同上 |
| Unsupported | OSが適用しなかった設定の一覧 | `unsupportedSettings`、`unsupportedInputVoiceProcessingSettings` |
| Ducking | Duck Other Audioの設定 → 今作動しているか | `isDuckOthersEnabled`、`isOtherAudioDuckingActive` |
| Isolation | Transmit・Master・相手ごとの設定 → 実ノードのActive／Bypassed／Unsupported | effect stage snapshot |
| VAD | VAD Sensitivity → 実際のThreshold・Noise floor | `VADGateRuntimeSnapshot` |
| Devices | 選択した機器（`Auto`など）→ 実際の機器 | `selectedInputPort`、`AudioSessionSnapshot.currentInput`／`currentOutput` |

RequestedとAppliedが異なる行だけ`exclamationmark.triangle`と`Differs`を付ける。非対応による差は`Unsupported`と書き、故障として扱わない。

AppliedにはCall（State・Group・Members・Invite）と、現行の`Internet Service`（状態の文・`Check Internet Service`・現行の注記）も置く。

### Copy Diagnostics（追加候補）

画面の内容を、秘密を含まないテキストとして書き出す`Copy Diagnostics`を候補とする。group secret・招待token・端末資格・音声payload・Apple識別子は含めない（[ログ記録規約](../../policies/ログ記録規約.md)と同じ禁止情報）。採否は未決事項とする。

### 毎秒値と更新

| 項目 | 方針 |
|---|---|
| 更新周期 | 現行どおり表示中0.5秒、非表示5秒、開いた時点で即時 |
| 毎秒値の計算 | 直前のsnapshotとの差分÷経過時間。差分の保持は`DiagnosticsInput`を作る側（表示中のtick）に置き、Presentationは純粋関数のまま保つ |
| 表示の安定 | 等幅数字を使い、桁が変わっても列幅を揺らさない |
| 停止の検出 | 通話中に毎秒値が0の段は、累計が増えていても今は流れていないと表示する |

### 新たに表示用へ渡す値

現行のViewModelまたはpackage reportに値があり、`DiagnosticsInput`へ渡していないもの。実装時に`DiagnosticsInput`へ追加する。

| 値 | 所有 | 状態 |
|---|---|---|
| 相手の送信条件（マイク、codec要求・実際・fallback、VAD、TXのSoundIsolation） | `remoteRuntimeStatuses[peer]`の`localMute`・`audioPolicy`・`packageReports` | ViewModelにある。payloadの復号と表示への写像を追加する |
| 相手ごとの経路（直接・中継・複数経路） | `RTCNetworkDiagnostics`の相手ごとの経路、`connectionState` | ViewModelにある |
| `currentInput`・`currentOutput`の機器名 | `AudioSessionSnapshot` | ViewModelにある |
| `resolvedConfiguration`・`unsupportedSettings` | `AudioSessionConfigurationReport` | ViewModelにある（`lastAudioSessionConfigurationReport`） |
| `bufferedOutputDuration`・`playbackResetCount` | `AudioStreamSnapshot` | 出力のoperation reportにある |
| VADのnoise floor・gain・分析値 | `VADGateRuntimeSnapshot` | ViewModelにある（`vadGateRuntimeSnapshot`） |
| codecの要求設定・実効設定 | `CodecRuntimeReport` | ViewModelにある（`codecRuntimeReport`） |
| Apple Watch経路の有無 | `watchAudioLink` | ViewModelにある |
| 経路ごとの送信packet数と宛先 | RTC | 現行は合計だけ。経路別の内訳が必要ならRTCの診断へ追加する |

## タブ構成

2026-11-02の利用者指示により、詳細表示も一般向けと同じく通話をタブから外し、Users（最初）・Groups・Diagnostics・Settingsの4つにする。通話は選んだときに開くシートと、接続中の`tabViewBottomAccessory`で扱う（[操作の流れ](../操作の流れ.md)）。中身は詳細表示の情報量のままとする。

| タブ | 内容 |
|---|---|
| Users | 最初の画面。保存済みユーザーと招待中。行のタップで内部のdirectグループを解決して接続を始め、通話のシートを開く |
| Groups | 通常グループ、1対1のための内部のdirectグループ（`Direct Groups`）、保存の復旧操作。行のタップで接続を始め、通話のシートを開く。Standardのグループタブの表示設定に関係なく常に表示する |
| Diagnostics | [診断画面](#診断画面) |
| Settings | [詳細表示の設定画面](#詳細表示の設定画面) |

記号は[タブとシステム表示の記号](../アイコン定義.md#タブ)に従う。Standard／Advancedで同じタブ名・同じ位置になるため、Diagnosticsの有無だけが違いになる。切替で存在しなくなるタブはUsersへ戻す。

## 詳細表示の通話画面

通話は相手が1人でも内部ではグループ（`IntercomGroup.kind == .direct`）である。詳細表示ではこの実体を隠さず、1対1でもグループ通話と同じ構成で表示する。操作の流れは[操作の流れ](../操作の流れ.md)に従う（StandardとAdvancedで共通）。Users・Groupsで選ぶと接続を始めてCallへ移り、グループ通話ではCallからそのまま人を追加できる。グループの一覧・作成と保存の復旧はGroupsタブに置き、Callには置かない。現行の通話画面（`callStatusHeader`・`call-primary-controls`・`call-participants-section`）の語を保ち、4つのまとまりを上から順に置く。

| 順序 | まとまり（表示名） | 内容 | 現行の語 |
|---|---|---|---|
| 1 | Call status | `callPresenceLabel`（例: `Connected`）、`routeLabel`、connected・authenticatedの人数。Group行に種類（`Group`／`Direct`）・メンバー数・短縮グループID。操作は`Disconnect`（切断後は`Connect`）。ツールバーの`…`メニューに`Group Settings`／`User Settings`・`Add Saved Users`・`Share Invite` | `Connect`、`Disconnect`、`Add Saved Users`、`Share Call Invite` |
| 2 | Input | `Unmuted`／`Muted`、VADの判定と感度、入力メーターにNoise floorとThresholdの目盛、ミュートの切替（`mic.slash`）、`Transmit Voice Isolation Effect` | `Input`、`Unmuted`、`Muted` |
| 3 | Output | `Output {n}%`のスライダー（100%に目盛、超過は`Boost`）、`Voice Isolation`（マスター）、出力ミュート、`Duck Other Audio`の作動状態 | `Output`、`Output Volume`、`Voice Isolation` |
| 4 | Participants | 自分（local member）を先頭に含め、`You + n`と数える。相手は1人1行で、名前、`Connected`／`Offline`と`authenticated`（文字）、codec、受信メーター、個別音量、Voice Isolation。行からDiagnosticsのRXの該当ブロックへ移動。グループ通話では一覧の下に`Add Saved Users`と招待中（`Share`）。グループの`Offline`のメンバーで招待の通知が届く人の行末に`Send Call Request`（送信後は`Cancel Call Request`と状態`Ringing`／`Declined`／`No Answer`）。1対1の呼び出しの状態はCall statusに`Call Request: Ringing`／`Busy`／`Declined`／`No Answer`／`Undeliverable`で出す（[通知の設計](../通知の設計.md)） | `Participants`、`No remote riders`、`Add Saved Users`、`Send Call Request` |

Callに置かないもの:

| 操作 | 置き場所 |
|---|---|
| グループの一覧・作成（`Create Talk Group`）・保存の復旧（`Reload Saved Groups`等） | Groupsタブ |
| 保存ユーザーの一覧と新しい相手の招待 | Usersタブ |

GroupとDirectの違いは、Call statusのGroup行の種類（`Group`／`Direct`）と、Directでは`Add Saved Users`を出さず`Share Call Invite`を出すことだけ。現行の接続・認証は記号2つだけで並んでいるため、文字（例: `Connected · authenticated`）を必ず添える。

現行との差: 2026-11-02時点の実装は、Users・Groupsの選択が`connectIfIdle: false`で接続しない。本案の採用時に、選択で接続を始め、会話中は切替を確認する（[操作の流れ](../操作の流れ.md#現行との差と依存)）。Callの`Groups`のtoolbar導線は外し、`Add Saved Users`・`Share Call Invite`はCallに残す。

## 詳細表示のUsersとGroups

一般向けのユーザー・グループ一覧と同じ並び（現在の通話 → 一覧 → 招待中 → 補足）にし、詳細を足す。データと操作は一般向けと共通のIF（[画面とのIF抽象化](../../backlog/機能拡張の実装前整理.md#画面とのif抽象化と一般向けの情報設計)）を使い、画面ごとの台帳を持たない。

| 画面 | 行に出す内容 | その他 |
|---|---|---|
| Users | 端末での呼び名、`Name shared by this person`、内部のdirectグループの短縮ID（未作成は`No direct group yet`）、端末数、呼び出しの許可、接続状態 | 先頭に`Current Call`、末尾に招待中（送った・受け取った招待。状態は[招待の状態](../招待と登録の設計.md#招待の状態)と同じ区別を英語で、`Invitation Sent`／`Waiting for Reply`／`Sending Reply`／`Reply Not Delivered`／`Expired`。行から招待の詳細へ、`Resend Invitation`と`Resend Reply`を別に置く）、反映待ちの`Pending Sync: {n}`、現行のfooter`Only direct invitations save a person here. …`。行の操作で名前の編集・削除・`Share Call Invite`・呼び出し |
| Groups | グループ名、メンバー数、鍵の状態（`key ready`／`key missing`）、短縮グループID、通話中 | `Create Talk Group`、`Reload Saved Groups`などの保存の復旧操作。1対1のための内部のdirectグループは別Section`Direct Groups`に、種類`Direct`・相手の名前・短縮グループIDで並べる。`Group Settings`ではメンバーを読み取り専用にし、`Add Saved Users`とメンバーの削除を出さない（[バックログ](../../backlog/未実装課題.md#個人招待の修復と画面アーキテクチャの整理)の個人通話の内部モデル）。行の長押し（contextMenu）・swipeの`Group Settings`でメンバー一覧・名前・`Add Saved Users`・メンバーの削除と名前の編集・招待・削除を開く（Callの`…`メニューからも同じ画面）。行のタップは接続を始めてCallへ（会話中は切替を確認） |

## 詳細表示の設定画面

Section名・項目名は現行コードの語のままとし、並びを同じ目的のグループにまとめる。グループの切れ目はSection間より少し広い余白で区切り、グループ名そのものは画面に出さない。リセットは最後に独立して置く。

| 順序 | グループ | Section（表示名） | 項目 |
|---|---|---|---|
| 1 | アプリと自分 | App Layout | Standard／Advanced |
| 2 | アプリと自分 | Account | Signed in with Apple、Sign Out、Delete Account |
| 3 | アプリと自分 | Access | Access Status、Restore Purchases、View Purchases |
| 4 | アプリと自分 | Your Display Name | Your name、Save Name |
| 5 | 通話 | Automatic Disconnection | Regular Calls、Calls Started from Watch |
| 6 | 通話 | Call Notifications | `Receive Call Requests`の切替1つと状態の1文（Standardの[呼び出しの通知](../一般向け/画面構成とレイアウト.md#呼び出しの通知)と同じ構成。Enable／Check／Disable Notificationsのボタンは置かない） |
| 7 | 通話 | Call status display | Show call status outside the app（macOSはShow call status in the menu bar） |
| 8 | 接続 | Communication | Local Network、Internet |
| 9 | 接続 | Internet Connection | 状態、Configure Internet Connection（sheet） |
| 10 | 音声（信号の流れの順） | Audio Session | Mode、Use Speaker、Echo Cancellation、Duck Other Audio |
| 11 | 音声（信号の流れの順） | Audio I/O | Input、Output、Transmit Voice Isolation Effect |
| 12 | 音声（信号の流れの順） | Voice Activity | VAD Sensitivity（Low Noise／Standard／Noisy） |
| 13 | 音声（信号の流れの順） | Transmit Codec | Codec、Sample Rate、AAC-ELD Bitrate／Opus Bitrate |

各Sectionのfooterは現行の文をそのまま使う（例: Communicationの`Internet controls this device’s service connection. …`、Reset Settingsの`Resets audio and call settings to their default values. Saved groups and members are not changed.`）。

現行との差: 現行はApp Layout → Account → Access → Call Notifications → Your Display Name → Call status display → Automatic Disconnection → Communication → Internet Connection → Audio Session → Audio I/O → Audio Check → Transmit Codec → Voice Activity → Reset Settingsの順。同じ目的のSectionを隣り合わせ、音声をSession → I/O → VAD → Codecの信号順にそろえ、Audio Checkを音声の最後へ移す。

## 画面ごとのUI Stackとレイアウト

[デザインシステムのUIスタック](../デザインシステム.md#uiスタック)と[レイアウトと画面サイズ](../デザインシステム.md#レイアウトと画面サイズ)を詳細表示にも適用する。

### 状態

| 画面 | Ideal | Empty | Loading | Partial | Error |
|---|---|---|---|---|---|
| Diagnostics | 全段Running | 音声未開始: `TX: Idle`／`RX: Idle`と`Media Idle`。値は`Not available` | 開いた直後の最初のsnapshot待ち（0.5秒以内）。前回値を出さない | 一部の段だけWaiting、一部の相手だけRunning、15秒を超えた古い値（薄く表示） | Blockedの段と既存の通知文。他の段は読める状態を保つ |
| Call（シート・右の列） | Connected・音声あり | 置かない（選ばれたときだけ開く） | Connecting、Media開始待ち | `Connected / Audio Paused`、一部の参加者だけ接続 | 音声エラー・接続失敗の既存文言と再試行 |
| Users・Groups | 一覧と詳細 | 現行の空状態の文言 | 招待・作成の準備中は操作を無効にして進行表示 | 招待中・鍵欠落の行 | 保存の読み込み失敗と`Reload Saved Groups` |
| Settings | 各Sectionの現在値 | — | 確認中の行だけ進行表示 | 非対応の項目（`Unsupported`）を非表示または無効 | 保存・確認の失敗は該当Sectionのfooter |

### 配置

| 画面 | iPhone 縦 | iPhone 横 | iPad・Mac（幅600pt以上） |
|---|---|---|---|
| Diagnostics | 上部のページ切替＋1列 | ページ切替を残し、OverviewとTX・RXは2列（左に判定とPipeline、右に詳細）。RXの合流する木は横幅いっぱいの1列 | 左列に常にOverview、右列に選んだページ（TX・RX・Network・Applied）。Diagnosticsを表示している間は通話の列を閉じ、`tabViewBottomAccessory`（Macはツールバー）から開く。幅1000pt以上ではRXの相手ごとのブロックを2列に並べ、Mix Downへの合流線は左端にまとめる |
| Call | シート: 1列 | 全画面のシート。左列（固定）: Call status・Input、右列: Output・Participants | 一覧の右の列（`inspector`）: 1列（Call status → Input → Output → Participants） |
| Users・Groups | 1列 | 1列 | 1列。接続中は右に通話の列。Group Settings・User Settingsは一覧の上に重ねるsheet |
| Settings | grouped Form | grouped Form | 同左 |

表や長いIDの行は横スクロールを許す。数値は等幅数字で列を揃え、2列のときも段名と値の桁位置を揃える。

## 実装の進め方

| 順序 | 内容 | 依存・完了条件 |
|---|---|---|
| 表示値の追加 | [新たに表示用へ渡す値](#新たに表示用へ渡す値)を`DiagnosticsInput`へ追加し、毎秒値の差分を作る | 既存のPresentationのテストを維持し、追加値のテストを先に書く |
| 状態の理由 | 各段の`PipelineStep`に理由（Waiting・Blockedの原因）を追加し、Overviewの判定を導く | 段ごとの理由の単体テスト。固定の段名列を作らない |
| 診断画面 | Overview・TX・RX・Network・Appliedの5ページへ再構成。RXは相手ごとのブロックからMix Downへ合流する入れ子の木 | 既存の識別子（`liveTransmitPipelineView`、`pipeline-*-step`、`receive-*`、`realDeviceCallDebugSummaryLabel`等）を維持し、UIテストを通す |
| タブ・通話・設定 | 5つのタブへの分割、Users・Groupsの詳細一覧、グループとして見せる通話画面、設定のSectionの並び替え | 既存の識別子を維持し、[Settings仕様](../../spec/App/UI/Settings.md)の記載と`check_documentation.py`を更新 |
| 文言 | 略号をやめた表示とIDの併記。日本語訳は追加しない | String Catalogの英語原文を更新 |

各工程は既存の識別子・accessibility label/valueを保護する回帰テストを先に確認してから変更する（[開発方針](../../policies/開発方針.md#実装と検証)）。
