# RideCom デザインシステム

本ドキュメントは、現行画面で使用している見た目・レイアウト・コントロール仕様を共通化し、実装を強制可能にするための正本である。
本ドキュメントに違反するUI変更は、実装済みであっても不合格とする。

## 強制度

- 必須: 実装時に必ず満たす。未達はマージ不可。
- 禁止: 実装してはならない。検出時は即修正。
- 許可条件付き: 明示した条件に一致する場合のみ許可。

## 適用範囲

- 対象画面: 主要導線画面群、診断導線画面群、設定導線画面群。
- 対象要素: 背景、カード、項目色、角丸、余白、文字、ボタン、タブ、Form Section、メーター、状態表示、アクセシビリティ。
- 対象プラットフォーム: iOS、macOS。
- 基準プラットフォーム: iOS。
- macOS適用方針: iOS基準の構造、状態、アクセシビリティ、意味を維持したうえで、macOS固有の入力・ウィンドウ特性に追従する。

## 利用環境の前提

RideComは、スキー・スノーボード・バイク・ドライブの最中に使う。要求は[製品要求](../requirements/製品要求.md#共通の品質方針)の「走行中の操作」を正本とし、本節はそれを画面・システム表示・Apple Watchの設計へ適用する規則を定める。

| 前提 | 具体的な状況 |
|---|---|
| 走行中・滑走中は手で操作しない | バイクの運転中やスキー・スノーボードの滑走中は、手を使って端末を操作できない。画面も見ない。会話は操作なしで続く必要がある |
| 操作するのは止まっている間だけ | 出発前、信号待ち・停車中、リフト、休憩など止まっている短い時間に操作する。そのときも携帯はポケット・ウェアの内側・バッグ・マウントに入れたままのことが多い |
| グローブをしたまま操作する | 指先の細かい操作ができず、狙った場所からずれて触れる。ポケット内やグローブ越しに意図せず触れることもある |
| 揺れ・寒さ・日差し | 振動、低温、直射日光、ゴーグル越しで、小さな文字や薄い色が読めない |

- 必須: 接続は出発前（止まっている間）に済ませ、走行中・滑走中は操作なしで会話が続くことを主な体験とする。発話検出による送信、経路の自動復旧、自動切断タイマーなど、操作なしで成り立つ仕組みを優先する。
- 必須: 走行中・滑走中に画面の操作を求める設計にしない。操作が必要になる状態は最小にし、必要な場合は理由を触覚・通知音・音声でも知らせ、止まったときに1回の操作で復旧できるようにする。
- 必須: 端末を解除せずに触れられる表示（ロック画面のライブアクティビティ、Dynamic Island、ロック中のコントロールセンター）には、取り消せない操作（切断・削除）を置かない。状態の表示と、取り消しても困らない操作（接続・アプリを開く）だけにする。
- 必須: 取り消せない操作（切断・削除・リセット）は、最も触れやすい位置を避け、押すと確認を出すか、主操作と十分に離して置く。誤って触れても接続を壊さない操作（ミュート・送話・音量）を最も触れやすい位置に置く。
- 必須: 止まっている間の操作は、携帯を取り出さずにできる入口（Apple Watch、ウィジェット・CarPlay、Control、Siri・ショートカット）を同じ共通操作で提供する。手を使わずに済むSiriを優先して整える。ウィジェット・CarPlayの切断は製品要求の操作として残し、ミュートと離して置く。
- 必須: 主要操作は、iOSの下限44ptより大きくする（iPhoneの円形ボタン64pt、Apple Watchの送話パネルは画面の下半分）。隣り合う操作の間には誤って隣を押さない余白を取る。主要操作をスワイプ・長押し・小さなアイコンだけに依存させない。
- 必須: 画面を見なくても結果が分かるよう、状態の変化を触覚（`sensoryFeedback`）とVoiceOverの読み上げでも伝える。状態の文言は短くし、文字は大きめ・高コントラストにする。色だけに頼らない。

## iOS基準定義

- 必須: 本ドキュメント内の値、トークン、レイアウト規約、文字規約は iOS 実装を基準値とする。
- 必須: 新規UI仕様は iOS で成立する具体値を先に定義し、その後に macOS へ同等意味で展開する。
- 必須: macOS 対応は iOS 基準を崩さない範囲で行い、意味差分を生む見た目差分を追加しない。
- 禁止: macOS 側の都合を理由に iOS 基準のトークン値や状態表現を変更すること。

## 実装原則

- 必須: iOS 実装を正とし、macOS は同一の画面構造、同一の状態管理、同一のアクセシビリティIDで追従する。
- 必須: OS差分は Adapter 層で吸収し、View へOS条件分岐を入れない。
- 必須: 主要導線画面は中核体験に必要な情報と操作のみを表示し、診断情報は診断導線画面へ集約する。
- 必須: 設定導線画面は Form と Section の標準構成を維持し、入出力設定、送信方式設定、自己診断設定を分離する。
- 必須: 状態伝達は色のみで完結させない。テキスト、アイコン、accessibility label/value を併用する。

## SwiftUI優先原則

- 必須: UI 実装は SwiftUI 標準コンポーネントを第一選択とする。
- 必須: `TabView`、`NavigationStack`、`List`、`Form`、`Section`、`Button`、`Toggle`、`Slider`、`Picker`、`ShareLink`、`Label` など、意味が一致する標準要素を優先する。
- 必須: カスタム UI は、標準コンポーネントでは意味を満たせない場合に限り導入する。
- 必須: カスタム UI を導入する場合は、標準コンポーネントでは満たせない理由を仕様で説明できなければならない。
- 禁止: 見た目を少し変えたいだけで独自コンポーネントを作ること。
- 禁止: 標準コンポーネントが持つアクセシビリティ、フォーカス、プラットフォーム適応を捨てる実装。

## 意味モデル

本デザインシステムは、見た目ではなく意味を統一対象とする。  
同じ意味は、同じ構造、同じ状態、同じトークン、同じ操作規約で表現する。

| 意味レイヤー | 説明 |
|---|---|
| Screen | 画面全体の役割。主要導線、診断導線、設定導線など |
| Section | 情報群または操作群のまとまり |
| Item | 行、カード、メーター、ボタンなどの最小意味単位 |
| State | その Item が今どういう状況か |
| Action | ユーザーが明示的に発火する操作 |

- 必須: UI 変更はまず「何の意味レイヤーが変わるのか」を説明できなければならない。
- 必須: Item の状態と Action を混同しない。
- 禁止: 同じ見た目で意味が異なるものを同一コンポーネントとして扱うこと。

## UI Stack構造原則

- 必須: 画面は `Screen > Section > Item` の順で意味を積み上げる。
- 必須: 上位ほど役割を、下位ほど具体状態を持つ。
- 必須: 同一 Section 内の Item は、比較可能な情報か、同一目的の操作に限定する。
- 必須: 主要導線画面は「状態把握 > 主要操作 > 対象一覧 > 補助情報」の順で積む。
- 必須: 診断導線画面は「要約 > 切り分け > 詳細」の順で積む。
- 必須: 設定導線画面は「環境依存設定 > 通話方式設定 > 自己診断設定」の順で積む。
- 禁止: 主要導線と診断導線の責務を同一 Section に混在させること。

## UIスタック

[開発方針のUI・UX方針](../policies/開発方針.md#uiux方針)に従い、[UI Stackの原文](https://www.scotthurff.com/posts/why-your-user-interface-is-awkward-youre-ignoring-the-ui-stack/)の5状態を画面設計・レビューの共通観点とする。既存の状態モデルを活用し、状態ごとの見た目と操作、および状態間の移行を一緒に設計する。

| 観点 | 表示・操作で確かめること |
|---|---|
| Ideal（目的が成立する状態） | 必要な情報と主要操作が揃い、目的を達成できること |
| Empty（空の状態） | 初回、利用者による消去、検索結果なしを区別し、理由と次の行動を示す。本書では初回をBlank、対象件数0をEmptyとして扱う |
| Error（失敗） | 理解できる説明と再試行・修正・戻る等の回復手段を示し、入力済み内容や利用可能な情報を保つ |
| Partial（部分的な情報・成立） | 少量・不完全な情報でもレイアウトと操作が成立し、使える範囲と不足を示す。既存の部分成立の定義にも適用する |
| Loading（処理中） | 完了や空状態と区別し、進行状況と必要な取消・重複操作防止を示す。既存情報を活かして待ちの負担を抑える |

Disabledは上の5状態とは別の操作可否として組み合わせる。画面の状態は共通の所有元から導出し、UI用に同じ状態を重複保持する代わりに既存の状態モデルへ対応させる。全画面に5種類の画面や新たなenumを機械的に増設するのではなく、対象に必要な状態を既存構造で表す。

画面仕様には、適用する状態と遷移の条件、表示、操作可否、入力保持、復帰先を記録する。UI検証では、対象変更に関係する状態と、開始→処理中→成功/空/部分成立/失敗→再試行・取消・復帰の該当経路を実際に再現する。表示の点検は技術経路の成立や製品E2Eの証拠と区別し、既存の受入条件を維持する。

## レイアウトと画面サイズ

iPhoneの縦・横、iPad、Mac、Apple Watch、Widgetで同じ画面構造（[UI Stack構造原則](#ui-stack構造原則)の`Screen > Section > Item`）を保ち、配置だけを使える幅と高さに合わせて変える。端末の種類ではなく、画面を描く領域の大きさで判断する（iPadの分割表示・Stage Manager、Macのwindowサイズ変更も同じ規則で扱う）。

### 幅と高さによる配置

画面は「一覧（ユーザー・グループ・設定）」と「通話」の2種類で、通話は接続中にだけ`inspector`で出す（[操作の流れ](操作の流れ.md)）。`inspector`は幅が狭いときOSがシートとして、広いときは右の列として表示する。接続していない間は通話の列を出さず、空の欄を作らない。

| 領域の大きさ | 主な場面 | 一覧 | 通話 |
|---|---|---|---|
| 幅600pt未満・高さ500pt以上 | iPhoneの縦、iPadの狭い分割・Slide Over | 1列。タブバー | シート（`inspector`のcompact表示）。閉じている間は`tabViewBottomAccessory` |
| 高さ500pt未満（`verticalSizeClass == .compact`） | iPhoneの横 | 1列（最大幅640pt、中央）。タブバー | 全画面のシート。中は2列で、左に状態と主要操作を固定（スクロールしない）、右にメンバーなどをスクロール |
| 幅600pt以上1000pt未満 | iPadの縦・分割、Macの標準window | 1列。タブは`.sidebarAdaptable`でタブバーまたはサイドバー | 右の列（`inspector`、幅320〜400pt）。中は1列 |
| 幅1000pt以上 | iPadの横・全画面、Macの広いwindow | サイドバー＋1列 | 右の列（幅360〜420pt）。中は1列 |

右の列のときも、通話の列を閉じた間は`tabViewBottomAccessory`（Macはツールバーの通話表示）から開き直せる。

判定は`ViewThatFits`と`horizontalSizeClass`／`verticalSizeClass`、必要な場合だけ`GeometryReader`の幅で行う。OSの種類で分岐しない（[実装原則](#実装原則)）。

### 余白・安全領域・最大幅

| 対象 | 規則 |
|---|---|
| 安全領域 | 文字・操作は必ず安全領域の内側に置く。iPhoneの横ではDynamic Islandと角の丸みがある左右の安全領域を守る。背景のグラデーションとガラスの面だけを`ignoresSafeArea`で画面端まで広げる |
| 画面の左右余白 | システムの既定（compactで16pt、regularで20pt）。`List`・`Form`の標準余白を使い、独自に狭めない |
| 内容の最大幅 | 一覧の1列は最大640pt、通話の右の列は上の表の幅、iPhoneの横の通話のシートは各列最大560pt。広い画面では中央に寄せ、行を横に引き伸ばさない。画面ごとの幅と寄せ方、中央に寄せる方法は[ウインドウの大きさの変化](#ウインドウの大きさの変化ipadmac) |
| まとまりの間隔 | Section間はFormの標準。グループの切れ目（例: 設定の「自分」と「接続」の間）は標準より一段広く（24pt）とる |
| 固定する要素 | タブバー（サイドバー）、ナビゲーションバー、通話中の`tabViewBottomAccessory`、右の列の通話の状態と主要操作、iPhoneの横の通話のシートの左列だけ。それ以外はスクロールする |
| はみ出し | 名前は2行まで表示し、超える分は末尾を省略する。状態の文言・ボタンのラベルは省略せず、収まらないときは縦に積む（`ViewThatFits`で`HStack`→`VStack`）。表・図など横に長いものだけ横スクロールを許す |

### 大きさと距離

[利用環境の前提](#利用環境の前提)（グローブ・止まっている間の短い操作）に合わせ、OSの下限より大きくとる。

| 対象 | iPhone・iPad | Mac | Apple Watch |
|---|---|---|---|
| 一般の操作の最小の押せる範囲 | 44×44pt | 28pt（推奨36pt） | OS標準 |
| 通話中の主要操作（ミュート・スピーカー・切断） | 64pt。横画面・狭い高さでも56pt以上 | 44pt | 送話パネルは画面の下半分 |
| 隣り合う主要操作の間隔 | 24pt以上 | 16pt以上 | — |
| 取り消せない操作（切断・削除）と他の操作の距離 | 並べる場合は列の端に置き、隣との間を32pt以上とるか確認を出す | 同左 | 画面の反対側（上部）に置き確認を出す |
| 文字サイズの変化 | Dynamic Typeの最小〜AX5で、横並びが収まらない操作列は2段に折り返す | システムの文字サイズ設定に従う | OS標準 |

### 端末ごとの補足

| 端末 | 補足 |
|---|---|
| iPhone 縦 | 基準のレイアウト。通話はシート、閉じている間は`tabViewBottomAccessory`で戻れる |
| iPhone 横 | 一覧は1列でタブバーを下に残す。通話は全画面のシートで、左列（幅の約45%）に状態と主要操作（56pt以上）を固定、右列にメンバー。ナビゲーションタイトルはインライン表示にして高さを確保する |
| iPad | 一覧＋右の列の通話（`inspector`）。分割・Slide Over・Stage Managerで幅が変わったら上の表の配置へ切り替え、狭くなると通話はシートになる。ポインタ操作のホバー表示はOS標準 |
| Mac | サイドバー＋一覧＋右の列の通話（`inspector`）。通話の列を閉じている間はツールバーに通話表示を出す。windowの幅が通話の列を出すのに足りないときはサイドバーを畳む。背景はグラデーションを使わずOS標準にする（[macOSの面と背景](カラーテーマ.md#macosの面と背景)）。windowの最小は幅720pt×高さ520pt。主要操作にキーボードショートカットを付ける。windowが非アクティブでも状態の意味を変えない（[macOS規約](#macos-フォアグラウンド--バックグラウンド規約)） |
| Apple Watch | 41〜49mmの画面で同じ配置。上部に状態と切断、下半分に送話パネル。大きさは画面に対する割合で決める |
| Widget・Control・Live Activity | OSが決める大きさ（Widgetは`systemSmall`・`systemMedium`）の中で、ボタンは44pt以上、ラベルは1行。ミュートと切断を並べるときは、ミュートを左、切断を右端に置き、間を12pt以上あける（`systemSmall`の幅で取れる最大） |

### ウインドウの大きさの変化（iPad・Mac）

2026-11-06の利用者指摘（中央揃えが効いていない、ウインドウの大きさを変えると位置がおかしい画面が多い）により、iPadとMacはウインドウの大きさが使用中に変わる前提で設計する。iPadは分割表示（1/3・1/2・2/3）、Slide Over、Stage Managerの自由な大きさ、外部ディスプレイ、Macは自由な大きさと全画面がある。どの大きさでも、どの途中の大きさでも、内容が欠けず、中央に寄るべきものが中央にあり、大きさを変えても今していることが失われないことを受入条件とする。

#### ウインドウの大きさの範囲

| 端末 | 最小 | 初期 | 最大 | 決め方 |
|---|---|---|---|---|
| Mac | 幅720pt×高さ520pt（サイドバーを畳んで一覧360pt＋通話の列360ptが並ぶ大きさ） | 幅1100pt×高さ720pt。前回閉じたときの大きさと位置を復元する | 制限なし（全画面を含む） | `WindowGroup`に`.defaultSize(width: 1100, height: 720)`、`.windowResizability(.contentMinSize)`、内容に`.frame(minWidth: 720, minHeight: 520)`。設定・購入などの別ウインドウ・シートは[シートの大きさ](#シートの大きさ)のとおり |
| iPad | OSが決める（Slide Overと1/3分割は約320pt幅でcompact） | OSが決める | 全画面 | 大きさを指定しない。どの幅でも[幅の段階](#幅の段階と切り替え)のどれかに入るようにする |

#### 幅の段階と切り替え

構造（タブバーかサイドバーか、通話がシートか列か）はOSのサイズクラスで切り替え、中の配置（列の数、最大幅、余白）は描く領域の実際の幅で決める。どちらも、ウインドウの大きさを変える途中で行ったり来たりしないよう、境目は1か所だけにする。

| 描く領域の幅 | サイズクラス | 構造 | 一覧・設定 | 通話 |
|---|---|---|---|---|
| 600pt未満 | compact | タブバー（Macでは使わない） | 1列、左右はシステムの余白だけ | シート（`inspector`のcompact表示）。閉じている間は`tabViewBottomAccessory` |
| 600〜1000pt | regular | `.sidebarAdaptable`がタブバーまたはサイドバー。Macはサイドバーを畳める | 1列、最大640ptで中央 | 右の列（320〜400pt）。列を出すと一覧の幅は狭くなるが、一覧は360pt未満にしない |
| 1000pt以上 | regular | サイドバー | 1列、最大640ptで中央（一覧の領域の中で中央） | 右の列（360〜420pt） |

| 変わるとき | すること | しないこと |
|---|---|---|
| 通話の列 → シート（iPadで幅が狭くなった） | 同じ通話をシートとして開いたまま続ける。スクロール位置・開いているメニュー以外の状態（ミュート、音量）を保つ | 通話を閉じる、接続先の選択を外す、一覧へ戻す |
| シート → 通話の列（幅が広くなった） | シートを閉じて同じ通話を右の列に出す。シートの上にさらに開いていたシート（メンバーを追加など）はそのまま前面に残す | 列とシートを同時に出す |
| Macで一覧＋列が入らない幅になった | まずサイドバーを畳む（`NavigationSplitViewVisibility`をdetailOnly相当に）。それでも足りない幅にはならないよう最小幅720ptで止める | 一覧を360pt未満につぶす、通話の列を勝手に閉じる |
| サイドバー ↔ タブバー（iPad） | 選んでいたタブ・項目を保つ | 最初のタブへ戻す |
| 高さが500pt未満になった（iPadのSlide Over横、Macの低いウインドウ） | 通話は状態と主要操作を上に固定し、メンバーだけスクロール | 主要操作をスクロールの外へ押し出す |

大きさを変えても保つもの: 選んでいるタブ・サイドバーの項目、一覧のスクロール位置（見えていた先頭の行）、入力中の文字とフォーカス、開いているシート・確認・メニュー、通話の状態。画面の部品の同一性を保つため、幅に応じて別の`View`へ差し替えず、同じ`View`の中で`AnyLayout`（`HStackLayout`／`VStackLayout`）や列数を切り替える。

#### 画面ごとの幅と寄せ方

| 画面 | 内容の最大幅 | 横の寄せ | 縦の寄せ | 背景・スクロールバー |
|---|---|---|---|---|
| ユーザー・グループの一覧 | 640pt | 中央 | 上 | 背景とスクロールバーはウインドウ（列）の端まで。内容だけ中央の640ptに収める |
| 一覧の空状態 | 420pt | 中央 | 一覧の領域の中で縦も中央。高さが足りなければ上から | 同上 |
| 設定（Standard・Advanced）と、その中の画面 | 640pt | 中央 | 上 | 同上 |
| 通話（右の列） | 列の幅いっぱい（列は320〜420pt） | — | 上（状態と主要操作）、メンバーはスクロール | 列の中 |
| 通話（シート・iPhoneの縦） | シートの幅 | 中央 | 上 | — |
| 通話（全画面のシート・2列） | 各列560pt、2列の合計1120pt | 2列のまとまりを中央 | 上 | — |
| サインイン・名前の入力・必須アップデート・アカウント削除の確認 | 420pt | 中央 | 縦も中央。高さが足りなければ上からスクロール | 背景は全体 |
| Diagnostics | 1列は640pt。描く領域が900pt以上ならOverview（360pt）とページの2列、合計1100pt | 中央 | 上 | 背景とスクロールバーは端まで |
| 購入・利用権 | 520pt | 中央 | 上 | 同上 |

中央に寄せる方法:

| 対象 | 方法 | 使わない方法と理由 |
|---|---|---|
| `List`・`Form`・`ScrollView` | スクロール領域はウインドウ（列）いっぱいに置き、内容の左右に余白を足す: `.contentMargins(.horizontal, 余白, for: .scrollContent)`。余白は`max(システムの余白, (幅 − 最大幅) / 2)`。幅は`onGeometryChange`で領域の幅だけを読む | `List`・`Form`を`.frame(maxWidth: 640).frame(maxWidth: .infinity)`で囲む。背景とスクロールバーが中央の帯だけになり、帯の外をスクロールできない |
| 1つのまとまり（サインインの内容など） | `.frame(maxWidth: 420)`の後に`.frame(maxWidth: .infinity, maxHeight: .infinity, alignment: .center)` | 寄せ先を指定しない`.frame(maxWidth: .infinity)`だけ（縦の寄せが決まらない） |
| 領域の大きさを読む必要があるとき | `onGeometryChange`または`containerRelativeFrame`で値だけを読み、配置は通常の`View`で行う | 画面の外側を`GeometryReader`で包む。中身が左上に寄り、中央揃えが効かなくなる |
| 空状態 | `List`の`.overlay`に`ContentUnavailableView`を置く（行が0件のとき） | `List`の`Section`の中の行として置く（上に寄り、中央に来ない） |
| 固定幅の列（Diagnosticsの段名・値） | `Grid`の列にして幅を内容に合わせる。最小幅だけ指定する | 82pt・104ptなどの固定の`frame(width:)`（文字サイズ・言語で切れる） |

#### 現行の実装で崩れる原因の候補

2026-11-06にコードを読んで見つけた、指摘の症状につながる箇所。実装時は[確かめる大きさ](#確かめる大きさ)で再現してから直す。

| 症状 | 箇所 | 原因の候補 | 直し方 |

| 設定が中央の帯になり、外側の余白をスクロールできない | `SettingsView`、`StorePurchaseView`、`AccountDataResetView` | `Form`・`ScrollView`を`.frame(maxWidth: singleColumnMaxWidth).frame(maxWidth: .infinity)`で囲んでいる | `contentMargins`で内容だけ寄せる |

| Macのウインドウを小さくすると一覧がつぶれる・大きさが毎回違う | `RideIntercomApp`の`WindowGroup` | 初期の大きさ・最小の大きさの指定がない | [ウインドウの大きさの範囲](#ウインドウの大きさの範囲)のとおり指定する |

## 操作と状態の共通規則

一般向け（Standard）と詳細表示（Advanced）の設計案に共通する。画面別の文書はこの規則を繰り返さず、違いだけを書く。

| 規則 | 内容 |
|---|---|
| Liquid Glass（必須） | タブバー・ツールバー・sheet・メニューはOS標準のガラスをそのまま使い、`toolbarBackground`等で不透明化しない。主要操作は`.buttonStyle(.glassProminent)`、補助操作は`.buttonStyle(.glass)`、隣接する円形ボタンは`GlassEffectContainer`でまとめ、カード状の面は`.glassEffect`。「透明度を下げる」でOSが不透明化しても成立させる。独自のblur・半透明色・光沢で代用しない |
| 1画面1主操作 | 各状態で最も重要な操作を1つだけ`glassProminent`にする。会話中は塗りの主操作を置かず、ミュートの選択状態と切断だけを色で示す |
| 操作の記号と状態の記号 | 操作ボタンの記号は操作の意味（ミュートは常に`mic.slash`の切替、切断は`phone.down.fill`）。反対操作の別ボタン（「ミュート解除」等）を作らない。状態表示の記号は今の状態（オンは`mic`、ミュート中は`mic.slash`）。同じ場所で混ぜない |
| 状態は3点で示す | 色＋SF Symbols＋文言。状態の文字は`textPrimary`、状態色は隣の記号・点・塗りに付ける（[カラーテーマ](カラーテーマ.md#状態色への割当て)） |
| 似た見た目を並べない | ミュート中（`Danger`の塗り）と切断（`Danger`の塗り）を隣り合わせない。通話画面ではスピーカーを間に置き、狭い場所（Widget）では切断をガラスの円に`Danger`の記号だけにする |
| 取り消せない操作 | 切断・削除・リセットは赤（`Danger`）で、[利用環境の前提](#利用環境の前提)と[大きさと距離](#大きさと距離)に従って置く。解除なしで触れられる表示には置かない |
| 失敗の伝え方 | 失敗・停止はalertで止めず、その場（状態ヒーローや該当Sectionのfooter）に理由1文と回復の操作1つを出す。alertは取り消せない操作の確認（切断・削除・リセット）だけに使う |
| 触覚 | 接続の成立、切断、ミュートの切替、音声停止、送話の開始と終了で`sensoryFeedback`を出す。画面を見なくても結果が分かるようにする |
| 選択肢の部品 | 2〜3択で短いラベルのときだけ`Picker(.segmented)`。文字サイズが大きく収まらないときは`.menu`または`.inline`へ切り替える（`ViewThatFits`）。ラベルを省略・縮小しない |
| 音量のSlider | 止まっている間の調整として扱い、走行中の音量はヘッドセット・端末のボタンを主とする。Sliderは列の幅いっぱいにし、両端に記号、値を数字で併記する |
| 標準部品 | `List`・`Section`・`Form`・`Button`・`Toggle`・`Slider`・`Picker`・`Label`・`ContentUnavailableView`・`ProgressView`・`ShareLink`・`DisclosureGroup`・`Gauge`。独自のShape描画・独自アニメーションを作らない |
| 適応 | Dynamic Type、VoiceOver、ライト／ダーク、コントラストを上げる、透明度を下げる、視差効果を減らす、[レイアウトと画面サイズ](#レイアウトと画面サイズ)で同じ構造を保つ |

### 状態の表し方

同じ内部状態を、StandardとAdvancedで次の語と記号で表す。記号と色は共通、語だけが異なる。

| 内部状態 | Standardの語（例） | Advancedの語 | 記号 | 色 |
|---|---|---|---|---|
| 流れている・成立 | 会話中 | Running | `waveform`（会話）／`checkmark.circle.fill`（段） | success |
| 待機（システム側の理由で今は流れていない） | 接続中、音声停止中 | Waiting ＋理由 | `ProgressView`／`pause.circle.fill`／`headphones` | warning |
| ミュート（本人の操作で止めている） | ミュート中 | Muted | `mic.slash`（入力）／`speaker.slash`（出力） | danger |
| 停止・失敗 | 音声エラー | Blocked ＋理由 | `exclamationmark.triangle.fill`／`xmark.octagon.fill` | danger |
| 未開始・未到達 | 未接続 | Idle | `phone`／`circle.dashed` | neutral |
| 非対応 | 表示しない | Unsupported | `minus.circle` | neutral |

Waitingは故障ではない。理由（話していない、相手を待っている等）を必ず添える。

ミュートと待機・注意は色だけでは区別できない（赤と琥珀色は、赤と緑の色覚特性で明るさの差1.5〜2.3、コントラストを上げる設定で1.4程度）。次の決まりで、記号と語だけでも必ず区別できるようにする。

| 決まり | 内容 |
|---|---|
| ミュートは独立した状態 | 本人の操作による停止は、常に`mic.slash`／`speaker.slash`と語「ミュート中」／`Muted`で表す。Waiting（琥珀色）の理由としてミュートを表示しない |
| 琥珀色に音声の記号を使わない | warningの記号は`ProgressView`・`pause.circle.fill`・`headphones`に限り、マイク・スピーカーの記号を使わない |
| 塗りの面 | ミュート中だけがボタンを`Danger`で塗る。待機・注意はボタンや面を塗らず、記号と進行表示だけにする |

### 入力欄と既定値

2026-11-06の利用者指示により、入力欄はプレースホルダーと既定値を使い分け、空のときでも何を入れるかが分かり、見本でも状態が読み取れるようにする。全員に同じ値が入る固定の既定値（現行の自分の名前「You」、グループ名「Talk Group」）は使わない。

| 使うもの | 使う場面 | 見た目と動き |
|---|---|---|
| ラベル | すべての入力欄 | 何の欄かを示す。`Form`ではSectionの見出しまたは`LabeledContent`で示し、プレースホルダーをラベルの代わりにしない（入力すると消えるため） |
| 例のプレースホルダー | 利用者が自分で決める値で、空のままでは使えない欄（自分の名前など） | 「例: ナオ」のように「例:」を付け、OS標準の薄い色（`prompt`）。空の間は主要操作を押せない |
| 既定値のプレースホルダー | 空のままでも使える欄（相手の名前、グループ名、呼び名） | 「例:」を付けず、空のときに実際に使う値をそのまま薄い色で見せる。footerに「空のままなら「{値}」になります。」を1回だけ書く。空で確定したらその値を保存する |
| 変化する既定値 | 同じ値が重なると見分けられない欄 | 作るたび・選び直すたびに値を変える（仮名は1件ごとに別の組み合わせ、グループ名は選んだメンバーに合わせて更新）。すでにある値と重ならないようにし、すべて使っている場合だけ末尾に数字を付ける |
| 現在の値 | 編集画面（名前の変更など） | 値を入れた状態で開く。消して空にしたときは既定値のプレースホルダー（戻る先）を見せる |
| 選択肢の初期値 | `Picker`・`Toggle`・`Slider` | 初期値で開く。「開発者向けの高度な設定」とAdvancedでは、選択肢の初期値に「（初期値）」を付け、変えた値から戻せるようにする。設定の主画面の選択肢には付けない |

入力欄の共通の動き: 前後の空白を除いて判定する。入力中は消去ボタン（`.whileEditing`相当）を出す。名前の欄は`textContentType(.nickname)`、アドレスの欄は`.URL`のキーボードで自動修正と大文字化を切る。

### 通話のアクセサリ

[バックログ](../backlog/改善候補.md#下部の小さい通話表示の分かりやすさと操作)の2026-11-04の報告（下部の通話表示が小さくなると分かりづらい。小さい表示でもミュートと切断を操作したい）による設計。ミュージックの再生中表示と同じOS標準の型で、何の表示か・誰と・どの状態かを、画面を開かずに読めるようにする。

| 部分 | 内容 |
|---|---|
| 大きさ | タブバーはスクロールで縮めない（`tabBarMinimizeBehavior`を指定しない）。アクセサリは常に通常の大きさ（`.expanded`）で表示し、タブバーの中に小さく収まる表示（`.inline`）を使わない。縮んだ表示が分かりづらいという報告と、縮んだタブバーではタブを選びにくいことの両方を避ける |
| 先頭 | 状態の記号（会話中は`waveform`をrideGreen、接続中・呼び出し中は`ProgressView`、音声停止は`exclamationmark.triangle.fill`をwarning） |
| 中央 | 1行目に接続先の名前（`.subheadline`・semibold、1行・末尾省略）、2行目に状態の語（`.caption`、例: 会話中／接続中／呼び出し中、ミュート中は「会話中・ミュート中」）。この部分のタップで通話を開く |
| ミュート | 末尾の左。[ミュートの切替](#共通コンポーネント設計案)と同じ規則（記号は常に`mic.slash`、ミュート中はDangerで塗った円）。押せる範囲は44pt以上 |
| 切断 | 末尾の右。`phone.down.fill`をDangerの記号でガラスの円に置く（塗りにしない。ミュート中の赤い塗りと隣り合わせても同じ見た目を並べない）。ミュートとの間は12pt以上 |
| 切断の確認 | アクセサリの切断だけ確認を出す（`confirmationDialog`）。タイトル「{接続先}との接続を切断しますか？」、「切断」（`role: .destructive`）と「キャンセル」。キャンセルでは接続を維持し、確定時は表示した時点の通話だけを切断する。確認中に通話が替わった場合は古い確認を実行しない。通話のシートの切断・ミュートには、この理由で確認を加えない |
| 長押し | メニューに「通話を開く」「ミュート」「切断」（切断は同じ確認を出す） |
| VoiceOver | 中央は1つの要素（label「{接続先}、{状態}」、hint「通話を開きます」）。ミュートと切断は別の要素（ミュートはvalueに「オン／オフ」） |
| 文字サイズ | アクセシビリティサイズでは状態の語の行を省き、名前を1行で残す。ボタンは記号だけにしてaccessibility labelを付ける |
| Mac | アクセサリはなく、ツールバーの通話表示（名前と状態）とメニューバーで同じ情報を出す |

## StandardとAdvancedの違い

同じデータ・状態・操作（共通のViewModelとIF）から導き、色・背景・部品・レイアウトの規則も共通にする。違うのは表示の量・密度・語だけで、違いはこの表の範囲に限る。ここにない点は共通とする。

| 観点 | Standard（一般向け） | Advanced（詳細表示） |
|---|---|---|
| 目的 | 少ない情報で接続・会話を完結させる | トラブルシューティングと詳しい設定 |
| 言語 | 英語・日本語（日本語は[一般向けの日本語の最適化](一般向け/画面構成とレイアウト.md#日本語の最適化)） | 英語のみ |
| タブ | ユーザー・設定。グループは設定で表示したときだけ（既定は非表示、[グループタブの表示](一般向け/画面構成とレイアウト.md#グループタブの表示)）。通話はタブにせず、シートと`tabViewBottomAccessory`（[操作の流れ](操作の流れ.md)） | Users・Groups・Diagnostics・Settings（Groupsは常に表示）。通話は同じくシートとアクセサリ |
| 色・背景 | [カラーテーマ](カラーテーマ.md)を共通で使う（iPhone・iPadは空色の背景グラデーションと白いカード、macOSはOS標準の背景、設定は標準Form） | 同左 |
| 情報量 | 名前・状態・主要操作。ID・codec・数値を出さない。1対1のための内部のグループは見せない | ID・codec・経路・毎秒値・要求値と実効値。1対1のための内部のグループもGroupsに`Direct`として出す（メンバーの追加・削除はできない） |
| 状態の語 | [状態の表し方](#状態の表し方)のStandardの語 | 同Advancedの語 |
| 通話のシート | 状態ヒーロー＋円形操作ボタン列＋メンバー | Call status・Input・Output・Participants（グループの実体として表示） |
| 設定 | 日常の項目だけ。専門項目は「開発者向けの高度な設定」へ | 全項目を信号の流れの順に |
| 密度 | ガラスのカードと大きな操作で余白を広くとる | 同じカードの中に罫線と段組みで多くの行を並べ、一覧性を優先する |

操作の流れ（選んですぐ接続、その場で追加、通知の接続・拒否）は両方で共通とし、[操作の流れ](操作の流れ.md)を正本とする。通知（送る場面・鳴り方・文言・巻き込みを防ぐ規則）も両方で共通とし、[通知の設計](通知の設計.md)を正本とする。招待・グループへの追加・削除の反映・呼び出せる相手の表示は[招待と登録の設計](招待と登録の設計.md)を正本とする。画面ごとの仕様は[一般向けの画面構成](一般向け/画面構成とレイアウト.md)と[診断と詳細画面の構成](詳細画面/診断と詳細画面の構成.md)。

## 設計案の点検表

画面の設計案と実装は、次の観点で点検する。Diagnosticsは一覧性を優先する画面として、慌てているとき・グローブの観点を除き適用する。

| 観点 | 確認すること |
|---|---|
| HIG | 標準部品とOSのガラス・タブ・ツールバーを使っている。押せる範囲は44pt（Mac 28pt）以上。取り消せない操作は赤で、確認を出すか主操作から離している。色だけで伝えていない。Dynamic Type・VoiceOver・ダーク・コントラストを上げる・透明度を下げるで成立する |
| 慌てているとき | 画面の最初に状態が読める（[状態ヒーロー](#共通コンポーネント設計案)の文字の大きさ）。状態の語は短く、理由と次の操作は1文と1つのボタン。失敗をalertで止めない。似た見た目の操作を並べない |
| グローブ | 主要操作は[大きさと距離](#大きさと距離)を満たす。切断・削除は最も触れやすい位置を避け、隣と32pt以上離す（Widgetは12pt以上）。主要操作をスワイプ・長押し・小さな記号だけにしない。スイッチを誤って切ると困る項目は1階層下へ置く |
| 走行中 | 走行中に操作を求めない。解除なしで触れられる表示に取り消せない操作がない（[利用環境の前提](#利用環境の前提)） |
| 一貫性 | 同じ意味に同じ語・記号・部品を使う（[状態の表し方](#状態の表し方)、[共通コンポーネント](#共通コンポーネント設計案)） |

## 状態モデル

UI における状態は、以下の意味として統一する。

| 状態種別 | 定義 | 代表的な扱い |
|---|---|---|
| Ideal State | もっとも期待通りに動作している状態 | 主情報と主操作を素直に見せる |
| Loading State | データや遷移結果を待っている状態 | プレースホルダ、進行中文言、操作制限 |
| Partial State | 一部だけ利用可能、一部だけ未成立の状態 | 利用可能範囲を示し、全体失敗扱いしない |
| Error State | ユーザーが認識すべき失敗や異常がある状態 | 文言、色、アイコン、必要なら再試行導線 |
| Blank State | まだ生成されていない初期状態 | 次に取るべき作成行動を示す |
| Empty State | データは概念上存在するが、結果が 0 件の状態 | 空である理由と次の行動を示す |
| Disabled State | 条件未成立により操作不能な状態 | 押せないことと理由を明示する |

### Ideal State

- 必須: 主要導線画面は Ideal State を基準に構造を決める。
- 必須: Ideal State では余計な診断や例外表示を前面に出さない。

### Loading State

- 必須: Loading は「まだ決まっていない」の意味で使う。
- 必須: Loading 中は成功/失敗色を確定表示しない。
- 必須: Loading 中に押せない操作は disable するか、重複発火防止を入れる。
- 禁止: Loading を Error の代替に使うこと。

### Partial State

- 必須: Partial は「一部成立・一部未成立」を意味する。
- 必須: 接続済みだが音声未開始、入力は生きているが出力先が不確定、などは Partial として扱う。
- 必須: Partial は全体失敗として塗りつぶさない。
- 必須: Partial では使える機能を残し、失われている機能だけを補助表示する。

### Error State

- 必須: Error はユーザーが認知すべき失敗に限る。
- 必須: Error は danger 色、文言、必要なら再試行導線を持つ。
- 必須: Error でも既存情報の読解を阻害しない。
- 禁止: 回復可能な待機や一時的未成立を Error 扱いすること。

### Blank State

- 必須: Blank State は「まだ何も作っていない」を意味する。
- 必須: Blank State では原因説明より次の第一行動を優先する。
- 例: グループ未作成時の「Create a group to start a call.」

### Empty State

- 必須: Empty State は「概念はあるが対象件数が 0」を意味する。
- 必須: Empty State は Error にしない。
- 例: 参加者一覧が空、検索結果が 0 件

### Disabled State

- 必須: Disabled は「押してはいけない」ではなく「今は成立条件を満たしていない」を意味する。
- 必須: Disabled の理由を推測可能にする。
- 必須: Disabled は opacity 低下だけで済ませず、文言や状態との整合を取る。
- 禁止: 実際には押してよい操作を見た目だけ disable にすること。

## Enable / Disable 規約

- 必須: Enable は「今この操作が成立し、押下可能」であることを意味する。
- 必須: Disable は「押下不能であり、押下しても結果が成立しない」ことを意味する。
- 必須: 進行中の重複防止は disable を使ってよい。
- 必須: 権限未取得、依存データ未取得、競合中など、成立条件が欠ける場合のみ disable を使う。
- 禁止: 単に目立たせたくない操作を disable にすること。
- 禁止: 見た目を muted にしたいだけで disable を使うこと。

## macOS フォアグラウンド / バックグラウンド規約

- 必須: macOS では window focus と app active の差を前提に設計する。
- 必須: フォアグラウンド時は主要操作、主要状態、入力系の可読性を最優先する。
- 必須: バックグラウンド時は意味を維持しつつ、視覚強度だけを下げてよい。
- 必須: バックグラウンド時も状態の意味そのものを変えてはならない。
- 必須: Active/Inactive の差は色の彩度、material の強度、補助情報の強弱で表現し、構造は変えない。
- 禁止: バックグラウンド遷移で項目を消すこと。
- 禁止: バックグラウンド時に success を danger へ変えるなど、意味差を生むこと。
- 必須: macOS でのバックグラウンド時も、接続維持や通話継続などの状態そのものは正しく表示し続ける。

## コントロール共通仕様

### 主要ボタン

- 必須: カード内の実装は appProminentButtonStyle() を使用する。標準Form内では、行の標準レイアウトを保つため同じ標準ButtonStyleと.controlSize(.large)を直接指定してよい。
- 必須: スタイルは .glassProminent、背景は buttonProminentBackground、文字色は buttonProminentForeground を使用する。
- 必須: サイズは .controlSize(.large) とする。
- 必須: iOS の表示高さは sizeButtonPrimaryHeight 以上を維持する。
- 必須: macOS の表示高さは sizeButtonMacMinHeight 以上を維持する。

### 補助ボタン

- 必須: 補助操作は .buttonStyle(.glass) を使用する。
- 必須: 状態反転型は danger と accentColor の2値で切り替える。
- 必須: iOS の表示高さは sizeButtonSecondaryHeight 以上を維持する。
- 必須: macOS の表示高さは sizeButtonMacMinHeight 以上を維持する。

### アイコン単体ボタン

- 必須: 押下領域は最小 44x44。
- 必須: accessibilityLabel を設定する。
- 必須: 状態を持つ場合は accessibilityValue を設定する。

### スライダー

- 必須: 音量系は既定では 0...1 の正規化範囲を使用する。通話画面のマスター出力スライダーのみ、1.0 を通常最大、1.0 超過を Boost とする 0...2.0 の範囲を使用できる。
- 必須: 数値表示を併記する。
- 必須: 閾値系は最小値、最大値、スナップ間隔を固定し表示する。

### トグル

- 必須: 環境依存機能は利用可能なときのみ表示する。

### リスト行とカード

- 必須: リスト行は行全体タップ可能。
- 必須: 削除操作は swipeActions と contextMenu の両方を提供する。
- 必須: カードは padding(12) と radiusCard を使用する。
- 必須: カード外側余白は最小で spaceM を確保し、隣接カード同士が視覚的に分離されること。
- 必須: カード境界は borderWidthCard と cardBorder を併用し、背景面と同化させない。
- 禁止: カード境界の省略や、背景面と識別できない低コントラスト設定。

### 空状態

- 必須: 主要導線画面内の各空状態は同一の空状態表現ルールを使用する。
- 必須: 空状態は空状態カードで表示し、cardMaterial、cardBorder、radiusCard、borderWidthCard、spaceXL を適用する。
- 必須: 空状態の本文は textSubheadline を使い、textSecondary で表示する。
- 必須: 空状態カードは画面幅いっぱいに貼り付けず、左右に spaceScreen 以上の余白を確保する。

- 必須: 通話ヘッダー、参加者カード、空状態カードは cardMaterial、cardBorder、radiusCard、borderWidthCard を使用する。
- 必須: 主要導線画面内の空状態表示は、同一ルールの空状態カードを使用する。

## 状態表示仕様

| 状態種別 | 色 | 補助表現 | 運用ルール |

| 接続成功 | success | テキスト（接続済み等）+ アイコン | 色単独で表現しない |
| 接続中/待機 | warning | テキスト（接続中/待機中等）+ アイコン | 色単独で表現しない |

- 禁止: 状態意味を色だけで表現する実装。

## テキスト色規約

テキスト色は、内容の重要度と状態意味の 2 軸で決める。  
状態とエラーの本文は`textPrimary`で示し、状態色は隣の記号・点・操作の塗りに使う。

| テキスト種別 | 既定色 | 状態連動時の許可色 | 禁止事項 |
|---|---|---|---|
| 画面タイトル | `textPrimary` | なし | 状態色へしない |
| セクション見出し | `textPrimary` | なし | 状態色へしない |
| 行タイトル / カード主タイトル | `textPrimary` | `danger` のみ許可条件付き | 通常状態で success / warning にしない |
| 補助見出し | `textSecondary` | `danger`, `success`, `warning`, `info` | 状態意味がないのに色を持たせない |
| 主状態値 | `textPrimary` | なし（記号に状態色） | 状態色で本文を染めない |
| 補助状態値 | `textPrimary` | なし（記号に状態色） | 操作理由など必要な情報を薄い文字だけにしない |
| 説明文 | `textSecondary` | なし | 状態色へしない |
| 最小補助文 | `textTertiary` または `textSecondary` | なし | 注意喚起を担わせない |
| エラー本文 | `textPrimary` | なし（dangerの記号を併記） | エラー本文を状態色にしない |

- 必須: 状態値でない本文は `textPrimary` / `textSecondary` / `textTertiary` のいずれかで表す。
- 必須: 状態の本文は通常の文字色を維持し、状態色は記号・点・塗りに限定する。
- 禁止: 状態アイコンがあるからという理由だけで隣接テキストまで同色に染めること。

## コントロール色規約

コントロール色は「何の操作か」と「今その操作がどの状態か」で決める。  
情報表示の色規約をそのまま操作へ流用してはならない。

| コントロール種別 | 通常時 | 強調時 | 反転/破壊/停止時 | 無効時 |
|---|---|---|---|---|
| 主要ボタン | `buttonProminentBackground` + `buttonProminentForeground` | 同左 | `danger` を許可 | 彩度を落とすが意味色へしない |
| 補助ボタン | `textPrimary` / bordered | `accentColor` を許可 | `danger` を許可 | opacity 低下 + 押下不可 |
| アイコン単体ボタン | `buttonProminentBackground` または bordered | `accentColor` を許可 | `danger` を許可 | opacity 低下 + 押下不可 |
| Toggle | システム標準 | システム標準 | 使用しない | 押下不可で示す |
| Slider | システム標準 | なし | 使用しない | 押下不可で示す |
| Picker | システム標準 | なし | 使用しない | 押下不可で示す |

- 必須: 破壊、停止、遮断、解除系の操作だけが `danger` を使える。
- 必須: `Connect` のような開始操作は success ではなく、主要操作色または標準操作色を使う。
- 必須: `Disconnect`、`Delete`、`Mute`、`Stop` のような停止・遮断操作は `danger` を使ってよい。
- 禁止: 現在状態が success だからという理由で、その状態を変える操作ボタンも success 色にすること。
- 禁止: 情報表示の success / warning / info を、そのまま押下操作色へ流用すること。

## 状態遷移時の色適用規約

状態遷移に伴い色が変わるのは、状態を表す要素だけである。  
レイアウト内の全要素を同時に染めてはならない。

| 要素 | 状態遷移で色が変わってよいか | 規則 |
|---|---|---|
| 接続状態アイコン | 変わってよい | `neutral -> warning -> success -> danger` |
| 接続状態テキスト | 変えない | textPrimaryを維持し、状態の違いは文言と隣の記号で示す |
| 経路ラベル | 原則変えない | `textSecondary` 基準。方式差分は意味で表し、成否色を持たせない |
| セクション見出し | 変えない | 状態色にしない |
| 説明文 | 変えない | エラー本文を除く |
| 主要ボタン | 状態に応じて変えてよい | ただし操作意味が変わる時だけ |
| アイコン単体ボタン | 状態に応じて変えてよい | mute / unmute などの反転操作に限る |
| トグル見出しラベル | 原則変えない | ON/OFF はコントロール自身で示す |
| 補助状態アイコン | 変わってよい | ただし補助状態だけを表す |

- 必須: 状態変化に伴い色が変わる対象を、状態主体の要素へ限定する。
- 禁止: ひとつの状態変化で、説明文、見出し、背景、補助情報まで一斉に同色化すること。

## 背景 / 面 / 前景の関係

- 必須: `背景`、`カード面`、`テキスト/アイコン前景` は別レイヤーとして扱う。
- 必須: 状態色は原則 `前景` にのみ使う。
- 必須: 背景やカード面は状態の意味ではなく、情報のまとまりを表す。
- 禁止: success / warning / danger をカード面全体に常用すること。
- 許可条件付き: エラーカードや破壊確認など、面自体が状態意味を持つ時のみ限定的に状態面を使える。

## macOS Active / Inactive 時の色規約

- 必須: macOS で app 非アクティブ時は、`textSecondary` と material の強度を下げてよい。
- 必須: 非アクティブ時も `danger`、`warning`、`success` の意味そのものは維持する。
- 必須: 非アクティブ時は「読めるが強すぎない」方向へ調整する。
- 禁止: 非アクティブ化で neutral に寄せて状態意味を消すこと。
- 禁止: success / danger などの状態差を消して全部同じ灰色にすること。

## アクセシビリティ仕様

- 必須: アイコン単体ボタンに accessibilityLabel を設定する。
- 必須: 状態値を持つ要素に accessibilityValue を設定する。
- 必須: accessibilityIdentifier はテスト識別専用で運用する。
- 必須: 音量、通信、ミュート、エラーは色以外でも判別可能にする。
- 必須: Dynamic Type 拡大時の文字切れを許容しない。
- 必須: タップ/クリック可能領域は iOS 基準で 44pt 以上とする。
- 必須: macOS は iOS 基準の意味を維持したうえで 28pt 以上を下限とする。

## 共通化時の禁止事項

- 禁止: 画面ごとに背景色、カード色、角丸値を個別定義すること。
- 禁止: 同種コンポーネントでトークン外の余白値を使用すること。
- 禁止: 主要導線画面へ診断情報を追加すること。
- 禁止: 将来利用を理由に未使用トークンを追加すること。
- 禁止: 標準 SwiftUI コンポーネントで意味を満たせるのに、独自のカスタム UI を導入すること。
- 禁止: Blank / Empty / Loading / Partial / Error / Disabled の意味を混同した状態表現。

## ばらつき是正の確定ルール

| ばらつき対象 | 旧状態 | 新ルール | 強制度 |
|---|---|---|---|
| 背景色 | 画面ごとに判断が分散 | 主要導線画面は callScreenBackground、診断導線画面はシステム背景、設定導線画面は grouped Form 背景に固定 | 必須 |
| カード面 | regularMaterial、thinMaterial、background が混在 | 通話系は cardMaterial、診断系は diagnosticsCardMaterial、補助パネルのみ panelSurface を許可 | 必須 |
| 項目色 | 状態色と補助色の使い分けが文脈依存 | 状態は success/warning/danger/neutral/info、補助情報は textSecondary/textTertiary に固定 | 必須 |
| 角丸 | 実質8中心だが規約化不足 | カード系はすべて radiusCard=8 に固定 | 必須 |
| 間隔 | 近い値が混在 | spacing は spaceXXS〜spaceScreen のみ使用可 | 必須 |

## 強制可能なレビュー基準

以下をすべて満たすまでPRを完了扱いにしない。

- 背景、カード面、項目色、角丸、余白がトークン定義だけで説明できる。
- 新規UIでトークン外の固定値が追加されていない。
- iOS で定義した基準値が先に存在し、macOS 側がその意味を保持している。
- 主要ボタンと補助ボタンの高さがトークン下限を下回っていない。
- 背景面とカード面の境界が視認できる。
- 主要導線画面内の空状態が同一ルールで表現されている。
- 主要導線画面と設定導線画面で caption 系のみを主要状態表示に使っていない。
- 状態表示が色単独になっていない。
- アイコン単体ボタンに accessibilityLabel がある。
- 状態要素に accessibilityValue がある。
- 主要導線画面へ診断情報が混入していない。
- 設定導線画面のセクション分離と順序が維持されている。
- 使用シンボルがシンボルファミリー意味規約に違反していない。
- 是正定義の旧シンボルが同用途で残存していない。
- variableValue 対応シンボルが固定表示で実装されていない。
- マルチカラー対応シンボルが .monochrome で描画されていない。
- SwiftUI 標準コンポーネントで成立する箇所に不要なカスタム UI が入っていない。
- Blank / Empty / Loading / Partial / Error / Disabled の状態種別が仕様上区別されている。
- macOS の foreground / background 差が意味差ではなく視覚強度差として扱われている。

## 逸脱時の扱い

- 原則として例外を認めない。
- どうしても例外が必要な場合は、同時変更で次を必須とする。
- 例外理由。
- 影響範囲。
- 代替不可の根拠。
- 解除条件。
- 期限。

## 現行差分と統一方針

| 観点 | 現行状態 | 統一方針 |
|---|---|---|
| 背景面 | Standardの主要導線画面は `standardScreenBackground`、Advancedは `callScreenBackground`、診断導線画面は素の背景、設定導線画面は Form 背景 | 画面種別ごとに背景ルールを固定し、同種画面での例外を禁止する |
| カード面 | `regularMaterial`、`thinMaterial`、`.background` が混在 | 通話系カード、診断系カード、補助パネルで面種別を明確に分離する |
| 角丸 | 実質 8 が中心だが定数化されていない | `radiusCard = 8` を共通トークンとして固定する |
| 間隔 | 2/3/4/6/8/10/12/14/16 が散在 | 余白トークンとして明示し、トークン外の値追加を制限する |
| ボタン | 主要ボタンと補助ボタンの使い分けはあるが規約化不足 | 主要・補助・アイコン単体の3分類を固定する |
