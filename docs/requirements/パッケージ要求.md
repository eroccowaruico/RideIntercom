# パッケージ要求

[製品要求](製品要求.md)を支える共通基盤の責務と判断基準を定める。API名、設定値、処理順、実装状態はここに記載せず、[パッケージ仕様](../spec/packages/Overview.md)と[Worker仕様](../spec/server/Worker.md)へ分ける。

| 統一して求めること | 背景・方針 |
|---|---|
| 通信の状態を所有者が説明できる | 通信を所有する基盤が診断情報を提供し、Appに独自の計測・推定を重複実装させない |
| 破棄の意味を区別できる | 端末内で待ち切れず捨てた情報と、ネットワーク上の損失を混同しない |
| 実測と取得不能を区別する | 取得できない値を0や正常値で埋めず、何が分からないかを通知する |
| 直接・中継の経路を理解できる | 観測した経路と、将来の到達性の保証を区別し、古い情報を現在の状態として扱わない |
| 接続資格を通信・サーバー側で管理する | 長期サービス秘密をAppへ配布せず、資格の取得・更新・失効をAppの独自処理へ押し込まない |
| 中断後に資源と資格を放置しない | 途中失敗、切断、期限切れを扱い、古い接続の処理が新しい接続を壊さない |
| 経路によらず同じ情報契約を使う | Appは共通の状態通知を表示する。通信方式ごとの計測・認証処理をAppへ複製しない |
| 必要な差し替え境界を維持する | OS・通信・コーデックの差を所有する責務へ閉じ込める。診断だけのために余分なplugin層を追加しない |

要求は満たした後も維持する。具体的な未実装作業は[課題](../backlog/README.md)、確認待ちは[検証](../validation/README.md)に記録する。工程と編集責任は[文書作成規約](../policies/文書作成規約.md)を参照する。

## RTC全体の制御と音声の配送契約

バイク・スキーのインカムでは、遅れた発話の完全配送より会話の即時性を優先する。この契約はLocal、Internet、中継、経路切替、障害時の代替経路に共通して適用する。

| 対象 | 必須要求と理由 |
|---|---|
| 制御情報 | 接続・認証・参加離脱・設定同期等は、信頼性ありの配送またはTCP系の通信を使う。必要な順序を保持し、未達を正常完了として扱わない |
| 音声情報 | 必ず再送制御のないUDP系のdatagram配送を使う。音声のための順序保証待ち、欠落packetの再送、信頼性ありコピー、TCP系へのfallbackを設けない。UDP上の仕組みでも、音声messageの再送が有効なら不適合とする |
| 遅延した音声 | 鮮度の期限を超えた音声は破棄する。古い発話を蓄積して後から再生せず、次の新しい音声へ進む。順序逆転・重複も再生しない |
| 制御と音声の独立 | 制御の再送・順序待ち・大きなmessageで音声配送を待たせない。制御と音声を同じ信頼性ありstreamへ混在させない |
| 接続の前提 | 音声配送を常設TCP接続や常設の信頼性ありstreamの維持に依存させない。通話の参加・認証状態やUDPの送受信資源を保持することと、常時接続型の音声配送を区別する |
| 複数経路 | 独立した利用可能経路の即時配送と先着採用は許容する。ただし再送待ちを導入せず、同じ音声は一度だけ再生する |
| 欠落への対処 | 欠落を完全配送のための待機へ置き換えない。有限の並べ替え・再生調整で連続性を改善し、回復できない欠落では次の音声を遅らせず不連続を抑える |
| 検証 | 全経路の音声再送無効、期限超過の破棄、制御待ちからの独立、重複非再生を自動検証する。波形の欠落・重なり・clickと遅延を実出力で確認し、音声同一性の判定を緩めない |
