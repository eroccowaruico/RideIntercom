# パッケージ要求

[製品要求](製品要求.md)を支えるパッケージの恒久的な責務と受け入れ条件を記録する。**満たした要求も維持する。** 改善作業は要求と現状との差であり、要求そのものとは区別する。API詳細は[RTC仕様](../spec/packages/RTC.md)と[Worker仕様](../spec/server/Worker.md)、工程・編集責任は[文書作成規約](../policies/文書作成規約.md)を参照する。

## 要求・実装・検証の対応

| 要求 | 責務と受け入れ条件 | 実装状態 | 検証・限界 |
|---|---|---|---|
| 端末内のイベント破棄を観測できる | RTCが購読mailboxの上限超過・期限切れを区別し、Local transport / route / native engine / CallSessionのreportへ通知する | 実装済み。RTCEventDropReport、RTCNetworkDiagnostics | overflow/expiry、停止・世代変更を自動検証。ネットワークpacket lossとは別の値 |
| 実測と取得不能を区別する | RTC/nativeがICE RTTとDataChannel待ちbyte数を取得し、未取得はnilと理由で通知。Appで品質を推定して正常値にしない | RTT・buffered bytes・取得不能の通知を実装済み | nativeペアで実測。SCTPの損失率はSDKが提供しないため未取得。RTP損失率や0で代替する実装は採用しない |
| 直接・中継の観測経路が分かる | 認証済みgroup envelopeの話者、path、受信route、観測時刻をRTCが報告し、古い情報を除く | 実装済み。RTCObservedPeerPath | 仮想4端末・中継交代・切断を自動検証。最後に届いた経路であり全候補経路の探索・将来の到達保証ではない |
| TURN資格をパッケージ/Workerで管理する | Workerが端末認証・利用枠確認後に短期資格を発行し、RTCがSDP前に適用。lease更新で同一接続へ更新する | 発行・更新・失効を実装済み。Appに長期Cloudflare秘密を持たせない | HTTP契約とnative設定更新は自動検証済み。実TURN・制限回線・長時間更新は未確認 |
| 接続中断後に資格を放置しない | 所有者・接続試行IDを確認し、切断・期限・未成立試行を回収。失効失敗は再試行する | 実装済み。Worker alarm、RTC世代検査 | 古いcleanup拒否、期限回収、失効失敗、接続/切断競合を自動検証。実サービスでの失効反映時間は未確認 |
| Appが共通reportで表示できる | Diagnosticsへ取得値・理由・破棄・観測経路を表示し、切断・グループ切替で旧値を残さない | App追従済み。計測・資格処理をAppへ複製しない | App単体とUIの証跡は[今回の検証記録](../validation/history/通信診断とTURN資格検証.md) |

## 残る作業

| 区分 | 内容 |
|---|---|
| アカウント設定後の受け入れ | TURN有効化、UDP制限/TCP/TLS回線、実SFUをまたぐ双方向音声、lease更新中の継続、切断・期限・資格失効の反映時間 |
| 公開運用 | identity・端末資格の公開登録/発行/失効、abuse・実請求監視は[製品要求](製品要求.md)の残件。短期TURN資格の利用枠だけでbyte課金上限を保証しない |
| 採用しない代替 | 未取得の損失率を0とする、RTP値をSCTPへ流用する、Appへ独自計測・TURN管理を置く、診断専用の新しいplugin層を作る |

以前の「パッケージ改善要求」に記載した実装不足は上表の契約で対応した。実サービス未確認を未実装と混同せず、また自動テストだけで実通話の受け入れ完了とはしない。
