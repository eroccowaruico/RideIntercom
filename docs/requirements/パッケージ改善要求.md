# パッケージ改善要求

[製品要求](製品要求.md)を満たすために、App側で見つかったpackageの不足責務をまとめる。Appの暫定実装を正当化する一覧ではない。解消条件を満たすまで未達として追跡する。

更新の責任と追記項目は[文書作成規約](../policies/文書作成規約.md)に定める。パッケージ工程では参照だけ行い、App追従工程で更新する。

## 未解決の要求と解消条件

| 対象 | 不足と現状 | Appに暫定実装しない理由 | 解消条件 |
|---|---|---|---|
| RTC / network diagnostics | EventSourceでの一時イベント破棄数、DataChannelのRTT/loss/buffered amountとpeer別の直接/中継到達経路がruntime reportに不足 | 実通信を所有するRTCが計測・通知する責務。Appで推定した品質を正常値にしない | 対応API / runtime reportで値と未取得状態を通知し、Appが同じreport契約で表示できる。破棄・取得不能・経路変更を自動テストで確認する |
| RTC / Worker | 現在はSTUN + SFU直接接続。制限回線向けTURN資格の取得・更新・失効が不足 | 資格取得と経路利用はRTC/Workerの責務。AppへCloudflare秘密を持たせない | RTC/Workerで取得・更新・失効を扱い、Appが既存の接続・状態通知経路で利用できる。契約の自動テストと制限回線での実サービス確認を区別して記録する |

## 具体化する仕様

[RTC仕様](../spec/packages/RTC.md)、[Worker仕様](../spec/server/Worker.md)、[アーキテクチャ](../spec/アーキテクチャ.md)へ契約を反映する。Cloudflare SFUの試用で残るTURN・制限回線の確認は上表に集約し、実サービス未確認のまま解決済みにしない。
