# iOS インカムアプリ 企画書

> 初期構想と2026-10-21時点の対応経緯を保持した資料。要求の現在の優先入口は[要求管理](../requirements.md)、実装契約は[アーキテクチャ](../../spec/アーキテクチャ.md)。未実装候補を削除せず残す。

## 目的

本書は初期構想を残しつつ、現行実装との差分を明示するための要求整理資料である。  
現行実装の正本は `docs/spec` を参照する。

## 初期構想として妥当な要求

| 要求 | 現状 |
|---|---|
| 音楽を聴きながら通話できる | 実装済み。通話セッションは `mixWithOthers` を使用 |
| 2〜8 名の同時通話 | 人数上限8。仮想4端末の混在通話を自動検証済み。実機8人品質は未確認 |
| 近距離は MultipeerConnectivity を利用 | 実装済み |
| Local 切断時は WebRTC へ移行 | 両経路の維持と中継を自動検証済み。実SFU品質は未確認 |
| WebRTC から Local へ自動復帰する | 有効な両経路を維持しLocal復帰後も到達性を保つ。実サービスでの復帰は未確認 |
| 起動後にグループ選択または新規作成できる | 実装済み |
| 同一グループだけ接続できる | 実装済み。groupHash と handshake で制御 |
| 招待 URL を共有して参加できる | 実装済み |
| 常時開通に近い同時通話体験 | 中継・再試行・lease自動更新を実装。分断・OS停止・利用枠終了時の継続は保証しない |
| 無音時は VAD で送信抑制する | 実装済み |

## 初期構想から削れた、または未実装の要求

| 初期構想 | 現状 |
|---|---|
| 過去接続メンバーを選んで任意構成のグループを作る | 未実装。新規作成は `Talk Group` 固定、ローカルメンバー 1 名のみ |
| AirDrop, など共有機能での複数招待方式を持つ | InviteはOSのShareLinkを利用。利用可能な共有先はOSに依存し、専用AirDrop/QR導線は未実装 |
| Owner 選出と調停ロジック | 未実装 |
| codec を自由に切り替える | PCM / AAC-ELD v2 / Opusを選択。利用不可時はPCM fallback、実選択をDiagnosticsへ表示 |
| 最大 8 枠の固定カード UI | 未実装。現行はリモート参加者分だけ縦カードを並べる |

## 現行実装の要求要約

### 画面

| 項目 | 現行仕様 |
|---|---|
| タブ | Call / Diagnostics / Settings |
| グループ作成 | `Create Talk Group` のみ |
| グループ削除 | 一覧行の swipe / context menu |
| 参加者削除 | 通話画面の参加者カードから削除 |
| 招待 | 通話画面の `Invite` ボタンで共有 |

### 通信

| 項目 | 現行仕様 |
|---|---|
| Local | MultipeerConnectivity |
| Internet | Cloudflare SFU用RTC/WorkerとApp設定を実装。招待制の自動検証済み経路。実アカウント接続・TURN・公開identityは未確認/未対応 |
| 認証 | group secret ベースの HMAC |
| 暗号化 | 全経路のgroup relay envelopeをAES-GCMで保護 |

### 音声

| 項目 | 現行仕様 |
|---|---|
| 入力 | SessionManagerの実hardware format → Mixer 48kHz → 選択RTC format 16/24/48kHzを明示変換 |
| VAD | `idle/attack/talking/release` |
| 出力 | 参加者別出力 + マスター出力 |
| Audio Check | 5 秒録音 + 5 秒再生 |

## Cloudflare 試用から公開への要求

| 要求 | 実装 / 残件 |
|---|---|
| 少人数で費用を抑える | SFU容量課金、SQLite DO Hibernation、個別端末資格、参加者秒の前払い枠。全課金項目は `docs/spec/server/Cost.md` |
| 手動再接続を減らす | 同一SFU sessionのlease自動更新。WS一時切断はmediaとは別に復帰 |
| 公開できる構成へ進む | SFUとWorker契約を固定し、公開登録/資格発行/失効・abuse対策を追加する。招待制registryを公開登録完成と呼ばない |
| 検証区分 | 自動検証、実Cloudflare未確認、実機未確認を分ける。実測料金で試算条件を更新 |

## 品質・保守性点検の反映

| 要求 | 現行の対応 | 残る受け入れ |
|---|---|---|
| UIなしの自動化 | headless入口。9 package/native SDP/Worker/Swiftペア/scripts | 実SFU媒体をローカル代替テストで保証しない |
| ペア・再接続 | 双方向制御、lease跨ぎ、片側再参加、10回の受信枠再利用、生成PCM双方30,000フレーム | 実回線/音響/画面ロック/音声デバイス切替 |
| 診断導線 | 経路概要、サービス認証、Audio Checkを分離。未提供指標を正常表示しない | DataChannel詳細統計、TURN、実機音質 |
| UI自動化 | 専用Simulator、主要導線、資格入力、large text/dark/landscape | VoiceOver実操作とMac/iPadサイズ別の最終目視 |
| 拡張性 | 既存route factory、codec、backend、Effector境界を維持。動的plugin機構は追加しない | 公開identity・abuse・課金運用の実サービス確認 |

## 混在グループの追加要求

| 要求 | 実装と受け入れ |
|---|---|
| 一部Local、一部Internet、Internet非利用者を含む全員通話 | 符号化済み音声を近くの参加者で中継。4端末・中継交代・双方向・mute中継を自動検証。実Cloudflare / 無線は未確認 |
| 接続経路がある限り維持 | 話者ID・epoch・sequence・pathで重複と旧通知を排除。切替中の瞬間的欠落は許容。最後の橋が消えた分断中は残る側だけ継続 |
| Bluetooth切断の直感性 | 自分の送受話停止・理由表示・明示再開。接続と中継は維持。OS実通知・実機聴感は後続 |
| 従量課金の抑制 | 中継者選出・送信重複削減・利用枠・期限回収。容量課金が常に安いとはせず実wireサイズからCost.mdを試算 |
