# 要求の入口

| 知りたいこと | 正本 | 区別 |
|---|---|---|
| アプリは何のために何を満たすか | [製品要求](製品要求.md) | 利用者の価値・機能・品質・受け入れ・残件 |
| パッケージの責務と未達は何か | [パッケージ要求](パッケージ要求.md) | 恒久的な責務・受け入れ・実装状態。満たした要求も維持する |
| 以前の構想と候補 | [初期構想と対応経緯](background/初期構想と対応経緯.md) | 未採用案も保持。現行仕様と混同しない |
| どう作る必要があるか | [開発方針](../policies/開発方針.md) | 工程、設計、品質検証、エディタ環境 |
| どう書き、整理するか | [文書作成規約](../policies/文書作成規約.md) | 文書構造、更新責任、命名、計画 |
| ログをどう実装するか | [ログ記録規約](../policies/ログ記録規約.md) | 共通実装規約。実際の発行状況はApp仕様 |

要求を変える場合は製品要求またはパッケージ要求から着手し、仕様・実装・マニュアル・検証状況へ反映する。作り方だけを変える場合はpoliciesから着手する。現在のAPIや設定値は[アーキテクチャ](../spec/アーキテクチャ.md)を入口に対応仕様を参照する。
