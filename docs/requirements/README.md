# 要求の入口

| 知りたいこと | 正本 | 内容 |
|---|---|---|
| アプリは何のために何を満たすか | [製品要求](製品要求.md) | 利用者の価値・背景・品質方針 |
| 共通基盤に何を統一して求めるか | [パッケージ要求](パッケージ要求.md) | 責務と判断基準 |
| どう作る必要があるか | [開発方針](../policies/開発方針.md) | 製品とは別の工程・設計・品質の制約 |
| どう書き、整理するか | [文書作成規約](../policies/文書作成規約.md) | 分類、更新責任、命名、計画 |
| ログの共通方針 | [ログ記録規約](../policies/ログ記録規約.md) | 記録すべきものと禁止するもの |

要求には実装の棚卸し・API詳細・達成状況を書かない。[仕様](../spec/アーキテクチャ.md)は現行実態、[課題](../backlog/README.md)は実装する作業と候補、[検証](../validation/README.md)は確認待ちと証跡を管理する。初期構想と対応経緯は[履歴](../validation/history/初期構想と対応経緯.md)に保存する。
