# 製品要求

## 目的と対象

RideIntercomは、音楽を聴きながら、近距離・Internet・中継をまたいでグループの同時通話を続けるiOS/macOSアプリである。iOSを主対象とし、macOSもデスクトップとして使える体験を提供する。接続経路がある限り手動での繋ぎ直しを減らし、経路によらず同じ音声調整と分かりやすい状態表示を提供する。

本書は**アプリが何を満たすか**の正本。[開発方針](../policies/開発方針.md)は**どう作るか**、[文書作成規約](../policies/文書作成規約.md)は**どう記録・保守するか**を定める。実装済みという理由だけで要求を縮めず、未達は残す。

## 根本的な品質要求

| 項目 | 要求 | 具体化 / 確認先 |
|---|---|---|
| 対応端末 | iOSとmacOS両方をサポートすること。iOSがメインのターゲットで、macOSはiOSの単純移植で済ませないこと | [UI設計](../spec/App/UI/全体構成.md)、[開発方針](../policies/開発方針.md)のUI・UX方針 |
| 安全なグループ通話 | 同一グループの認証済み参加者だけで通話し、全経路で音声を暗号化する。秘密・音声内容をログへ出さない | [通信](../spec/App/通信仕様.md)、[ログ記録規約](../policies/ログ記録規約.md)。公開identity・失効は残件 |
| 直感的な操作 | 接続経路によらず音量・mute・effectを同じ意味で使える。接続、音声停止、失敗と再開方法を区別して示す | [使い方](../manual/使い方.md)、[状態遷移](../spec/App/UI/画面・状態遷移.md) |
| アクセシビリティ | 状態を色だけに依存させず、VoiceOver・文字サイズ変更・各端末の入力方法と画面サイズに対応する | [デザイン](../design/デザインシステム.md)、[検証状況](../validation/README.md)。実操作の未確認を残す |
| 音声品質・継続性 | 低遅延、無音時の送信抑制、音楽との共存、機器変化の説明と復帰を提供する。音響品質は実機で評価する | [音声仕様](../spec/App/音声処理仕様.md)、[設定と効果](../manual/設定と音声効果.md) |
| 費用と公開への移行 | 少人数試用で費用を抑え、利用枠と公開運用へ拡張できる構成を持つ。容量だけでなく全課金項目を試算し、継続通話で不要な再接続を要求しない | [費用](../spec/server/Cost.md)、[Worker](../spec/server/Worker.md)。請求上限の保証・公開準備完了とは扱わない |

## 製品要求と受け入れ

| 利用者の要求 | 現在の対応 | 正本 / 受け入れ |
|---|---|---|
| iOS/macOSでグループ通話する | 上限8人、招待URL、LocalとInternet、中継 | [通信](../spec/App/通信仕様.md)。仮想4端末とペアは自動検証、実機8人品質は未確認 |
| グループを見比べても通話が切れない | selected / activeを分離。Connectで明示切替 | [状態遷移](../spec/App/UI/画面・状態遷移.md)、App単体試験 |
| 一部離脱・Local/Internet混在でも届く経路を維持 | 元話者IDの暗号化音声を中継し重複排除 | [RTC](../spec/packages/RTC.md)。最後の橋を失う分断は継続不能。実SFU・無線は未確認 |
| 経路にかかわらず同じ音声調整 | 共通Mixer / Codec / Effectors、個別・master音量 | [音声](../spec/App/音声処理仕様.md)、実PCM自動検証 |
| 古い音声をため込まない | unordered・再送0、bounded queue・期限・再生予約上限 | RTC / Mixer / SessionManager仕様。過負荷時の欠落を許容 |
| Bluetooth等の機器消失を分かりやすく扱う | Audio Paused、理由、Resume。接続・中継は保持 | 実機通知順・音響・ロック中継続は未確認 |
| 音楽との共存・VAD・自己録音確認 | session設定、可聴受信時duck、VAD、Audio Check | [設定と効果](../manual/設定と音声効果.md)。OS/機器で実効差あり |
| 少人数試用から公開へ進める | SFU / Worker、個別資格、利用枠、lease継続 | [Worker](../spec/server/Worker.md)、[費用](../spec/server/Cost.md)。公開identity・abuse・実請求確認は未完了。TURNは実装済み・実回線未確認 |

## 未達と候補を保持する方針

| 区分 | 内容 / 完了条件 |
|---|---|
| 実装が必要な残件 | 公開identity・資格発行/失効の公開運用、abuse・請求監視。RTC診断とTURN資格は実装済みで、下段の実運用確認が残る |
| 実運用で確認する残件 | Mac/iPhone招待・双方向・10分・同時発話・画面ロック・Bluetooth/有線、実SFU/TURN、実測料金 |
| UIの未確認 | VoiceOver実操作、Mac/iPadのサイズ別表示 |
| 初期構想の候補 | 任意メンバー構成、名前編集、QR/AirDrop専用導線、Owner調停、履歴。既存OS ShareLinkと専用機能の実装を区別 |
| 過去要求の保存 | [初期構想と対応経緯](background/初期構想と対応経緯.md)に背景・候補を保持。現行の状態は本表・現行spec・検証記録で判断 |

## 要求の詳細と残件

[パッケージ要求](パッケージ要求.md)に恒久的な責務・受け入れ・実装状態、[初期構想と対応経緯](background/初期構想と対応経緯.md)に初期の候補と優先度を保持する。新たな根本要求は本書へ、実装契約は[アーキテクチャ](../spec/アーキテクチャ.md)から対応仕様へ、達成の証拠は[検証状況](../validation/README.md)へ記録する。
